# 2026-10-26 AI 进展简报

> 信息窗口：优先覆盖 2026-10-24 至 2026-10-26 的公开进展，并扩展回看 2026-10-13 至 2026-10-23 的重要官方发布，形成适合团队推送的近两周趋势版。榜单与社区指标为 2026-10-26 抓取时可见快照，不等同于完整平台统计。

## 今日最值得关注

1. **OpenAI Agents API 已把定时任务纳入官方工作流，Agent 从“被动调用”走向可持续运行。** 官方文档支持一次性或 cron 调度、复用或新建 session、查看调用历史，并可暂停、恢复和删除 automation；但“调度已触发”不等于任务已完成。来源：[OpenAI Agents API — Scheduled automations](https://developers.openai.com/api/docs/guides/agents-api/sessions/automations)。**影响判断：**生产级 Agent 的重点将从单次推理转向幂等、重试、可观测和人工接管。**行动建议：**先选一个低风险日报或巡检任务，补齐成功判定、失败告警与重入保护后再自动化。
2. **MCP 官方参考服务器仓库发布 v2.1.0，`mcp-server-fetch 2026.10.24` 重点强化地址分类、主机连接检查与 robots.txt 处理。** 这是官方服务器/工具链更新，不是 MCP 核心协议换版。来源：[modelcontextprotocol/servers Releases](https://github.com/modelcontextprotocol/servers/releases)。**影响判断：**抓取型 MCP 服务的 SSRF、私网访问和 robots 合规边界进一步收紧。**行动建议：**升级前后回归私网地址、重定向、DNS 变化和 robots 规则，不要只验证正常公网 URL。
3. **Canva 发布自研图像模型 Canva Craft，继续把“生成图片”推向可编辑设计资产。** 官方称其支持任意宽高比的 2K 输出、30 多种常用比例、55 种语言文本，并通过先规划后渲染提升排版与文字表现；Canva MCP 仍标注为 “Coming Soon”。来源：[Introducing Canva Craft](https://www.canva.com/newsroom/news/canva-craft/)。**影响判断：**设计生成竞争正在从画质转向文字、版式、品牌控制和后续编辑链路。**行动建议：**用含中文长标题、品牌色和多尺寸导出的同一 brief 做实测，不直接采信厂商榜单结论。
4. **OpenAI 披露一次前沿训练环境的网络隔离事件，并把基础设施红队纳入持续安全案例。** 官方称 2026-09-20 一次 DNS 配置问题让内部模型获得有限公网访问，随后暂停最强训练/评测负载、加固后于 10 月 1 日恢复部分工作。来源：[Securing our frontier model training environment](https://openai.com/index/securing-our-frontier-model-training-environment/)。**影响判断：**高能力 Agent 的安全边界已经延伸到 DNS、网络出口与集群控制面。**行动建议：**把“模型是否能意外出网”加入 Agent 基础设施威胁建模和演练清单。
5. **Firecrawl 上线 Government & Legal Index，把 3,000 万个美国政府页面整理成可搜索数据源。** 覆盖法规、地方条例、判例等页面，可在 ChatGPT、Claude 或 API 中检索。来源：[Firecrawl Changelog — Government & Legal Index](https://www.firecrawl.dev/changelog)。**影响判断：**垂直 RAG 的差异化越来越依赖索引覆盖、更新频率与可追溯来源，而不只是通用抓取。**行动建议：**法律场景试用时保存原始 URL、抓取时间和版本，避免把检索结果当作法律意见。
6. **Cerebras 公开万亿参数模型部署拆解，社区关注点从“能否运行”转向带宽、量化与服务拓扑。** 文章以约 3T 参数的开放模型为例，给出 4-bit 权重、8-bit KV cache 与多晶圆部署推算，并宣称可达 1,000–2,000+ tokens/s；该吞吐为厂商技术说明中的主张，非独立基准。来源：[Cerebras technical blog](https://www.cerebras.ai/blog/how-we-deploy-trillion-parameter-frontier-models-on-cerebras)、[Hacker News 讨论](https://news.ycombinator.com/item?id=50227356)。**影响判断：**超大模型服务的工程约束正在成为公开讨论核心。**行动建议：**评估时要求端到端并发、上下文长度、首 token 延迟和成本数据，不只看单请求吞吐。
7. **GitHub 日榜出现明显的“让编码 Agent 更会做设计”工具潮。** `hallmark` 与 `impeccable` 分别显示 1,317 和 1,092 “stars today”，同时 `security-audit-skill` 再度在榜。来源：[GitHub Trending](https://github.com/trending)。**影响判断：**可复用 skill 正在从提示词模板演化为带流程、规则和验收标准的工程资产。**行动建议：**先审查 skill 的指令边界和脚本权限，再把设计或安全技能接入真实仓库。

## 近两周扩展资讯：团队推送补充

### 设计生成与产品研发

1. **Figma 把设计、代码和 Agent 放进同一工作面。** 10 月 15 日发布的 Build by Design 带来 Code Layers、Specs，以及从 GitHub、本地代码和 MCP 引入上下文的工作流，目标是让原型、设计系统与可交付代码减少往返。[Figma 官方发布](https://www.figma.com/blog/build-by-design/)。**团队判断：**设计到代码的竞争重点，已从“能否生成页面”转向“能否继承真实组件、约束和评审上下文”。
2. **Krea 3 主攻批量生产中的编辑速度和一致性。** 官方称其可在原生 2K 下于 8 秒内完成多数编辑，单张 0.06 美元，并支持最多 6 张参考图；这些性能和价格对比均为厂商口径。[Krea 3](https://www.krea.ai/blog/introducing-krea-3)。**团队判断：**电商、广告和内容团队应以 SKU 批量改图、主体一致性和不可改区域保持作为评测集，而不是只看单张示例。
3. **Canva Craft 的意义是“可编辑设计资产”，而不只是新图像模型。** 它补齐文字、构图、多尺寸与 Canva 画布内继续编辑的链路，和 Figma/Krea 一起说明设计生成正在进入生产交付阶段。[Canva Craft](https://www.canva.com/newsroom/news/canva-craft/)。

### 搜索、抓取与 RAG

4. **Exa 3.0 升级独立搜索索引，并推出低价 Lite 档。** 10 月 19 日官方宣布 Dynamic Highlights 全面可用，称相比整页文本可减少 95% token；Exa Lite 为每千次请求 4 美元，并增加商品、本地商户、航班、赛事和实时数据覆盖。[Exa 3.0](https://exa.ai/blog/exa-3)。**团队判断：**搜索 API 的竞争已变成“召回质量 × 上下文压缩 × 单次研究成本”，应在自有查询集上比较最终答案质量而非只看搜索 benchmark。
5. **DeepSeek 将 Search / Fetch API 对所有用户开放。** 10 月 17 日的 V4.1 Flash 1017 更新同时开放自研搜索与网页抓取接口，两个端点均为每千次 0.75 美元；模型权重也已开放。[DeepSeek 官方说明](https://api-docs.deepseek.com/news/news261017/)。**团队判断：**这会降低 Agent 接入搜索的门槛，但仍要验证中文长尾覆盖、引用稳定性、动态网页与反爬失败模式。
6. **Firecrawl、Exa、DeepSeek 正形成三种数据层路线。** Firecrawl 更强调抓取与垂直数据包，Exa强调自建索引与检索压缩，DeepSeek把搜索作为模型/Agent 配套工具。**行动建议：**团队可以用同一批“新闻追踪、公司情报、技术文档、深网页”查询做盲测，记录召回率、引用有效率、token、延迟和总成本。

### Agent、自动化与企业工作流

7. **Claude Duet 把“主动找你”作为新交互范式。** 10 月 21 日开放研究预览，面向美国 Pro/Max 候补用户；它会汇总连接应用中的每日重点、持续监测，并在代表用户采取行动前确认。[Claude Duet](https://claude.com/resources/articles/claude-duet)。**团队判断：**下一代企业助手不只是响应提示，而是争夺“主动提醒、持续运行、判断何时打扰”的入口。
8. **Notion Agent 单任务运行上限从 5 分钟提升到 24 小时以上。** 新运行时采用队列式 worker、上下文压缩和大工具结果外置，并用独立模型执行“Review for me”安全检查；速度、成本和稳定性数字属于 Notion 自报。[Notion Agent 运行时](https://www.notion.com/blog/notion-ai-more-for-less)。**团队判断：**长任务的护城河正在从模型转向运行时、状态恢复、上下文管理和治理面板。
9. **Microsoft Foundry Browser Automation Tool 正式 GA。** 它提供托管 Playwright 浏览器、私网连接、Live View、人工接管、Entra/RBAC 以及 MCP 兼容工具箱，面向没有完整 API 的企业系统。[Microsoft Foundry](https://devblogs.microsoft.com/foundry/browser-automation-tool-ga/)。**团队判断：**浏览器自动化开始进入企业托管阶段，但网页提示注入、凭证边界和写操作审批仍是上线门槛。
10. **Google 正把 Skills 变成 Gemini 的统一定制层。** Gemini Customize 中央入口将 Skills 与 40 多个连接应用聚合；Skills 使用开放的 Markdown `SKILL.md` 形式，并逐步替代 Gems。[Google Workspace 更新](https://workspaceupdates.googleblog.com/2026/10/an-easier-way-to-customize-how-gemini-works-for-you.html) · [Skills/Gems 迁移说明](https://workspaceupdates.googleblog.com/2026/09/skills-gemini-app-workspace.html)。**团队判断：**“技能文件可移植、连接权限可审计”正在成为跨 Agent 平台的基础能力。
11. **OpenAI Decisions API 正式 GA，专门处理高频、边界明确的小决策。** 支持文本、图片和原生 JSON，一次最多 400 个问题，并加入缓存、GPT-Live 集成与美欧推理驻留；“最高 10 倍更快”是厂商对比口径。[Decisions API](https://openai.com/index/decisions-api/)。**团队判断：**分类、路由、打分和策略选择不一定要调用完整大模型链路，Agent 架构会出现更细的模型分工。
12. **OpenAI Agents API 的 Scheduled automations 与上述产品共同指向“持续运行”。** Claude Duet、Notion、Foundry 和 OpenAI 的共同主题，是把 Agent 从单次聊天转为有调度、有状态、有权限和可恢复的工作系统。**行动建议：**产品规划中单列 Agent Runtime 层，不要把所有可靠性都寄托在模型提示词上。

### 给团队的三条总判断

- **主线一：Agent 正从聊天界面变成可持续运行的业务系统。** 调度、长任务、浏览器、审批、恢复、可观测和连接器治理，会比单次 demo 更决定能否上线。
- **主线二：Skill 与上下文正在成为跨平台资产。** Google、Notion、MCP、OpenAI 和开源社区都在争夺可复用指令、组织知识和工具权限的承载层；团队应尽早建立版本化、可审计的内部技能库。
- **主线三：模型差异化转向垂直任务和成本结构。** 语音、时序、搜索、科学、遗留代码和设计编辑都出现专用模型或 API；选型应从“谁的总榜更高”转向“谁在我们的任务集上质量/延迟/成本/治理更优”。

## 今天值得深入研究的 1 个主题

### 定时 Agent 的“调度成功”为什么不等于“业务完成”

Scheduled automations 把 Agent 变成长期运行系统，也把传统分布式系统问题重新带回产品层：调度器只能证明任务被投递，不能证明模型调用、工具执行、外部写入和最终验证全部成功。一个可靠闭环至少需要：稳定的任务幂等键；区分 `scheduled`、`started`、`tool-running`、`committed`、`verified` 的状态机；有界重试和死信队列；外部写入前后的内容哈希；以及失败时可恢复的人工接管入口。

最值得做的实验，是把一个“生成日报并同步两处”的任务拆成可验证阶段：本地源文件冻结、第一外部渠道回读、第二渠道提交、最终一致性校验。每一步都记录输入哈希和远端凭证，而不是用“API 返回 200”替代完成证明。这类工程能力会比再增加一个模型提示词，更直接决定 Agent 是否能进入生产。
