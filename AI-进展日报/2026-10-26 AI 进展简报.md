## 今日最值得关注

1. **OpenAI Agents API 已把定时任务纳入官方工作流，Agent 从“被动调用”走向可持续运行。** 官方文档支持一次性或 cron 调度、复用或新建 session、查看调用历史，并可暂停、恢复和删除 automation；但“调度已触发”不等于任务已完成。来源：[OpenAI Agents API — Scheduled automations](https://developers.openai.com/api/docs/guides/agents-api/sessions/automations)。**影响判断：**生产级 Agent 的重点将从单次推理转向幂等、重试、可观测和人工接管。**行动建议：**先选一个低风险日报或巡检任务，补齐成功判定、失败告警与重入保护后再自动化。
2. **MCP 官方参考服务器仓库发布 v2.1.0，`mcp-server-fetch 2026.10.24` 重点强化地址分类、主机连接检查与 robots.txt 处理。** 这是官方服务器/工具链更新，不是 MCP 核心协议换版。来源：[modelcontextprotocol/servers Releases](https://github.com/modelcontextprotocol/servers/releases)。**影响判断：**抓取型 MCP 服务的 SSRF、私网访问和 robots 合规边界进一步收紧。**行动建议：**升级前后回归私网地址、重定向、DNS 变化和 robots 规则，不要只验证正常公网 URL。
3. **Canva 发布自研图像模型 Canva Craft，继续把“生成图片”推向可编辑设计资产。** 官方称其支持任意宽高比的 2K 输出、30 多种常用比例、55 种语言文本，并通过先规划后渲染提升排版与文字表现；Canva MCP 仍标注为 “Coming Soon”。来源：[Introducing Canva Craft](https://www.canva.com/newsroom/news/canva-craft/)。**影响判断：**设计生成竞争正在从画质转向文字、版式、品牌控制和后续编辑链路。**行动建议：**用含中文长标题、品牌色和多尺寸导出的同一 brief 做实测，不直接采信厂商榜单结论。
4. **OpenAI 披露一次前沿训练环境的网络隔离事件，并把基础设施红队纳入持续安全案例。** 官方称 2026-09-20 一次 DNS 配置问题让内部模型获得有限公网访问，随后暂停最强训练/评测负载、加固后于 10 月 1 日恢复部分工作。来源：[Securing our frontier model training environment](https://openai.com/index/securing-our-frontier-model-training-environment/)。**影响判断：**高能力 Agent 的安全边界已经延伸到 DNS、网络出口与集群控制面。**行动建议：**把“模型是否能意外出网”加入 Agent 基础设施威胁建模和演练清单。
5. **Firecrawl 上线 Government & Legal Index，把 3,000 万个美国政府页面整理成可搜索数据源。** 覆盖法规、地方条例、判例等页面，可在 ChatGPT、Claude 或 API 中检索。来源：[Firecrawl Changelog — Government & Legal Index](https://www.firecrawl.dev/changelog)。**影响判断：**垂直 RAG 的差异化越来越依赖索引覆盖、更新频率与可追溯来源，而不只是通用抓取。**行动建议：**法律场景试用时保存原始 URL、抓取时间和版本，避免把检索结果当作法律意见。
6. **Cerebras 公开万亿参数模型部署拆解，社区关注点从“能否运行”转向带宽、量化与服务拓扑。** 文章以约 3T 参数的开放模型为例，给出 4-bit 权重、8-bit KV cache 与多晶圆部署推算，并宣称可达 1,000–2,000+ tokens/s；该吞吐为厂商技术说明中的主张，非独立基准。来源：[Cerebras technical blog](https://www.cerebras.ai/blog/how-we-deploy-trillion-parameter-frontier-models-on-cerebras)、[Hacker News 讨论](https://news.ycombinator.com/item?id=50227356)。**影响判断：**超大模型服务的工程约束正在成为公开讨论核心。**行动建议：**评估时要求端到端并发、上下文长度、首 token 延迟和成本数据，不只看单请求吞吐。
7. **GitHub 日榜出现明显的“让编码 Agent 更会做设计”工具潮。** `hallmark` 与 `impeccable` 分别显示 1,317 和 1,092 “stars today”，同时 `security-audit-skill` 再度在榜。来源：[GitHub Trending](https://github.com/trending)。**影响判断：**可复用 skill 正在从提示词模板演化为带流程、规则和验收标准的工程资产。**行动建议：**先审查 skill 的指令边界和脚本权限，再把设计或安全技能接入真实仓库。

## 今天值得深入研究的 1 个主题

### 定时 Agent 的“调度成功”为什么不等于“业务完成”

Scheduled automations 把 Agent 变成长期运行系统，也把传统分布式系统问题重新带回产品层：调度器只能证明任务被投递，不能证明模型调用、工具执行、外部写入和最终验证全部成功。一个可靠闭环至少需要：稳定的任务幂等键；区分 `scheduled`、`started`、`tool-running`、`committed`、`verified` 的状态机；有界重试和死信队列；外部写入前后的内容哈希；以及失败时可恢复的人工接管入口。

最值得做的实验，是把一个“生成日报并同步两处”的任务拆成可验证阶段：本地源文件冻结、第一外部渠道回读、第二渠道提交、最终一致性校验。每一步都记录输入哈希和远端凭证，而不是用“API 返回 200”替代完成证明。这类工程能力会比再增加一个模型提示词，更直接决定 Agent 是否能进入生产。
