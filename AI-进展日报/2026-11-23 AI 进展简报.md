### 1. OpenAI 提议把困惑度纳入前沿模型的共同安全节奏线

- OpenAI 首席科学家 Jakub Pachocki 11 月 22 日公开内部预训练趋势，主张用困惑度（实践中通常跟踪交叉熵损失）与其他指标建立跨实验室的透明度和阶段性能力边界。
- **影响判断**：这是“模型安全标准”从下游 benchmark 前移到预训练阶段的信号，但还不是行业标准。文章自己承认跨实验室数据集不可比、困惑度不直接对应真实任务、无法覆盖推理强化带来的能力跃升，且未知理论下限。
- **行动建议**：研究或采购团队不要把单一困惑度当成通用智能分数；至少同时保留任务评测、危险能力评测、监控可见性和部署风险。OpenAI 报告数字来自内部代码库固定快照，不能直接外推到通用文本。
- 来源：[OpenAI：Perplexity and Intelligence](https://openai.com/index/perplexity-and-intelligence/) · [HN 讨论](https://news.ycombinator.com/item?id=50601525)

### 2. Microsoft Agent Framework 的两个 PyPI 版本被植入凭据窃取代码

- GitHub Advisory 与微软官方仓库 issue 确认，agent-framework 1.26.1 和 1.26.2 为恶意发布：通过 Python 启动时自动执行的 .pth hook 收集环境变量、凭据文件和云身份令牌；两个版本已从 PyPI 移除，当前已知干净版本为 1.26.0。
- **影响判断**：这不是普通依赖漏洞，而是会在任何 Python 进程启动时触发的供应链事件；仅“升级最新版”不能作为修复，因为两个连续版本都曾被污染。
- **行动建议**：使用过受影响版本的团队应按官方 issue 的顺序移除启动 hook、重建镜像并清理缓存、固定到 1.26.0、轮换可达密钥，并检查 11 月 17 日之后的 CI、云身份和外联日志。
- 来源：[GitHub Advisory GHSA-764m-3ppc-5m73](https://github.com/advisories/GHSA-764m-3ppc-5m73) · [microsoft/agent-framework issue #10411](https://github.com/microsoft/agent-framework/issues/10411) · [PyPI 项目页](https://pypi.org/project/agent-framework/)

### 本窗口的新安全信号：Python SDK Skills URI 校验问题

- **版本 / 日期**：问题影响 Python SDK 2.x 当前分支；issue 于 2026-11-21 建立，11 月 23 日仍无修复 release。
- **涉及能力**：动态 skills 的 skill:// URI、resources/directory/read 目录 URI 与 query/fragment 拒绝逻辑。
- **能力变化**：没有新能力；这是实现层的验证缺口报告。不能把 issue 写成已发布 CVE、已确认远程利用或已修复。
- **迁移影响**：使用 Python SDK 内置 Skills provider 或自定义动态资源映射的团队应做临时防护；不使用 Skills 扩展的普通 MCP tool server 不受这条特定问题直接影响。
- **试用建议**：拒绝任何 . / .. 路径段、query、fragment；解析后做根目录 containment 检查；为字面量和 percent-encoded 变体增加回归测试；等待官方 issue / PR / release 后再移除临时防护。
- 来源：[Issue #3884](https://github.com/modelcontextprotocol/python-sdk/issues/3884) · [Python SDK releases](https://github.com/modelcontextprotocol/python-sdk/releases)

## 今天值得深入研究的 1 个主题

### 困惑度能否成为前沿 AI 的“共同速度表”

OpenAI 的提案值得研究，不是因为一个指标能替代安全评估，而是它尝试把“何时应暂停、何时可继续训练”绑定到可提前观测的预训练信号。

建议从四个问题验证：

1. **可比性**：不同 tokenizer、数据混合和 held-out 集之间，是否能用 bits-per-byte、共同基准集或校准模型建立可比较量纲。
2. **预测力**：历史困惑度下降对哪些能力跃升有提前量；对推理、工具使用、长程 Agent 和危险能力是否仍成立。
3. **治理阈值**：如果设置能力边界，触发条件、验证者、例外、复测和解除条件由谁决定。
4. **互补指标**：把困惑度与下游任务、模型可解释性、CoT 监控有效性、部署控制和红队结果放在同一安全 case 中。

当前最重要的限制是：OpenAI 公布的主数据来自内部代码库固定快照，且文章明确承认它难以跨实验室直接比较、无法覆盖所有后训练能力。今天应把它看成“建立共同测量语言的提案”，不是“智能已被一个数字解释”。
