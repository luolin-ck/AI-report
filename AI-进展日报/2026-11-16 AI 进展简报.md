### Agent 工作流

- **从“全自动”转向“有界授权”。** ChatGPT Wallet 的每笔购买确认、Plannotator 的人工批注回传、LoopForge 的人工审批门，指向同一模式：高价值 Agent 不必完全自治，但必须清楚展示“准备做什么、谁批准、外部系统是否确认”。[Wallet](https://openai.com/index/introducing-chatgpt-wallet/) · [Plannotator](https://github.com/backnotprop/plannotator) · [LoopForge](https://github.com/Tencent/LoopForge)
- **模型内部后门需要运行时控制兜底。** Microsoft Research 的 Lazare 工作表明，休眠神经元可被重编程，使工具型 Agent 在隐藏触发条件下执行恶意命令。[研究说明](https://www.microsoft.com/en-us/research/blog/lazare-veni-foras-reprogramming-dormant-neurons-to-backdoor-ai-agents/) **适合落地的控制：** 命令级策略、网络/文件沙箱、敏感操作二次确认、独立于模型的审计。
- **“计划—审阅—执行”界面成为独立产品层。** [Plannotator](https://github.com/backnotprop/plannotator)将计划塑形、代码批注、团队共享和一键回传 Agent 放在同一工作区；11:15 Trending 显示 11,947 总 stars、866 stars today。对多人协作尤其有价值，因为它把自然语言反馈转成可回放的决策记录。

## 今天值得深入研究的 1 个主题

### Agent 的最后一公里：从“会做”到“可授权、可确认、可回滚”

ChatGPT Wallet、Plannotator、MCP Apps WebMCP bridge 和编码 Agent 浏览器工具看似属于支付、审阅、协议和调试四个赛道，实质上都在解决同一个问题：**Agent 准备改变外部世界时，系统如何把意图、权限与结果绑定在一起。**

建议用一个小型采购或发布流程做端到端实验，强制包含五个控制点：

1. **意图快照：** 在执行前固化商品/代码版本、参数、价格与来源。
2. **权限最小化：** 每个工具只获得本步骤所需的读取或写入权限。
3. **显式批准：** 高风险动作展示可理解的差异，而不是只弹出“允许/拒绝”。
4. **外部确认：** 以商家订单、Git 远端 SHA、部署状态等外部事实确认完成，不能只信 Agent 自报。
5. **幂等与回滚：** 重试不会产生重复订单/提交，失败后能恢复到明确状态。

**研究产出建议：** 把上述五点写成团队通用的 Agent action contract，随后分别套到支付、代码推送、文档写入和浏览器操作中。相比继续堆 prompt，这更可能降低真实事故率。
