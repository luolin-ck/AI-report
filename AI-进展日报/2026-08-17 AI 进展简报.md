## 分领域进展

### 设计生成

- Figma 在 7 月持续强化 AI 设计到可编辑资产：代码生成或捕获回 canvas 后可以更好绑定变量，auto layout 更接近 CSS，Figma Make 接入更高版本模型，并支持并行 AI 图像编辑。来源：[Figma release notes](https://www.figma.com/release-notes/)。这对产品团队的价值不是“省一张图”，而是减少从 prompt 到 design system 的重建成本。
- Figma Weave tools 已进入 Design open beta，覆盖 mockup 生成、风格迁移、换背景、改光照、文生矢量插画、套色板等图像与设计任务。来源：[Use Weave tools in Figma](https://help.figma.com/hc/en-us/articles/40779260614935-Use-Weave-tools-in-Figma)。适合做品牌素材变体、活动图和快速视觉探索，但仍需要设计师把输出纳入组件和变量体系。
- Claude Design 以设计系统导入、GitHub 同步、Claude Code `/design-sync` 和 MCP Server 为核心。来源：[Claude Design 官方博客](https://claude.com/blog/claude-design-stays-on-brand-for-daily-work)、[Claude Design 帮助文档](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)。它更适合已有品牌规范的团队，而不是只想快速生成一次性海报的人。
- 近期 YouTube 上 “Agentic Design Skills For Claude Code and Codex” 和 Figma MCP 自动化内容在开发者圈有可见传播。来源：[Agentic Design Skills](https://www.youtube.com/watch?v=gwduNjsOaNA)、[Figma Weave + MCP](https://www.youtube.com/watch?v=obQJ3uVZ2Rc)。口径限制：这里使用 YouTube 搜索结果可见播放量和发布时间，不代表全平台完整热榜。

### 数据采集 / RAG

- Firecrawl `/search` 的 2026-07-22 更新突出“相关片段直接返回”和更少 token 消耗，降低了把搜索结果塞进 RAG 或 Agent 上下文的清洗成本。来源：[Firecrawl changelog](https://www.firecrawl.dev/changelog)。适合替代“先搜索、再抓取、再清洗”的多段链路做第一轮检索。
- Firecrawl v2.11 的 Research Index、keyless endpoint access、PII redaction、deterministicJson 和 video discovery，显示网页数据采集正在走向可审计、可隐私处理和多媒体上下文。来源：[Firecrawl changelog](https://www.firecrawl.dev/changelog)。建议把 PII redaction 放进默认抓取链路，而不是等到入库后再补。
- AnySearch 在 Product Hunt 上以 agent/dev 搜索 API 出现，强调实时结构化搜索、过滤、去重和可信来源并行检索。来源：[AnySearch Product Hunt](https://www.producthunt.com/products/anysearch)。它的价值在于把搜索结果做成 Agent 可直接消费的结构，而不是返回一堆网页链接。
- Context.dev 和 Octolens 分别押注“网页上下文 API”和“社交数据层”。来源：[Context.dev](https://www.context.dev/)、[Octolens Agents](https://octolens.com/agents)。如果产品需要监控竞品、用户反馈或公开舆情，这类 API 比从零拼 crawler 更快，但要关注覆盖平台、限流、价格和合规。

### Agent 工作流

- BrowserAct 把浏览器自动化包装成 Agent 可调用层，卖点是处理登录、动态页面、上传和人类接管。来源：[BrowserAct Product Hunt](https://www.producthunt.com/products/browseract)。适合做内部运营自动化、数据录入、web app QA，但上线前要明确权限隔离和审计日志。
- Rerun 类 no-code agent 产品强调 24/7 执行、实时 dashboard 和审批门禁。来源：[Rerun Product Hunt](https://www.producthunt.com/products/rerun-2)。这类产品反映一个趋势：Agent 不只需要“能执行”，更需要可观测、可暂停和可批准。
- Hacker News 近期仍有 “Claude Code or Codex” 讨论，说明开发者选择正在从模型偏好变成工具链偏好：IDE、terminal、browser、权限、review、成本和团队规范都会影响选择。来源：[Ask HN: Claude Code or Codex?](https://news.ycombinator.com/item?id=48989357)。可复盘价值高于互动数字本身。
- Agent 安全继续是硬约束。The Hacker News 报道过 GhostApproval symlink 类问题和 AI coding agent 触发 endpoint 规则的案例。来源：[GhostApproval symlink flaws](https://thehackernews.com/2026/07/ghostapproval-symlink-flaws-could-let.html)、[AI coding agents triggering endpoint rules](https://thehackernews.com/2026/07/ai-coding-agents-found-triggering.html?m=1)。真实生产建议：默认把未知仓库、外部 prompt 和自动执行命令当成高风险输入。

## 今天值得深入研究的 1 个主题

**Agent 数据层与浏览器层正在成为基础设施。** Firecrawl、AnySearch、Context.dev、Octolens、BrowserAct、Rerun 共同指向一个方向：真正可用的 Agent 不只需要大模型，还需要可信搜索、网页抓取、结构化上下文、社交监听、浏览器执行、人类接管、审批和可观测性。下一步建议做一个 2 小时 spike：选一个真实业务任务，例如“每天监控 20 个竞品页面和社区反馈并生成变更摘要”，分别用 Firecrawl/AnySearch/Context.dev 加 BrowserAct 或现有 Playwright 实现，对比成功率、成本、错误恢复和人工审核时间。
