## 今日最值得关注

### 1. Anthropic 用生产流量验证环完成 Messages API 的 Rust 迁移

- **结论**：Anthropic 11 月 25 日披露，团队让 Claude 参与把核心 Messages API 从 Python 迁移到 Rust，但真正的突破不是“AI 写了多少代码”，而是用生产流量影子对比、沙箱内快速复现、生产外环和规则记忆组成验证系统。
- **来源**：[Anthropic 官方工程文章](https://www.anthropic.com/research/migrating-api-to-rust)
- **影响判断**：Rust 版在 4 月已通过约 98% 的测试，却只有约四分之一生产输入与 Python 行为一致；最终影子对比升到 99.6%。这说明 Agent 把代码生成成本压低后，行为等价验证会成为大型迁移的主要瓶颈。
- **行动建议**：做 Agent 驱动重写时，先建设旧/新实现的差异指纹、可快速重放的最小输入、生产 shadow 和防漂移检查；没有外部 verifier，就不要扩大自动改写范围。

### 2. Pydantic 发布 Pax，把 coding agent 拆成可替换的 Harness 能力

- **结论**：Pydantic 11 月 25 日发布终端 coding agent Pax，并宣布 Pydantic AI Harness 进入面向 1.0 的 beta 阶段。Coder、sandbox、MCP、Logfire、Agent Skills 与模型回退都被做成能力或插件，Pax 也可直接加载用户自己的 Pydantic AI Agent。
- **来源**：[Pydantic 官方发布](https://pydantic.dev/articles/pax-harness-beta) · [Pax 文档](https://pydantic.dev/docs/ai/pax/)
- **影响判断**：coding agent 正从单体 CLI 走向“框架 + harness + 可插拔运行面”。官方称 Harness 含 100+ capabilities，并在自有 Harness-Bench 单次运行中表现领先；该结果是厂商自测，不能当成独立通用排名。
- **行动建议**：适合 Python Agent 团队用一个真实仓库试跑文件编辑、命令权限、恢复、trace 和成本；注意 durable execution 尚未进入 Pax，beta API 也可能在 1.0 前变化。

### 3. Microsoft 给出五模型视频生成流水线，创意工作流开始按阶段选模型

- **结论**：Microsoft Foundry 11 月 25 日发布 fal 多模型视频生成实践，覆盖 LTX 2.5 Fast/Pro、Kling v3 Pro、MiniMax H3 Max/Max Turbo 五个 public preview 模型，并把概念探索、批准图像动效化与参考素材驱动的版本生成拆成不同阶段。
- **来源**：[Microsoft Foundry 官方文章](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/build-a-multi-model-video-generation-workflow-with-fal-on-microsoft-foundry/4573786)
- **影响判断**：设计生成的竞争点不再只是“哪一个模型最好”，而是能否在同一生产管线里按速度、质量、参考输入、区域与成本路由模型。任务是异步的，结果链接会过期，且 fal 服务运行在 Microsoft 设施之外。
- **行动建议**：先固定一份产品素材做文本转视频、图生视频和参考转视频 A/B；保存 request ID、提示词、输入资产、模型版本、结果和人工评分，并在发送敏感资产前审查数据外流与合规要求。

### 4. Foundry Toolbox + Tool Search 把工具治理与上下文成本拆开处理

- **结论**：Microsoft 近期文章展示了共享 Toolbox：把 OpenAPI、远程 MCP server 和 Foundry 内置工具放进一个受管、带版本的 MCP-compatible endpoint；Tool Search 则按需返回工具定义，而不是把整个 schema 目录塞进上下文。
- **来源**：[Microsoft Foundry 官方文章](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/from-inline-tools-to-a-shared-toolbox-in-microsoft-foundry/4575475)
- **影响判断**：Toolbox 解决“多 Agent 重复接入与治理”，Tool Search 解决“工具太多导致 token 与选择成本上升”，二者不是同一层。官方示例中 Toolbox 版本使用了更少输入 token，但没有给出可泛化的绝对节省比例。
- **行动建议**：先把两个 Agent 都需要的一个只读工具放进 Toolbox，验证身份、稳定/版本化 endpoint 与监控；只有目录变大后再启用 Tool Search，并保留高频工具 pinning。

### 5. Google 用多 Agent 社交模拟构造“可验证的人际推理”评测

- **结论**：Google Research 11 月 25 日开源社交推理评测框架：给目标角色一个隐藏动机，让用户代理从主观视角讲述互动，再测试助手能否还原动机，从模拟初始条件中获得可验证 ground truth。
- **来源**：[Google Research 官方文章](https://www.research.google/blog/verifiable-social-reasoning-for-llm-assistants/) · [开源代码](https://github.com/google-research/google-research/tree/master/user_mediated_social_reasoning)
- **影响判断**：研究发现模型容易受用户 framing 影响，需要比人类更多细节，也没有充分利用澄清问题。它把“会不会顺着用户偏见给建议”从主观案例变成可重复评测，但模拟社会并不等同真实关系。
- **行动建议**：客服、教练、健康和陪伴类产品应加入“主动澄清、列出未知信息、给出多种解释”评测，不要只测回答是否温和或让用户满意。

### 6. OpenAI 把 Healthcare 配置开放到 Responses API

- **结论**：OpenAI 11 月 24 日更新模型发布说明，API 组织可通过 Responses API 使用面向医疗场景的 Astra、Sol 配置；启用 web search 后可查询专用医疗索引并给出引用，不要求先拥有 ChatGPT for Healthcare workspace。
- **来源**：[OpenAI Model Release Notes](https://help.openai.com/en/articles/9624314-model-release-notes)
- **影响判断**：专业垂直配置开始从独立工作区下沉到通用 Agent API，便于把检索、引用和业务流程结合；官方同时强调它不能替代专业判断，PHI 处理仍受单独要求约束。
- **行动建议**：只在明确数据边界和审批链的受控试点中评测检索召回、引用正确性、过期指南、拒答与升级人工，不把“医疗专用配置”写成诊断或合规保证。

### 7. Photoshop 2027 争议说明“AI 功能是否可感知”已经影响专业工具准入

- **结论**：PetaPixel 11 月 24 日引述《纽约时报》发言人称，其投稿摄影师在任务中应避免 Photoshop 2027（28.0.0+），原因是部分生成式 AI 功能可能不易被用户识别，并可能使照片元数据被标记为 AI 编辑。
- **来源**：[PetaPixel 报道与 NYT 发言人回应](https://petapixel.com/2026/11/24/new-york-times-prohibits-photographers-from-using-photoshop-2027/) · [Adobe MAX 2026 功能清单](https://news.adobe.com/news/downloads/pdfs/2026/11/creative-cloud-release-max-2026.pdf)
- **影响判断**：对新闻摄影、取证和合规设计，问题不只是“用户有没有主动生成内容”，还包括软件是否明确显示哪些操作会触发生成式处理和 Content Credentials。工具版本因此可能直接成为组织政策边界。
- **行动建议**：创意软件采购应建立版本白名单、功能级 AI 标识、导出元数据检查和可回滚路径；高真实性场景优先使用能关闭生成式功能并保留审计记录的工具链。

### Agent 工作流

- **Anthropic Rust 迁移** 给出可复用的三层验证环：沙箱内快速差异复现、生产 shadow 外环、把人工 review 转成规则/测试的 memory loop。
- **Pydantic Pax** 让 coding harness、sandbox、MCP、observability 和技能都能独立替换，适合需要自带模型、自带运行环境或自带 Agent 的团队。
- **Foundry Toolbox / Tool Search** 把工具目录治理和 schema 按需加载分开；对于工具数量少的 Agent，官方仍建议直接暴露所有工具，不必为了“Agent 化”增加发现层。

### 热门应用

- **值得小规模试：Pax**。适合已使用 Pydantic AI、希望把内部 Agent 直接放进终端的 Python 团队；beta 阶段应锁版本并保留退出路径。
- **值得试：fal 多模型视频流程**。适合品牌概念片、产品动效和参考素材驱动的 campaign 变体；必须把数据出境、临时 URL 和人工质检加入流程。
- **谨慎试：Healthcare configurations**。适合证据检索和研究辅助，不适合无人工监管的诊断、治疗或 PHI 流程。
- **值得复盘：Photoshop 2027 版本政策**。设计管理者应把 AI 能力开关、内容凭证与组织内容规范一并写进工具采购与升级门禁。

### 能力与迁移建议

- **本次没有协议迁移项**。生产端继续分别锁定 Core、SDK、扩展、Reference Servers 和宿主支持版本。
- **生态实现的共同方向是按需披露**：Pax 把技能和工具做成插件，Foundry Tool Search 按需返回 schema，Skills over MCP 提供 manifest/resource 分层；目标都是减少不必要上下文，但权限判断仍要在工具执行侧完成。
- **Toolbox 不等于 MCP Core**：它是 Microsoft 的受管产品层，可承载 MCP、OpenAPI 与内置工具。跨供应商方案应把协议兼容与平台治理能力分开验收。
- **行动建议**：先用只读工具验证身份、版本、schema 缓存、错误语义和审计，再增加写操作；Skills 只提供程序知识，不应绕过工具级授权和确认。

## 模型 / 平台更新

- **OpenAI**：Healthcare model configurations 进入 Responses API，重点是专用检索索引与引用，不是新的通用旗舰模型。
- **Google Research**：可验证社交推理框架开源，揭示助手容易受主观叙述影响且不足以主动澄清；它是评测研究，不是 Gemini 产品功能更新。
- **Microsoft Foundry**：fal 五模型视频工作流与 Toolbox/Tool Search 给出创意模型路由和大工具目录治理的具体实现。
- **Anthropic**：Messages API Rust 迁移说明生产系统的大规模 Agent 编码已可行，但官方把“verification is the new bottleneck”作为主要结论。
- **通用模型**：本窗口未发现 OpenAI、Anthropic、Google 的新通用旗舰模型正式发布；不把公开测试者关于 Claude Opus 5.6 的猜测当新品。

## 今天值得深入研究的 1 个主题

### 当代码生成不再稀缺，工程组织要把“验证带宽”当核心基础设施

Anthropic 的迁移最值得复用的不是 Rust，也不是“Claude 写了 80%+ 合并代码”的历史比例，而是验证架构：

1. **先定义可比较对象**：输入验证、prompt 构造、token 化、safety、输出分类、计费字段分别生成差异指纹。
2. **把反馈压到秒级**：Agent 在沙箱中从指纹猜测触发条件，自造可读取的最小请求，让旧/新实现并跑并加回归测试。
3. **再让生产流量裁决**：测试 98% 通过仍可能只有约 24% 生产输入一致，shadow 才能发现真实分布中的长尾和高频小差异。
4. **把人工修正变成系统资产**：review 意见进入规则、lint、测试和跨实现同步门禁，避免下一批 Agent 重复犯错。
5. **把同一思路扩展到非代码任务**：Google 社交推理用可控隐藏动机构造 ground truth；视频生成用固定 brief 与人工评分表；医疗检索用引用核对与专家升级。

可行动的研究问题是：**团队每增加一名 Agent，是否同步增加了可重放样本、确定性检查、生产 shadow、人工 review 容量和失败归档？** 如果没有，生成吞吐越高，未验证变更堆积越快。
