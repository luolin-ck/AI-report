## 今日最值得关注

1. **Google DeepMind 发布 Genie 4，把世界模型推进到“实时可操控、原生音频、可用于训练 Agent”的阶段。** [官方页面](https://deepmind.google/models/genie/)显示它能用文本实时改变天气、镜头和角色，并把 Gemini 4 Argon 的多步计划送入模拟环境；但目前只是受信任测试者的研究预览，连续交互约几分钟，物体恒常性、文字和多人交互仍会漂移。**影响判断：** 设计生成正在从静态画面/视频转向可交互世界与仿真数据。**行动建议：** 游戏、机器人和空间设计团队先把它列入 2027 原型路线，而不是现在就替换生产引擎。
2. **OpenAI 发布 GPT-6.1 Terra，把高频电脑操作的成本压到更适合规模化自动化的区间。** [官方发布](https://openai.com/index/introducing-gpt-6-1-terra/)称其标准 API 价格为每百万输入/输出 token 1/5 美元，支持视觉理解、表单填写、视频编辑与编码；OpenAI 自测中，Terminal-Bench 4.0 最大推理档为 50.3%。**影响判断：** 电脑操作 Agent 的瓶颈开始从“能否完成”转向“单位任务成本与授权边界”。**行动建议：** 用一组真实桌面任务对 Terra 与更强模型做成功率/成本双指标 A/B，不要只看厂商 benchmark。
3. **Anthropic 公布 Claude 参与六家药物研发机构的早期结果，重点不只是分子设计，而是端到端科研运营。** [官方案例](https://www.anthropic.com/research/early-progress-drug-development)包括约 3.5 万个抗体设计、1,061 页制造文档复核、监管文件初稿和临床试验规划；其中 Enveda 报告人工复核时间从 25 小时以上降至不足 3 小时。**影响判断：** 垂直 Agent 的价值来自数据、实验、文档和人类审批组成的闭环。**行动建议：** 医疗团队先复刻“文档复核 + 证据追踪”这类低风险流程，并保留所有厂商数据仍属早期、以临床前为主的限制。
4. **OpenAI 与 Oracle 把企业应用、数据权限和 ChatGPT 工作流做成一体化入口。** [官方公告](https://openai.com/index/oracle-apps-in-chatgpt/)披露 Oracle 有 13 万名活跃 ChatGPT 用户和 9.5 万名活跃 Codex 用户，并预告 Oracle AI Workspace、AI Security Mesh、AI SMB Bundle 与 App Composer。**影响判断：** 企业 Agent 的竞争重点转向受控数据访问、统一身份、预算和审批。**行动建议：** 做企业 Agent 时先画权限/数据流图，再决定聊天入口和模型。
5. **GitHub Copilot SDK 开始支持面向组织的 server-to-server 身份。** [GitHub Changelog](https://github.blog/changelog/2026-10-27-github-copilot-supports-server-to-server-authentication/)显示，GitHub App 可凭只读 `Copilot Requests` 权限和短期安装令牌代表组织发起请求，使用量归属组织并受模型政策、预算和支出控制。**影响判断：** 无人值守 Agent 不必绑定某个员工账号，审计和撤销更清晰。**行动建议：** 平台团队评估工作负载身份，禁止长期复用个人 token。
6. **Agent Skills 被捐赠给 Linux Foundation 旗下 AAIF，标准治理从单一厂商走向中立社区。** [Anthropic 公告](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)称已有 70 多个平台接入，下一步路线包括版本化发布、正式提案流程和安全指南。**影响判断：** Skill 的可移植性和供应链安全将成为跨 Agent 生态的公共基础设施。**行动建议：** 团队应为 SKILL.md 建立来源、版本、哈希和执行权限清单。
7. **抓取/RAG 主窗口没有 Firecrawl 新版本，社区热点转向“持久知识结构”而不只是即时检索。** [Firecrawl changelog](https://www.firecrawl.dev/changelog)截至本次检查仍以 10 月 22 日 Government & Legal Index 为最新产品更新；同时 [LLM Wiki](https://github.com/nashsu/llm_wiki)进入 GitHub Trending，主张把文档持续整理成相互链接的本地知识库。**影响判断：** RAG 产品开始补“知识维护与演化”层。**行动建议：** 评估时增加增量更新、溯源、冲突处理和可编辑性，而非只测单次问答。

## 分领域进展

### 设计生成

- **Genie 4 是本窗口最重要的设计生成信号。** 它不是普通视频生成器，而是可用键鼠导航、用文本在运行中改变场景的世界模型；官方还展示了 Gemini 4 Argon 规划、Genie 4 渲染的机器人仿真链路。现阶段仅研究预览，适合关注交互原型、游戏预演、影视预可视化和合成训练环境，不适合生产承诺。
- **Gemini 4 Argon 的 10 月 27 日案例是后续能力展示，不是新的模型首发。** [Google 案例](https://blog.google/products-and-platforms/products/gemini/gemini-4-argon-in-action/)展示了从零编写约 5,000 行数学代码生成 3D 图书馆、把实景照片转成可玩赛道，以及联动 Blender MCP、Nano Banana 和 Veo 的多 Agent 视觉流水线。对设计团队的启示是：未来差异不只在生成模型，而在任务拆解、工具编排和可编辑中间产物。
- **Figma/Canva 基线保持。** 截至 11:07 CST，未发现晚于此前已覆盖的 Figma Build by Design、Code Layers、Specs、Payload 或 Canva Craft 的重大官方发布；不把旧功能重新包装成 10 月 28 日新品。

### 数据采集 / RAG

- **Firecrawl：未发现 24—48 小时内的产品/版本更新。** 官方 [changelog](https://www.firecrawl.dev/changelog)最新仍是 10 月 22 日 Government & Legal Index，10 月 21 日公司增强 benchmark 与 10 月 20 日免费 people data 均已在前期简报覆盖。今天的实用动作是继续验证索引覆盖、来源时间戳、robots.txt 和重定向安全，不追逐重复营销内容。
- **LLM Wiki 把 RAG 改造成持续生长的知识库。** [仓库](https://github.com/nashsu/llm_wiki)是跨平台本地桌面应用，增量把文档转成互相链接的 wiki，并提供 MCP server；相比每次重新检索生成答案，它更适合长期项目、个人研究档案和团队知识维护。需要重点复核许可、隐私、冲突合并及大规模索引性能。
- **来源质量比抓取量更重要。** Anthropic 的药物研发案例说明，生产级 RAG 往往要连接原始实验数据、制造文件与审计记录；仅有网页向量库无法承担高风险决策。

### Agent 工作流

- **Copilot server-to-server 身份**让定时任务、后台服务和组织 Agent 使用短期安装令牌，费用、模型政策和撤销权仍归组织；这是从“个人助手”走向“平台工作负载”的关键基础能力。
- **Oracle AI Workspace/App Composer**把聊天入口、企业数据、应用构建和权限控制放在同一体系；值得关注的不是“又一个聊天框”，而是能否在采购、财务和安全等流程中实现最小权限和审批可追溯。
- **Claude 药物研发案例**给出了垂直 Agent 的真实形态：科学设计、实验数据、制造文档、监管初稿、人类复核和外部实验室共同组成长期工作流，模型只是其中一层。

## MCP / Agent Skills 更新

### 结论

**MCP 核心协议未发现 10 月 26—28 日官方新版；当前 FINAL 基线仍为 `2026-07-28`。** [官方扩展仓库](https://github.com/modelcontextprotocol/ext-skills)仍将 `io.modelcontextprotocol/skills` 稳定规范绑定到该协议版本；[MCP conformance 页面](https://plan.modelcontextprotocol.io/conformance)也把 `2026-07-28`列为 FINAL，`2026-12-15`仍是 NOT READY。不要把参考服务器、SDK 或 Agent Skills 治理变化误称为 MCP 核心协议升级。

### 本轮真实变化：Agent Skills 进入 AAIF

- **版本 / 日期**：2026-10-22 的治理迁移；不是 Agent Skills 新语法版本，也没有新的版本号。
- **更新来源**：[Anthropic 公告](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)与 Linux Foundation [AAIF 公告](https://www.linuxfoundation.org/press/agentic-ai-foundation-announces-four-new-projects-agent-skills-open-responses-openenv-and-opensandbox)。
- **涉及技能名称**：变化对象是 Agent Skills 标准、名称/Logo、GitHub 组织与 `agentskills.io` 域名；不是新增一个具体业务 skill。Anthropic 披露 70 多个平台已集成，并称已发布约 100 万个 skills、安装近 2.8 亿次——这些是厂商统计，不是本次独立审计结果。
- **能力变化**：当前文件结构仍是最少一个 `SKILL.md` 加可选 scripts/references/assets；短期能力没有自动升级。实质变化是未来计划加入版本化发布、正式 proposal 流程和作者/安装安全指南，并由 Anthropic、Google、OpenAI 等维护者以个人身份参与。
- **迁移影响**：现有本地 skill 无需立即重写；但上游仓库、域名、release 和签名/哈希策略可能逐步变化。团队应停止“永远跟 main”，改为固定 release 或 commit SHA，记录来源和权限，升级时重新评审脚本。
- **适合谁试用**：已有多个 Agent 宿主、需要跨 Codex/Cursor/Claude/GitHub Copilot 复用流程的团队最受益；单一宿主个人用户可先观望版本化发布落地。
- **行动建议**：建立 Skill SBOM：名称、来源、版本/commit、SHA-256、脚本执行权限、网络权限、负责人和回滚版本。

### Build with Agent Skills / `mcp-server-dev` 基线

[Build with Agent Skills](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/develop/build-with-agent-skills.mdx)当前仍列出三项参考技能，**本窗口未发现清单变化**：

- `build-mcp-server`：入口技能，先询问接入对象、用户、动作面、交互和认证，再选择 Remote HTTP、MCP App、MCPB 或本地 stdio。
- `build-mcp-app`：为服务器增加可在聊天中渲染的表单、选择器、图表和仪表盘。
- `build-mcpb`：把本地 stdio server 与运行时打包为可安装 `.mcpb`，适合访问本机文件、桌面应用和 localhost。

三项均由 `SKILL.md` 与按需读取的 `references/` 组成；适合 MCP 开发者减少部署形态、认证和工具设计上的重复决策。没有证据表明 10 月 26—28 日发布了第四项官方 skill。

### 相关但不应混淆的基线

- **MCP Skills 扩展**：`io.modelcontextprotocol/skills` 负责通过 MCP 发现/分发 skill；规范明确远端 skill 是高风险提示注入面，必须保留来源、校验大小/摘要，并避免无批准的本地代码执行。
- **Reference Servers v2.1.0**：10 月 25 日 [release](https://github.com/modelcontextprotocol/servers/releases/tag/v2.1.0)修复 filesystem/everything/fetch 八项漏洞，已在 10 月 26 日简报覆盖；今天只保留升级基线，不重复称新品。`mcp-server-fetch` 当前安全版本为 `2026.10.24`。
- **OpenAI Plugins 文档**：当前 [Skills 概念页](https://developers.openai.com/plugins/concepts/skills)明确 MCP server 提供实时数据、认证和动作，Skill 提供可复用工作流；这是实现边界，不是新的 MCP 协议版本。

## 模型 / 平台更新

### 从“生成内容”到“生成可行动世界”：Genie 4 + Agent 的新评测框架

Genie 4 最值得研究的不是画质，而是它把环境、音频、可操控性和 Agent 训练接到一起。建议建立四层评测：第一层看视觉/音频一致性；第二层看物体恒常性、因果和可控性；第三层让 Agent 在场景中执行有明确成功条件的任务；第四层检查合成环境迁移到真实系统后的偏差。这样能避免把精选演示误判为通用世界模型，也能帮助设计工具团队把“可编辑、可测试、可恢复”作为下一代生成产品的核心指标。
