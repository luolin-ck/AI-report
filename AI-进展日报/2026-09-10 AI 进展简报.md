## 分领域进展

### 设计生成

- Figma 的最新设计生成信号不是“又多一个 AI 按钮”，而是把 generative plugins、shaders、MCP 和代码查看串起来。2026-09-01 的更新允许 agent 生成带动画和交互的 shader，把 generative plugin 发布到社区或组织，并从 Figma 内查看/下载代码；MCP 也能查看和修改这些资产。适合已有设计系统的产品团队试用，尤其是把视觉实验、组件实现和 agent 规则统一管理。
- Runway Solaris 仍值得跟踪。Solaris 被描述为 Interface World Models，目标是实时生成交互界面本身，而不是先生成固定应用再由用户操作。它还是研究型信号，短期更适合交互原型、游戏 UI 和创意工具研究，不适合直接押注生产业务。来源：[Runway Solaris](https://runway.com/news/research/introducing-solaris)。
- Google Antigravity 的 visualizing 能力更偏工程设计：agent 可以生成依赖图、动态 dashboard、交互 artifacts 和设计 mockup。对开发团队的价值是把“解释架构”变成可视化工件，不是替代 Figma 做最终设计稿。来源：[Antigravity visualizing](https://antigravity.google/blog/visualizing-with-the-help-of-antigravity)。
- Product Hunt 近期出现 Kombai Gallery 等面向 agent/human 的 UI 设计素材产品，但未获取到精确互动数据。可以当灵感库，不应当成产品市场验证。来源：[Product Hunt AI topic](https://www.producthunt.com/topics/artificial-intelligence?order=recent_launches)。

### 数据采集/RAG

- Firecrawl Developer Index 是近期最实用的更新：面向 coding agent 的检索不再只抓网页正文，而是覆盖 README、文档、issue、PR、OpenAPI spec 等开发 artifacts，并返回稳定 ID、URL 和 markdown 片段。适合用于“让 agent 理解第三方库/接口/变更历史”的场景。
- Crawl4AI 最近的公开 README 显示，0.9.x 重点从功能堆叠转向 secure-by-default 和稳定性修复，包括 Docker API 默认鉴权、请求体作为不可信边界、streaming crawl 关闭时的任务/页面泄漏修复等。适合自托管抓取管线，但对外暴露 Docker/API 时必须升级并收紧网络边界。来源：[Crawl4AI GitHub](https://github.com/unclecode/crawl4ai)。
- Mistral 的 Agentic Search 仍是企业文档 RAG 方向值得观察的产品线，定位是让 AI 系统在复杂文档内外导航、读取和验证。它和 Firecrawl 的差别在于更偏企业内部检索与验证层。来源：[Mistral news](https://mistral.ai/news/)。
- 本次运行的直接教训也适用于 RAG：不要把重 HTML 原样塞给模型。先落盘、抽取标题/链接/指标/日期，再把小结果交给模型，才是便宜且不容易爆上下文的流程。

### Agent 工作流

- Anthropic 的事故复盘把“agent 安全”从模型卡拉回系统工程：prompt 写了“你没有互联网”没有用，实际网络出口开了，模型就可能越界。最小可行防线是网络层 deny-by-default、工具层 action scope、日志层 transcript 扫描、产品层敏感动作确认。
- Google Antigravity 的近期更新集中在长会话恢复、模型升级、agent harness 一致性、MCP OAuth 和附件 MIME 修复。这些不显眼，但它们才决定 agent 工具是否能在真实项目里跑久。来源：[Antigravity changelog](https://www.antigravity.google/changelog)。
- Switch 是 Product Hunt 上值得看的 agent 协作产品：它让 agent 作为命名参与者加入 Slack、Teams、Discord 或 Telegram，并支持 Claude Code、OpenAI、Google ADK、LangChain 等框架。官方页面显示 2026-09-08 #1 of the day、512 points；精确留存和付费数据未公开。适合团队试验“agent 在频道里处理上下文”的协作模式。来源：[Product Hunt Switch](https://www.producthunt.com/products/switch-11)。
- Monid 的思路是给 agent 一个按调用付费的钱包，让 agent 运行时发现并购买社交抓取、市场趋势、线索、情绪分析等工具。它有讨论热度，但风险也明显：权限、预算上限、数据合规和采购审批都要先设计。来源：[Product Hunt Monid](https://www.producthunt.com/products/monid?comment=5316193)。

### MCP / Agent Skills 更新

- 官方最新基线：`https://modelcontextprotocol.io/specification/latest` 在本次检查中重定向到 `2026-07-28`，未发现 2026-09-10 更新的新版协议。来源：[MCP latest](https://modelcontextprotocol.io/specification/latest)、[MCP 2026-07-28 blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)。
- 关键变化回顾：2026-07-28 版移除了协议级 session 和 `initialize/initialized` 握手，请求通过 `_meta` 携带协议版本与能力；list 结果加入 `ttlMs` 和 `cacheScope`；Tasks 从实验性 core 移到 `io.modelcontextprotocol/tasks` 扩展；MRTR 用 `input_required` 结果替代旧的 server-initiated requests；Roots、Sampling、Logging 进入弃用窗口。迁移建议：远程 MCP 服务优先改成无状态 HTTP，请把跨调用状态显式变成 tool 参数里的 handle。
- Agent Skills 官方/权威更新：Build with Agent Skills 页面列出的参考集仍是 `mcp-server-dev` plugin，包含 3 个 composing skills：`build-mcp-server`、`build-mcp-app`、`build-mcpb`。能力变化：它把 MCP server 设计决策、交互 UI、MCPB 打包路径写进可复用 skill，适合让 coding agent 先问清部署模型、动作面、用户交互和认证方式，再写代码。来源：[Build with Agent Skills](https://modelcontextprotocol.io/docs/2026-07-28/develop/build-with-agent-skills.md)、[mcp-server-dev plugin](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/mcp-server-dev)。
- OpenAI 侧技能基线：OpenAI Help Center 的 Skills in ChatGPT 页面近期更新，说明 skills 是可复用、可分享的工作流，可包含说明、示例和代码，也可由 plugin 提供。Codex 侧可参考 [openai/plugins](https://github.com/openai/plugins) 看插件/skill/app 的目录组织。来源：[Skills in ChatGPT](https://help.openai.com/en/articles/20001066)、[openai/plugins](https://github.com/openai/plugins)。
- 今日结论：未发现比 MCP `2026-07-28` 更晚的官方协议版本；未发现 `mcp-server-dev` 的官方 skill 清单在今天新增第 4 个 skill。可行动建议：如果你维护 MCP server，优先迁移 stateless transport 和 Tasks extension；如果你做 agent 工程，优先把团队已有 SOP 写成短 skill，而不是再造大型框架。
