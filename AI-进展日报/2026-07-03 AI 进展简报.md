## 今日最值得关注

1. **Open Design 0.13.0 把“AI 设计生成”从一次性出图推向可恢复、可交付的工作流。** 来源：[Open Design GitHub Releases，2026-07-02](https://github.com/nexu-io/open-design/releases)。影响判断：设计生成工具正在补齐会话恢复、模型选择、运行诊断和 PPTX/PDF 导出，价值不只在“生成 UI”，而是在多轮修改后保留上下文并交付文件。行动建议：如果你在做产品原型或设计到代码，优先测试“长会话恢复 + 导出 + 设计系统预览”，不要只用单轮 prompt 评估效果。

2. **Firecrawl 的 web-scale `/monitor` 说明 RAG 数据采集正在从定时爬取转向事件驱动。** 来源：[Firecrawl Product Updates，2026-07-01](https://www.firecrawl.dev/blog/category/product-updates) 和 [/monitor 文章入口](https://www.firecrawl.dev/blog/web-monitoring-launch)。影响判断：对竞品监控、政策更新、价格页变更、招聘/融资信号等场景，触发式抓取比每天全量重跑更省 token，也更适合 Agent 自动行动。行动建议：把“每天爬全站”改成“监控关键查询或 URL，变更后再抓取、摘要、入库”。

3. **Z.ai 的 ZCode 正式把 GLM-5.2 包装成桌面 Agentic Development Environment。** 来源：[ZCode 官方文档](https://zcode.z.ai/en/docs)、[Z.ai GLM-5.2 发布说明，2026-06-16](https://z.ai/blog/glm-5.2)。影响判断：ZCode 的卖点是 1M 上下文、长任务、Git 状态、终端和远程/移动跟进，直接对标 Cursor、Claude Code、Codex CLI 等编码代理。行动建议：适合用大型仓库、跨文件重构和长测试任务做试用；重点记录真实上下文保持、失败恢复和权限确认体验。

4. **SonarQube 正在把代码质量验证嵌进 Claude Code、Copilot、Codex、Cursor 等代理内循环。** 来源：[SonarSource，2026-07-01](https://www.sonarsource.com/blog/secure-ai-coding-agent-workflows-plugin/)。影响判断：AI 代码生成速度继续上升，瓶颈会转向“生成后谁负责验证”；统一的质量门、MCP Server、CLI 和 Agent App 会成为企业采用多代理开发的基础设施。行动建议：团队如果已经使用两个以上编码代理，应先统一 lint/test/SAST/secret scan 的代理内触发方式，再扩大使用范围。

5. **VS Code Agent hooks 进入预览，把代理行为控制变成可配置生命周期事件。** 来源：[VS Code 文档，2026-07-01](https://code.visualstudio.com/docs/agent-customization/hooks)。影响判断：hooks 能在 `PreToolUse`、`PostToolUse`、`SessionStart` 等节点运行确定性命令，用于拦截危险命令、自动格式化、记录审计和注入上下文。行动建议：先从两个低风险 hook 开始：`PreToolUse` 阻止破坏性 shell 命令，`PostToolUse` 对改动文件运行格式化或最小测试。

6. **Anthropic 继续强化“中高价位 Agent 模型 + 企业平台落地”的组合。** 来源：[Claude Sonnet 5，2026-06-30](https://www.anthropic.com/news/claude-sonnet-5)、[Fable 5 重新部署，2026-06-30/07-01](https://www.anthropic.com/news/redeploying-fable-5)、[Claude in Microsoft Foundry GA，2026-06-29](https://azure.microsoft.com/en-us/blog/claude-in-microsoft-foundry-is-now-generally-available/)。影响判断：Sonnet 5 主打更低成本的 agentic coding 和工具使用，Foundry GA 则解决企业采购、治理、数据驻留和 Azure 计费问题。行动建议：个人和小团队先用 Sonnet 5 做日常编码/自动化；企业团队关注 Foundry 中的 Entra ID、RBAC、零数据保留和模型路由。

## 分领域进展

### 设计生成

- Open Design 0.13.0 的重点不是新增一个“更会画 UI”的模型，而是围绕真实设计工作补齐流程：会话恢复、BYOK 预设、OpenDesign Cloud 状态、导出、设计系统 chip/preview、run lifecycle tracing。对设计到代码来说，这些能力比单张截图质量更关键，因为团队需要持续迭代和交付。
- Google 的 Nano Banana 2 Lite 与 Gemini Omni Flash 组合值得设计团队关注：前者适合 4 秒级草图与批量风格探索，后者适合把静态设计或产品图转为短视频演示。官方 demo 里包括室内设计 Space Lift 和 e-commerce Omni Product Studio，说明 Google 正在把“设计生成”从图片扩展到视频化产品表达。
- 可观察信号：Open Design release notes 多次提到 design-system、brand preview、PPTX/PDF export、workspace/team，这说明 AI 设计工具正在从个人玩具进入团队交付场景。

### 数据采集/RAG

- Firecrawl `/monitor` 是今天最值得跟的 RAG 数据层进展。它把“网页变化”作为触发器，让 Agent 在新页面出现或关键页面更新时再启动抓取、摘要、嵌入和通知。
- Firecrawl 近期路线还包括 Research Index、Keyless、Question/Highlights、`/search`、`/parse` 和 Browser Sandbox。对 RAG 产品来说，核心启发是把数据采集分成四层：发现、抓取、解析、变化检测，而不是把所有问题都交给通用浏览代理。
- Google Deep Research 和 OpenAI GeneBench-Pro 都在强调“复杂问题需要多步检索、判断和可审计来源”。这会推动 RAG 系统从问答检索升级为“研究任务执行器”，输出不仅是答案，还包括方法、证据和失败边界。

### Agent 工作流

- ZCode 把 GLM-5.2 的长上下文能力放进桌面 ADE，功能覆盖任务、文件、终端、浏览器上下文、Git 状态、远程控制、飞书/微信 Bot 和安全确认。它的关键竞争点是能否在长任务中保持计划、状态和验证，而不是单次补全速度。
- VS Code Agent hooks 和 SonarQube 插件都指向同一件事：Agent 需要可控内循环。未来成熟的编码代理工作流会像这样运行：先读取约束，再生成改动，生成后立即跑格式化/测试/静态分析，失败则回到代理修复。
- Google Interactions API 已将 Gemini 模型与 Managed Agents、后台执行、工具组合、Deep Research、媒体生成放进一个统一接口。它虽不是 48 小时内的新发布，但仍是观察 Google agent-first 开发栈的基础入口。

### 热门应用

- 近期热度最高的应用方向仍是“AI 编码桌面/CLI”：ZCode、Claude Code、Cursor、Codex、OpenCode、Antigravity 相关讨论都在争夺同一类用户。值得试，但评估标准要从“能不能写代码”升级为“能不能规划、改完、验证、解释风险”。
- “图像到视频/产品图到广告短片”正在成为热门工作流。Google 的 Nano Banana 2 Lite + Omni Flash 给了官方链路，适合电商、设计、短视频团队快速做 3 到 5 个候选方向，再由人工挑选和剪辑。
- Perplexity Comet、Antigravity 2.0 等话题在社交平台热度高，但本轮没有找到足够新的官方发布细节。今天只作为观察项，不作为主要事实来源。

### 开源项目

- Open Design 是今天开源/本地优先设计生成方向最值得看的项目。它已经不只是“Claude Design 替代品”，而是在堆桌面应用、agent 适配、技能、设计系统、导出和团队化入口。
- Z.ai 的 GLM-5.2 官方说明强调 MIT 许可、1M context、IndexShare、agentic RL 和 coding benchmark。对开源模型应用开发者来说，最值得验证的是长上下文真实工程任务，而不是只看榜单。
- Firecrawl 继续保持“可作为产品 API，也可作为 Agent 工具层”的路线。对想做 RAG/抓取产品的人，Firecrawl 的 API 设计和 MCP/CLI 生态本身就是可学习对象。

### 模型/平台更新

- Anthropic：Sonnet 5 发布后成为 Free/Pro 默认模型，并进入 Claude Code 和 Claude Platform；Fable 5/ Mythos 5 重新开放，同时引入更细的网络安全 safeguard 和 jailbreak 严重度框架讨论。
- Microsoft：Claude in Microsoft Foundry GA，企业可通过 Azure 账户、Entra ID、RBAC、Foundry Agent Service、数据区域和 Azure 计费使用 Claude。这对有合规要求的企业比“某模型分数更高”更实际。
- Google：Nano Banana 2 Lite 和 Gemini Omni Flash 面向 AI Studio、Gemini API、Enterprise Agent Platform；Interactions API 仍是 Gemini agent 与多模态工作流的统一接口。
- OpenAI：6 月 30 日发布 GeneBench-Pro，强调科学代理的高阶判断和可审计分析；6 月 26 日预览 GPT-5.6 Sol/Terra/Luna，重点是编码、科学、网络安全能力与分层安全栈。由于这些不是今天新发，今天作为近一周补充观察。

## 今天值得深入研究的 1 个主题

**主题：Agent 工作流的“可验证内循环”会成为下一阶段生产力工具的分水岭。**

过去一年大家主要比较模型能不能生成代码、UI 或报告；今天的信号显示，真正进入团队生产后，竞争会转向以下问题：

- 代理开始工作前，能否获得正确的项目约束、设计系统、质量标准和安全策略。
- 代理执行时，能否在关键生命周期点触发确定性检查，而不是完全依赖模型自觉。
- 代理完成后，能否产出可交付文件、测试结果、审计记录和可追溯来源。
- 失败时，能否从同一会话恢复，并用工具结果继续修复，而不是重新开局。

建议今天做一个小实验：为一个真实仓库配置 `PreToolUse` 和 `PostToolUse` 两个 hook，接入格式化、单测和 secret scan，然后分别用 Claude Code/Codex/Cursor/ZCode 跑同一个修复任务。记录三项指标：首次通过率、修复轮次、人工介入点。这比看榜单更能判断哪个工具适合你的团队。
