3. **OpenAI 把 Agent 工作流推进 CAD、PCB 与制造仿真。** [OpenAI](https://openai.com/index/accelerating-engineering-for-the-physical-world/) 11 月 3 日展示 GPT-6/Astra 协同完成设备外壳、PCB、软件集成，并与 Chip Ganassi Racing、Mazda 探索逆向 CAD、空气动力学和碰撞安全。**影响：**computer use 正从浏览器扩到专业工程软件。**行动：**先选“扫描件转可编辑 CAD + 人工可制造性审核”这类边界清晰任务，不把研究展示当无人值守生产能力。
4. **Firecrawl 将实时选举记录封装成免费垂直数据源。** [Firecrawl](https://www.firecrawl.dev/changelog/election-records-launch) 11 月 3 日在 Alexandria 上线 470 场美国众议院/参议院竞选的结果、资金来源与现任投票记录。**影响：**RAG 数据采集继续从通用 crawl 转向带语义和时效承诺的专用索引。**行动：**政治/公共记录场景必须保存抓取时点、原始州/监管来源和更正链，不把聚合召回直接当事实终局。

## 分领域进展

### 设计生成

- **Prototype connections → code layers（11 月 3 日）。** Figma agent 现在能读取 frame 的交互连线，再生成 code layer，减少为复杂 flow 重复描述状态跳转的提示成本；功能仍是 open beta。[官方来源](https://www.figma.com/release-notes/)。适合产品原型和设计到代码团队试用，验收应覆盖 hover/click、返回路径、空状态与错误状态。
- **新连接 GitHub 仓库默认允许克隆（11 月 3 日）。** Figma 对新 repository connection 默认开启 cloning，管理员可逐仓库关闭，既有连接不变并向所有计划推出。[同一发布页](https://www.figma.com/release-notes/)。这是更顺滑的 code context，也是一项权限默认值变化；含商业秘密的组织应复核仓库 allowlist 与审计日志。
- **近 7 日补充：Figma 自研编辑模型。** [Figma 工程文章](https://www.figma.com/blog/training-a-figma-fluent-editing-model/) 披露以原生文件格式、合成编辑请求、确定性 validator、视觉 judge、SFT 与 RL 训练专用模型；早期流程使用超过 25 万示例，未发布的新模型在内部 eval 中为 77.8%，Sol 6.1 为 76.9%。这些是厂商内部评测，不能当跨产品通用排名，但值得借鉴“结构检查 + 视觉判断 + 设计师校准”的评测拆分。

### Agent 工作流

- **Cheminformatics Skills：领域 skill 不等于让 LLM 自由算化学。** Google 的实现把数据库搜索、匹配分子对分析、预测模型与反应方案编排交给 Agent，把计算交给 RDKit/ChEMBL/PubChem 等可检查工具；官方也明确稀疏数据、跨实验室噪声和窄动态范围仍限制预测。[来源](https://deepmind.google/blog/agentic-cheminformatics-with-google-antigravity/)。这套分工适合迁移到材料、金融和合规场景。
- **Copilot × JetBrains Air：Agent 订阅成为可插拔执行后端。** ACP 让 Air 的 agent picker 直接选择 Copilot，本地任务使用 IDE 上下文，云任务在新 VM 的 Docker 容器执行且任务间不保留状态。[来源](https://github.blog/changelog/2026-11-03-github-copilot-is-now-available-in-jetbrains-air/)。适合 JetBrains 团队并行处理独立任务，需特别补齐成本上限和使用量可见性。
- **Postman 插件争议暴露 trust boundary。** 一个仍开放的 [Postman issue](https://github.com/postmanlabs/postman-app-support/issues/14370) 报告桌面端升级后自动安装 Codex/Claude 插件、startup hook 和远程 MCP，并尝试信任自身 hook；作者明确说尚未在干净机器复现，也不声称数据外泄。它是待核实的个案而非已确认的普遍漏洞，但足以提醒：插件安装、hook 信任、MCP 启用与全局路由规则必须由用户显式批准并可审计撤销。

## 今天值得深入研究的 1 个主题

### Agent Skills 正在成为新的软件供应链：怎么做来源、完整性与批准

Google 用 Cheminformatics Skills 封装专业工作流，Figma 把设计交互和代码仓库交给 agent，MCP 则用 `skills/list/get`、digest、来源命名空间和 capability negotiation 做远程分发；与此同时，Postman issue 提醒我们，插件/hook/MCP 若在用户不知情时改变全局 Agent 行为，会直接越过信任边界。值得建立一套统一门禁：来源身份与签名、清单/digest、读取与激活分离、脚本/hook/tool 权限逐项批准、可撤销安装、运行日志和秘密扫描。Beta 阶段先把这套安全模型跑通，比追求更多 skill 更重要。
