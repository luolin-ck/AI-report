# 2026-10-23 AI 进展简报

> 观察窗口：优先覆盖 2026-10-21 至 2026-10-23（Asia/Shanghai）公开信息；资料不足处扩展到 2026-10-16 至 2026-10-23，并逐项标注。动态指标以文中访问时点为准。

## 今日最值得关注

1. **有界决策正从通用生成中独立出来。** [OpenAI Decisions API](https://openai.com/index/decisions-api/) 于 2026-10-22 正式进入 GA，原生支持选择、真假判断与评分，单请求最多 400 个问题；[Baseten](https://www.baseten.co/blog/the-best-decision-models-in-the-world-mammoth-1-and-elephant-1/) 则在 2026-10-21 发布开放权重的 mammoth-1 27B 与 elephant-1 9B。**影响：** Agent 的分类、路由、护栏和风险评分开始形成独立模型层。**行动：** 用同一回放集比较准确率、校准、p95 延迟与总成本，再决定托管或自部署；“最高 10 倍提速”等为厂商口径，本轮未独立复现。
2. **企业 Agent 的落地单元正在变成“连接器 + 内部技能库 + 治理”。** [Uber 与 OpenAI](https://openai.com/index/uber-chatgpt-work-rollout/) 2026-10-22 宣布把 ChatGPT Work 从 1,000 人试点扩到全球 30,000 多名员工，并连接企业日历、邮件、文件与协作工具。**影响：** 规模化部署的瓶颈从账号开通转向权限、技能模板、培训和效果度量。**行动：** 先选 2—3 个高频流程定义数据边界与成功指标，不把合作公告等同于已验证 ROI。
3. **设计生成的壁垒正在从“首图好看”迁移到“结构可编辑”。** [Canva Research](https://www.canva.com/newsroom/news/introducing-canva-research/) 于 2026-10-21 公开其设计 AI 实验室路线，强调层级、字体、布局、品牌一致性、可控性与可编辑性。**影响：** UI/UX 生成与设计到代码产品需要证明生成结果能进入真实编辑链路。**行动：** 新增“元素独立编辑、跨尺寸/品牌保持、人工精修轮数”三项评测；本轮没有发现 OpenDesign 或 Claude Design 的可核验新版本。
4. **RAG 数据采购开始以字段质量而非页面数量竞争。** [Firecrawl 更新日志](https://www.firecrawl.dev/changelog) 在 2026-10-21 发布公司信息增强基准，关注字段准确性与缺失；2026-10-20 又将 Alexandria 人员/公司数据接入 ChatGPT 与 Claude 插件。**影响：** 抓取平台正向结构化数据连接器扩展。**行动：** 建立 50—100 家金标公司集，测准确率、空值率、时效、来源可追溯性与单位成本；二者分别是厂商基准与第三方数据插件，不是抓取引擎核心版本。
5. **长时 Agent 的竞争核心是运行时，而不只是模型。** [Notion](https://www.notion.com/blog/notion-ai-more-for-less) 2026-10-19 公开第六代 Agent harness：队列式持久执行、浏览器/计算机使用、上下文外置、模型路由与独立动作复核。**影响：** 断点续跑、预算治理和安全复核决定 24 小时级任务能否可靠运行。**行动：** 对自有 Agent 做故障恢复、上下文压缩、路由漂移与高风险动作升级测试；速度和成本数据均为厂商自测。
6. **Agent 获得更多权限后，运行时隔离成为热点。** [NVIDIA OpenShell](https://github.com/NVIDIA/OpenShell) 在截至 2026-10-23 11:24 的 Hacker News 公开快照中获得 321 points、166 条评论。**影响：** 网络白名单、凭据代理、文件隔离和审计不再是“平台以后再补”的能力。**行动：** 仅在非生产环境做攻击面与数据外泄演练，先验证策略边界再扩大权限。
7. **Gemini Deep Research 旧预览端点今天到停用日。** [Google 官方弃用表](https://ai.google.dev/gemini-api/docs/deprecations) 将 `deep-research-pro-preview-12-2025` 的停用日期列为 2026-10-23，并推荐迁移至 `deep-research-preview-04-2026`。**影响：** 固定旧模型名的研究 Agent 与评测流水线可能中断。**行动：** 立即检索配置并完成迁移，对输出深度、流式行为、预算和超时重新回归；这是今日生效的旧公告，不是今日发布。

## 分领域进展

### 设计生成

本窗口内最实质的一手进展来自 2026-10-21 的 [Canva Research](https://www.canva.com/newsroom/news/introducing-canva-research/)。其研究重点不是再做一个文生图入口，而是让文字、图像、字体和布局保持结构关系，并把品牌一致性、文化语境、可控性和可编辑性纳入模型目标。Magic Layers 的学习式分层、Lucid Origin 的可控低延迟生成，以及 Image-to-Video “每 GPU 小时生成量提升 70%”均来自 Canva 自报，未独立复现；这是一项官方设计 AI 实验室与技术路线进展，不应写成所有研究能力已全面上线。

对 UI/UX、原型生成和设计到代码团队，建议把评测从单张截图扩展为完整生产链：结构分层是否正确、组件语义能否保留、品牌规则能否跨尺寸延续、设计师能否低成本回退和重做。本轮没有发现 OpenDesign、Claude Design 在 2026-10-21 至 2026-10-23 的可核验官方新版本，因此不做旧闻包装。

### 数据采集 / RAG

[Firecrawl](https://www.firecrawl.dev/changelog) 的两项更新应分开理解：

- **2026-10-21，公司信息增强基准（主窗口）。** 官方称以数百家美国公司比较数据准确性与缺失情况，但本轮没有独立复核完整样本、逐供应商排名或原始结果。可复用的是方法：对每个字段同时测准确率、空值率、刷新时间、来源可追溯性与成本，而不是只看“覆盖多少网站”。
- **2026-10-20，Alexandria 插件接入（7 日补充）。** Firecrawl 称 ChatGPT 与 Claude 插件可访问 Alexandria 的 2.7 亿以上公司和人员记录，并提供每月 1,000 免费 credits；规模与额度为厂商表述，数据质量、适用法域、去重率和删除机制未独立审计。这是第三方结构化数据插件，不是 Firecrawl 抓取引擎核心版本更新。

适合销售情报、招聘研究和企业知识图谱团队小规模试用，但生产前应完成字段级金标、个人数据合规与来源透明度审查。

### Agent 工作流

2026-10-22 正式 GA 的 [OpenAI Decisions API](https://openai.com/index/decisions-api/) 与 2026-10-21 开放权重的 [mammoth-1 / elephant-1](https://labs.baseten.co/articles/mammoth-1-and-elephant-1-frontier-decision-models) 形成一组清晰对照：前者是托管的低延迟有界决策端点，后者允许团队自部署、校准和控制数据驻留。适合工单路由、垃圾与钓鱼检测、提示护栏、模型选择与量表评分，但高风险决策仍应设置拒绝阈值和人工升级；两家的性能数字均为厂商评测。

企业侧，[Uber 全员部署案例](https://openai.com/index/uber-chatgpt-work-rollout/) 显示，连接器、获批集成、内部技能库和培训治理正在成为 Agent 平台的标准配套。运行时侧，[Notion 第六代 Agent](https://www.notion.com/blog/notion-ai-more-for-less) 把持久任务、上下文外置、动作复核和模型路由放到同一层；其中 Notion MCP 记忆同步已上线，而 Skills via MCP 仍是即将推出，不能混写为现有能力。

### 热门应用

- **ChatGPT Work 企业工作平台。** 为什么火：Uber 从 1,000 人试点扩到 30,000 多名员工，提供了少见的组织级公开案例。适合企业 AI、IT 治理与知识工作自动化团队关注；值得复盘其技能治理和培训体系，但公告尚无节省工时、任务成功率等结果指标。
- **Notion 长时 Agent。** 为什么火：从五分钟级交互转向 24 小时以上任务，直击“代理能开始但不能可靠完成”的痛点。适合知识管理与 Agent 基础设施团队；值得试验断点恢复和安全复核，不应直接接受“最高快 50%”“成本下降”等厂商数据。
- **Firecrawl + Alexandria。** 为什么火：把原始网页处理压缩成 Agent 可直接消费的人员与公司实体。适合快速原型，是否进入生产取决于字段质量、地区覆盖和个人数据治理。

## 今天值得深入研究的 1 个主题

### 长时 Agent 的可靠性栈：从“模型回答”到“可恢复任务系统”

Notion 的公开架构、Uber 的组织部署和 OpenShell 的安全讨论指向同一个结论：Agent 成败越来越取决于任务队列、断点恢复、上下文外置、动态模型路由、权限隔离、动作复核与预算治理，而不是只换更强模型。建议做一次最小故障注入实验：让同一 Agent 在长任务中经历网络中断、工具超时、上下文膨胀、权限拒绝和模型切换，记录恢复点、重复副作用、总成本与人工接管率。这个主题直接连接产品体验、基础设施、安全与组织治理，比继续比较单一模型榜单更有复用价值。
