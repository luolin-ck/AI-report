## 今日最值得关注

### 1. GPT-6.2 进入 ChatGPT 普通聊天页，但不是 Work / Codex 模型更新

- OpenAI 于 11 月 23 日开始向 Plus、Pro、Business、Enterprise 推送面向普通聊天页优化的 GPT-6.2；官方说明它基于 GPT-6.2 Sol，强化复杂指令、联网信息查找、图像理解与适时追问。
- 官方在 Chat tab 测试中给出的图像理解成绩为 **71.7%**，对照 GPT-6 的 **47.4%**。系统卡同时将该版本的网络安全能力标为 Critical，生物与化学能力标为 High，因此能力升级伴随更严格的监控与使用边界。
- **影响判断**：普通用户现在能直接获得更强的多步骤信息整理与视觉理解，但不能据此推断 Work、Codex 或 API 模型同步换代；OpenAI 明确说本次不改变 Work 与 Codex 的底层模型。
- **行动建议**：用一组包含图片、长约束和联网比较的真实任务做回归；企业管理员同时检查模型策略、数据保留与高风险领域审批。
- 来源：[ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes) · [GPT-6.2 in ChatGPT System Card](https://deploymentsafety.openai.com/gpt-6-2-chatgpt/safety-overview)

### 2. GLM-5.4 用 Loop Transformer 把“推理深度”变成可扩展维度

- Z.ai 11 月 23 日发布 GLM-5.4，称其为首个旗舰级 Loop Transformer：在 750B 基座上将 28 层循环两次，并用门控更新、跨循环 KV 共享和稀疏注意力索引复用控制部署成本。
- 官方声称其智能水平可比 2T—3T 参数模型，并把 coding 延展到视频、游戏、3D、CAD 与网络安全；但 API 仍是 Coming Soon，开放权重也要等安全加固后再发布。
- **影响判断**：如果后续第三方复现实证成立，模型扩展会从“只加参数”转向参数规模、循环深度与自适应计算共同优化；目前性能与成本数字主要来自厂商自测。
- **行动建议**：先把它列入编码与长链工程评测候选，不要在 API、权重和可复现基准未就绪前迁移生产流量。
- 来源：[GLM-5.4 官方技术博客](https://z.ai/blog/glm-5.4) · [Hacker News 讨论](https://news.ycombinator.com/item?id=50609685)

### 3. Figma Agent 正式进入 FigJam 与 Slides，设计 Agent 从画布扩展到会议—规格—演示链

- Figma 11 月 23 日宣布 Agent 在所有付费计划的 FigJam 与 Figma Slides 中正式可用，两端都支持附件与连接器；可从 Hex、Slack、Asana 等带入上下文。
- 它能把杂乱 FigJam 板整理为包含总结、下一步和 Agent 可执行内容的 Spec，也能从 Spec 和品牌模板生成演示稿、拆分拥挤页面、收紧结论并起草讲稿。
- **影响判断**：这是比“提示词生成一个界面”更有组织价值的变化——Agent 开始承担从讨论素材到可执行规格、再到沟通交付物的跨工件转换。
- **行动建议**：设计团队可用一次真实评审会验证：来源是否可追溯、Spec 是否保留约束、品牌模板是否被遵守、生成结论是否需要人工改写。
- 来源：[Figma Release Notes](https://www.figma.com/release-notes/) · [Figma Blog](https://www.figma.com/blog/)

### 4. Firecrawl 把抓取与数据聚合进一步垂直化到招聘 Agent

- Firecrawl 11 月 23 日推出面向 ChatGPT 与 Claude 的招聘工具，官方口径覆盖 **2.5 亿+候选人、2600 万+公司**，并可根据候选人的公开内容生成个性化触达。
- 其“比 Clay 低 88%”只针对 2026 年 11 月年付标价下“档案 + 工作邮箱”和 Clay Launch 常见 6-credit record 的特定比较，不能泛化成所有工作流的成本结论。
- **影响判断**：Firecrawl 正从通用网页抓取层转成面向岗位的知识与动作入口；真正壁垒会从“能抓到”转向数据新鲜度、身份匹配、合规与可解释来源。
- **行动建议**：招聘团队只用公开且与岗位相关的数据做小规模试点，记录匹配准确率、过期档案、退订、地区隐私规则和人工复核成本。
- 来源：[Firecrawl Recruiting Tools](https://www.firecrawl.dev/changelog/recruiting-tools) · [Firecrawl Changelog](https://www.firecrawl.dev/changelog)

### 5. Codex Security 给出 Agent 化安全审查的四条落地原则

- OpenAI 11 月 23 日给出 Codex Security 实践：为 Agent 提供系统特定上下文、把审查嵌入开发流程、按风险设定范围与报告阈值、让每个发现可检查。
- 文中明确区分 `AGENTS.md`、`SECURITY.md`、威胁模型与知识库，并展示本地 working tree、分支 diff、GitHub alerts 与 CI 的 CLI 路径。
- **影响判断**：安全 Agent 的差异化不只在模型，而在“它知道什么边界、扫了什么、遗漏什么、为什么报告”；没有威胁模型和覆盖清单的自动扫描很容易变成高噪声检查器。
- **行动建议**：从一个高风险仓库开始，先提交最小威胁模型与 `SECURITY.md`，用已知漏洞和已知误报校准阈值，再扩大到自动 PR 审查。
- 来源：[OpenAI Developers：Building security review into your SDLC](https://developers.openai.com/blog/building-security-review-into-your-sdlc-with-codex-security)

### 6. Vercel 用 canary URL 持续审计 AI Gateway 的 ZDR 执行

- Vercel 11 月 23 日宣布 AI Gateway 对推理供应商运行 Zero Data Retention canary 审计：为供应商、模型与审计轮次生成唯一 URL，把它放入正常推理提示，并监控是否出现外部访问。
- ZDR 供应商不应保留、检查或抓取提示内容，因此 canary URL 不应收到请求；非 ZDR 组合则作为正向对照。
- **影响判断**：这是把一次性合同和安全审计补成持续检测的实用做法，但它只能检测部分“内容被读取/抓取”的路径，不能证明供应商绝对没有保留数据。
- **行动建议**：AI 平台团队可复用“唯一诱饵 + 正向对照 + 可归因观察”的模式，同时保留合同、独立审计、日志和事件响应。
- 来源：[Vercel：AI Gateway now runs canary ZDR audits](https://vercel.com/changelog/ai-gateway-now-runs-canary-zdr-audits)

### 7. Vercel AI Gateway 增加专用结构化抽取模型

- Vercel 同日为 AI Gateway 接入 extraction models，首个模型 ScaleDown Extract-1 可从文本、图片和 PDF 中抽取文本值或列表，返回 0—1 置信度，文本输入还能返回字符偏移。
- 当前仅通过 AI SDK `ai@7.0.176` 及以上的 `experimental_extract` 使用，字段缺失时返回 `null`。
- **影响判断**：对发票、合同和记录处理来说，专用抽取 API 比“让通用聊天模型返回 JSON”更便于做置信度门槛与人工复核；experimental 状态意味着接口仍可能变化。
- **行动建议**：优先试结构固定、可抽样核验的文档，明确低置信度和缺失字段的回退，不把单次抽取结果直接写入关键系统。
- 来源：[Vercel：AI Gateway now supports extraction models](https://vercel.com/changelog/ai-gateway-now-supports-extraction-models)

## 分领域进展

### 设计生成

- **Figma Agent in FigJam / Slides** 是今天最重要的设计更新：它把研究与会议素材转为 Spec、再转为品牌化演示，不再只停留在画布内生成。
- **Stitch Skills** 仍在 GitHub Trending，页面快照为 422 stars today / 12,340 总 stars，但其发布已在 11 月 23 日简报覆盖，本次只作为“设计技能链持续受关注”的趋势信号。
- **值得验证的边界**：连接器带入的数据权限、品牌模板遵从、Spec 中决策与假设的区分、演示稿引用是否仍能回到原始材料。

### 数据采集 / RAG

- **Firecrawl Recruiting Tools** 表明通用抓取正在向垂直数据产品演进：候选人、公司、公开内容与触达生成被装进同一 Agent 工作流。
- Firecrawl 11 月 23 日还发布了 Agent Web 安全指南，强调把检索与执行分权、内容检查与动作授权分开、用确定性策略限制外发目的地与载荷。其 prompt-injection check 是一道输入侧防线，不等于 Agent 免疫注入。
- **RAG 团队行动**：保留原始 URL、抓取时间、实体匹配依据与过期策略；对招聘和销售等个人数据场景额外做隐私与地区合规审查。
- 来源：[Firecrawl：AI agent security](https://www.firecrawl.dev/blog/ai-agent-security)

### Agent 工作流

- **Codex Security**：把 `SECURITY.md`、威胁模型、知识库、扫描范围和 coverage artifact 组合成可审计的安全 Agent 上下文。
- **Vercel ZDR Canary**：展示了“用合成诱饵验证基础设施声明”的持续控制方式，可迁移到提示泄漏、索引污染和第三方连接器测试。
- **Figma 跨工件 Agent**：会议板、Spec、Slides 与外部连接器构成一个可串联的知识工作流，价值取决于权限、引用与审批是否随工件传递。

### 热门应用

- **Figma Agent**：适合产品、设计、研究和售前团队把会议材料快速整理成规格与演示；值得试，但最终决策与品牌审查仍要有人负责。
- **Firecrawl Recruiting**：适合招聘研究和候选人发现；是否值得规模化取决于数据新鲜度、邮箱准确率、合规与回复质量，而不是覆盖数字本身。
- **ScaleDown Extract-1**：适合文档录入与审核辅助；有置信度和字符偏移是优势，但 experimental API 与专用模型供应商锁定需要评估。

## 今天值得深入研究的 1 个主题

### 从“会做事的 Agent”到“可验证的 Agent 流水线”

今天最值得研究的不是单一模型，而是五个层面开始收敛：

1. **输入与来源**：Firecrawl 把网页、垂直数据和提示注入检查放进可追溯检索层。
2. **跨工件组织**：Figma 把会议板、Spec、Slides 与外部连接器串成一个交付链。
3. **专用执行接口**：Vercel extraction model 用字段、置信度和字符偏移替代模糊 JSON 提示。
4. **安全上下文**：Codex Security 要求威胁模型、`SECURITY.md`、扫描范围和 coverage 一起进入审查。
5. **运行中验证**：ZDR canary 用可归因诱饵持续检查基础设施声明是否被违背。

可以用一个最小闭环做验证：选一份含图片与结构化字段的真实业务文档，由受控检索层读取，抽取字段并生成 Spec / Slides，再由安全 Agent 检查数据外发、权限和关键代码；全程记录来源、置信度、工具调用、批准、拒绝与最终人工签字。若无法回答“每个结论来自哪里、每个动作由谁授权、哪些内容没检查”，就还不是生产级 Agent 流水线。
