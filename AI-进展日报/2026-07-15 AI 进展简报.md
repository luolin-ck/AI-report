## 分领域进展

### 设计生成

Figma 的最新方向是把设计、代码、动画、shader 和 agent skills 放到同一画布，重点不再是“AI 生成一张图”，而是让设计资产进入可编辑、可协作、可交付的链路。对 OpenDesign、Claude Design、Stitch、Figma Make 一类产品来说，下一阶段的差异会落在：是否能读取现有设计系统、是否能输出可维护代码、是否能让设计师保留足够控制权。

GitHub 日榜里的 hallmark 值得单独看：它不是新的 UI 生成器，而是面向 Claude Code、Cursor、Codex 的“反通用 AI UI”设计 skill。近期增长说明开发者已经意识到“AI 生成界面”最容易失败在视觉密度、间距、组件语义和真实业务信息层级，而不是失败在能不能写出 React。

### 数据采集 / RAG

本轮未检索到 Firecrawl 官方近 24-48 小时重大版本发布；与 Firecrawl 直接相关的可验证新消息不足，因此不编造 release。更值得关注的是数据采集侧的治理变化：canary token 论文证明网站可以通过唯一标记追踪 LLM 背后的抓取链路，这会影响未来企业抓取、AI 搜索和 RAG 数据管线的合规设计。

Agentic RAG 的近期论文将单 LLM、朴素 RAG 和多 agent RAG 放在受监管决策流程里比较，结论是多步骤、缺失信息和需要外部检查的任务更适合结构化 agent 管线。对业务系统来说，RAG 不应只做“向量库 + 回答”，而应显式区分检索、规则校验、第三方数据检查、置信度与人工复核。

### Agent 工作流

OpenAI 的 ChatGPT Work、Claude Cowork 的移动/Web 云端执行，以及 GitHub 上 Graphify/skills 的增长共同指向一个趋势：agent 正在从“单次帮我做事”变成“可安装、可复用、可审计的工作单元”。[微软早期 2026 CLI agent rollout 研究](https://arxiv.org/abs/2607.01418)给出一个有用基线：组织采用不均匀，留存与工程活跃度相关，采用者合并 PR 数量有明显提升，但成本和真实价值需要持续衡量。

企业落地时应把 agent workflow 当作小型软件系统管理：版本、权限、输入输出、日志、失败回滚、人工审批、成本上限都要定义清楚。否则“能跑起来”的 demo 很容易变成权限过大、上下文污染、凭据泄露或不可复盘的黑盒流程。

### 热门应用

Google Images 的新首页是“搜索前推荐 + 视觉生成”的组合，说明 AI 搜索正在吞并 Pinterest 式发现体验。它适合内容、电商、家居、旅行和灵感收集场景，但也会提高内容方对图片结构化标注、真实来源和版权策略的要求。

Spotify 的 Talk to Spotify beta 把听歌、播客、有声书历史变成聊天上下文。它值得产品经理关注：用户不是为了和 Spotify 聊天而聊天，而是为了更快找到“我想听但说不清”的内容；这类垂直 AI 的核心指标应是探索成功率、会话后播放/收藏行为，而不是聊天轮数。

Claude Reflection 是另一个方向：让用户审视自己如何使用 AI。它短期像“AI 版使用周报”，长期可能成为 AI 素养、企业合规和工作方式复盘的入口。

## 今天值得深入研究的 1 个主题

**Agentic RAG 的“可审计数据链路”。** 过去 RAG 关注召回率、chunk、embedding 和 rerank；现在更关键的问题是：数据从哪里来、谁抓的、是否遵守访问策略、何时过期、回答引用了哪一段、哪些结论是推断而不是原文。建议用一个真实业务流程做小实验：用 Firecrawl/Crawl4AI/Browserbase 任一抓取工具采集 20 个网页，记录抓取身份、时间戳、原文 hash、清洗规则、失败原因，再用 agent 做多步回答，输出每条结论的来源链和置信度。
