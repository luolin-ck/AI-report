## 今日最值得关注

1. **Google 把 Gemini 4 Carbon 与可观察的多 Agent 编排一起推向开发者。** [官方发布](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/)称 Carbon 面向长时程 Agent、复杂编码、科学推理与网络安全，并在 Antigravity 预览 `/swarm`：一个提示拆成可实时追踪的 Agent 团队。影响是“强模型”开始与并行工作区、角色分工、对抗验证绑定销售；建议只在高价值复杂任务试用，并记录任务成功率、验证成本和每任务费用，而不是只看榜单。
2. **AlphaProof Code 把 Agent 生成推进到机器可检查的证明。** [Google DeepMind](https://deepmind.google/blog/introducing-alphaproof-code/)称其用多模型 Agent 与人类专家，在四周内生成超过 600 万行 Lean，形式化验证 Signal 核心密码协议，并把需要人工二次检查的范围压到约 1%。影响是高风险代码的价值链可能从“生成更多”转向“生成证明 + 小范围人审”；建议安全、金融和基础设施团队先研究其开源验证产物，而非直接把结果外推到普通业务代码。
3. **Figma Motion 把物理参数和交付预览拉进设计系统。** [Figma 11 月 10 日更新](https://www.figma.com/release-notes/)新增动画风格预览、可配置质量/刚度/阻尼的物理弹簧，以及 Lottie 导出前预览；弹簧还可保存为设计系统资产。影响是动效规范开始像颜色、间距一样被复用；建议设计团队选一个移动端交互，把 spring token、平台差异和 Lottie 回放纳入验收。
4. **Google × Adobe 正在把创意 Agent 嵌入搜索、聊天和办公入口。** [合作公告](https://blog.google/company-news/inside-google/company-announcements/adobe-google-partnership-integration/)披露 Drive/Gmail 到 Acrobat 的直接编辑入口、Gemini/AI Mode 中的 Adobe 连接器、Gemini Enterprise 中的 Adobe CX Enterprise Coworker，并探索 Photoshop 近实时图像编辑模型。多数能力仍是“将推出/探索”，但方向明确：设计工具不再只争夺独立工作台；建议关注权限继承、资产回写和品牌审计是否跟得上跨应用生成。
5. **Firecrawl 把检索能力包装成可直接完成求职任务的垂直工具。** [11 月 10 日更新](https://www.firecrawl.dev/changelog/job-tools)称 Firecrawl plugin 可在 ChatGPT/Claude 中匹配 700 万+职位、检索 2.5 亿+人物并研究目标联系人近期动态。这不是抓取引擎核心版本升级，而是“通用抓取 + 专业数据源 + Agent 动作”的应用化；建议招聘/求职场景先抽样验证职位新鲜度、人物身份和外联合规。
6. **OpenAI 为 GPT Image 2 给出明确迁移截止日。** [官方弃用页](https://developers.openai.com/api/docs/deprecations)显示 `gpt-image-2` 与 `gpt-image-2-2026-04-21` 将于 2027-02-10 下线，建议迁移到 `gpt-image-2.6-sunburst` 或 `gpt-image-2.6-flare`。影响是依赖旧模型一致性、编辑参数或成本曲线的设计生成流程需要回归；建议立即建立同一提示、参考图、蒙版和 SVG/GIF 输出的双跑样本集。
7. **Agent Skills 热度继续上升，但“可评测、可更新”比技能数量更重要。** [GoogleChrome modern-web-guidance](https://github.com/GoogleChrome/modern-web-guidance)用本地语义检索把现代 Web API、性能和无障碍指导按需注入 Agent，并公开 guided/unguided 评测；今日 Trending 中 `anthropics/skills`、`mattpocock/skills` 同时高位。建议团队优先建设技能版本、来源、触发条件、回归测试和遥测退出机制，不要把下载一个技能目录等同于能力已可靠上线。

## 分领域进展

### 设计生成

- **动效成为设计系统的一等资产。** Figma Motion 的弹簧参数可复用、风格可上画布预览、Lottie 可在导出前回放，减少“设计稿看起来对、交付后运动感变了”的断层。[来源](https://www.figma.com/release-notes/)
- **创意工具向跨应用 Agent 迁移。** Google 与 Adobe 的合作把 Acrobat、创意连接器和 CX Enterprise Coworker 放到 Drive、Gmail、Gemini、AI Mode 等入口；现阶段应区分已宣布集成与仍在探索的 Photoshop 实时编辑能力。[来源](https://blog.google/company-news/inside-google/company-announcements/adobe-google-partnership-integration/)
- **开源侧出现“Agent-ready 设计系统”热度。** `meta/astryx` 今日在 GitHub Trending 的页面标签为 3,108 stars today，仓库把自己定义为可完全定制、面向 Agent 的开源设计系统。值得产品设计/前端团队审查其 token、组件、代码生成和治理边界，但热度不等于生产成熟度。[仓库](https://github.com/meta/astryx)
- **图像模型迁移进入倒计时。** 旧 `gpt-image-2` 的下线日期已确定；设计团队应把人物/品牌一致性、局部编辑、透明背景、SVG 与 GIF 纳入迁移测试，而不是只比较单张“最好看”的样图。[来源](https://developers.openai.com/api/docs/deprecations)

### 数据采集 / RAG

- **Firecrawl 今日变化是垂直检索产品化，不是爬虫内核升级。** 新求职工具把职位、人物与近期动态组合为 Agent 可调用流程，官方口径为 700 万+职位和 2.5 亿+人物。[来源](https://www.firecrawl.dev/changelog/job-tools)
- **知识工程含义：检索层正在从 URL/文档召回升级为“领域对象 + 动作”。** 对 RAG 团队而言，评估维度应从抓取成功率扩展到实体去重、时效、来源追踪、隐私与行动前验证。
- **去重说明：** 11 月 9 日简报已覆盖 Firecrawl SEC Filings，本期不重复包装；11 月 10 日的“200K stars + plushies”是社区营销节点，也不当作抓取能力更新。[Firecrawl changelog](https://www.firecrawl.dev/changelog)

### Agent 工作流

- **Carbon + `/swarm`：** Google 让深度推理模型承担架构、协调、审计，让更轻模型在隔离工作区并行，再用对抗 verifier 检查变化。这比“所有任务都用最强模型”更接近可控的生产编排。[来源](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-carbon-now-available/)
- **AlphaProof Code：** 先由人和模型共同定义可审查规范，再让 Agent 生成证明，最后由 Lean 机器检查；关键不是 Agent 永不出错，而是把不可信生成放在可信检查器后面。[来源](https://deepmind.google/blog/introducing-alphaproof-code/)
- **Modern Web Guidance：** 技能用离线、零依赖的 embedding + BM25 检索按需返回现代 Web 指南，并提供 `legacy-scan` 找旧模式；官方仓库同时披露匿名遥测范围和 `DISABLE_TELEMETRY=1` 退出方式。[仓库](https://github.com/GoogleChrome/modern-web-guidance)

## 今天值得深入研究的 1 个主题

### 从“Agent 会做”到“结果可验证”

今天的几条新闻可以串成一条生产链：Carbon 提供长时程推理与 `/swarm` 编排，Firecrawl 提供领域数据，Agent Skills 提供可版本化的方法，AlphaProof Code 则用 Lean 把关键结果变成机器可检查的证据。真正可复用的架构不是不断加 Agent，而是把每一层的失败显式化：来源能追踪、技能有版本、动作有权限、输出有确定性验收、无法自动验证的部分缩小给人审。建议本周挑一个真实流程做四栏审计：**输入证据、执行技能、外部副作用、验收器**；任何一栏为空，都不应直接无人值守运行。

## 可忽略的噪音

- **把 GitHub `stars today` 当成精确日增。** 它适合发现趋势，不适合做增长财务口径；本期没有用总 stars 排名冒充新增排名。
- **只公布 benchmark 第一、不给任务与成本。** 优先看公开任务、统一 harness、turn budget、失败样本和每任务成本；MKA 至少开放了样例和方法说明。
- **把合作探索写成已上线功能。** Google × Adobe 中多项能力仍是“soon / exploring”，采购或迁移前应等待可用性、地区、定价与管理员控制。
- **用发现数量代替安全成效。** 漏洞 Agent 的价值还要看重复率、公开率、修复率、严重性和维护者验证负担。
- **把技能目录数量当成 Agent 可靠性。** 未经来源审查、触发测试、权限限制和回归评测的技能，会扩大而不是缩小风险面。
