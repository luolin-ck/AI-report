### 数据采集 / RAG

Firecrawl 近期官方内容继续强调四类模式：search + scrape、已知 URL 结构化抽取、多页 crawl、agent-driven gathering。对 RAG 产品而言，价值不只是“能抓网页”，而是把网页转成模型可直接使用、可缓存、可引用的上下文，并减少无关页面带来的 token 浪费。

GitHub 日榜中的 [KnockOutEZ/wigolo](https://github.com/KnockOutEZ/wigolo) 本次抓取显示 3,196 total stars、642 stars today，定位为本地优先的 search/fetch/crawl/research MCP 工具。它适合想把网页检索放进 Claude Code、Codex、Cursor 等 coding agent 的开发者；生产使用前要验证页面抓取质量、缓存策略、代理环境和隐私边界。

### Agent 工作流

OpenAI/Hugging Face 事件说明，agent 工作流的关键控制点从 prompt 和模型选择延伸到运行环境、工具权限、网络出口、密钥、日志和事故响应。尤其是会运行 shell、访问包管理器、抓网页或调用 MCP 的 agent，需要默认按半可信自动化进程治理。

Atlassian Jira 的官方方向是把 Claude Code、Cursor、GitHub Copilot 等 coding agent 接入 Jira 工单、Teamwork Graph、PR 和成本管理。VS Code Agent Host 则把多个 agent harness 放进 IDE 的 session 层。这两条线合起来意味着企业会更关心“谁派发任务、agent 看到了什么上下文、产物如何审查、成本归到哪个团队”。

### 热门应用

值得试的应用和工作流主要有三类。第一类是 OpenDesign/Claude Design/Figma Make 这类视觉原型和设计到代码工具，适合在产品探索、营销页、概念验证时缩短首版时间。第二类是 Firecrawl/Wigolo 这类网页上下文工具，适合需要公开资料、竞品页、文档和价格页的 RAG/agent 场景。第三类是 Jira/VS Code/GitHub Copilot 的 agent orchestration，适合把 agent 从个人试验搬进工程组织。

暂时不建议被“一个 prompt 生成完整产品”的短视频带跑。真正值得复盘的是：工具是否能吃进你的设计系统和 repo 上下文，是否能给出可审查 diff，是否能保留来源和执行日志，是否能在失败时安全退出。

## 今天值得深入研究的 1 个主题

**长任务 agent 的安全边界：从 prompt 防护转向运行时治理。**

OpenAI/Hugging Face 事件值得单独复盘，不是为了讨论谁“更强”，而是为了建立一套实际 checklist：agent 是否能访问外网，包管理器代理是否可能成为出口，凭据是否会被工具链继承，benchmark/测试环境是否混有真实生产路径，日志是否能在 agent 高速行动时被还原，安全模型是否会阻断防守方的取证。建议本周做一次内部 tabletop exercise：让一个受限 agent 执行抓取、安装包、读 repo、调用 MCP、写文件、提交 PR 的完整流程，记录每一步权限、网络、密钥和审计证据。
