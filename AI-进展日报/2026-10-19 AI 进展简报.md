- **值得保留的产品判断是“上下文与交接优先于首屏生成效果”。** Figma 10 月 15 日公开测试把可运行 Code Layers、书面 Specs、设计系统 Guidelines 与代码来源放入同一工作面。[官方总览](https://www.figma.com/blog/build-by-design/) 对 OpenDesign、Claude Design 类工具的评估也应增加四项指标：约束是否持续生效、上下文能否版本化、代码能否回流、团队能否审阅每次 Agent 变更。
- **行动建议：** 本周不必因“无新品”停测；选一个带真实组件库、两条关键交互和 API mock 的小功能，对比设计稿到可运行原型的返工次数、可访问性缺陷与设计系统偏差。

### 数据采集 / RAG

- **DeepSeek Search / Fetch（10 月 17 日，新增）**：Search 面向 AI 原生网页检索，Fetch 获取页面内容；官方以统一 API 和临时免费工具调用降低 coding agent 接入成本。[官方发布](https://api-docs.deepseek.com/news/news261017/) 生产评估应把“召回正确来源”和“抓到可引用原文”拆开测，并记录最终 URL、抓取时间、重定向链与许可。
- **Firecrawl 本窗口无新核心抓取发布。** [官方 Changelog](https://www.firecrawl.dev/changelog) 最新条目仍为 10 月 13 日 Fireround，10 月 8 日 Universal Scrape 更早；两者均已在前几期覆盖。本期只保留基线：Universal Scrape 统一网页、PDF、图片与办公文件，Fireround 是 Alexandria 的融资数据源，不是抓取引擎新版本。
- **选择建议：** DeepSeek 适合快速获得“模型 + 搜索 + 抓取”闭环；Firecrawl 更适合需要跨格式解析、供应商数据和独立采集层的架构。两者都应以来源可追溯、缓存/重试、成本与合规作为门槛，而不是只看回答流畅度。

### Agent 工作流

- **Vercel Sessions / session affinity（10 月 17 日，新增）**：同一会话优先留在前一供应商以复用 prompt cache；Sessions 视图暴露每 turn 模型、时延、供应商、缓存命中和成本。[官方说明](https://vercel.com/changelog/ai-gateway-logs-now-show-session-affinity) 这使“路由是否省钱”第一次可按完整 Agent 会话复盘。
- **DeepSeek-V4.1-Flash-1017（10 月 17 日，新增）**：Vercel 同日将其接入 AI Gateway，支持图像输入、统一追踪、预算、重试和故障转移。[Vercel](https://vercel.com/changelog/deepseek-v4-1-flash-1017-now-available-on-ai-gateway) 最合理的试用不是换掉所有模型，而是在长仓库修改、视觉调试和多步工具任务上做路由 A/B。
- **Hybrid Reasoning Agents（10 月 14 日，近 7 日补充）**：论文提出 HybridLink 与连续工作记忆，让 Agent 在潜空间推理、文本观察和工具行动之间切换；作者报告 11 个基准上性能提升 10.4%、token 减少 35.5%–54.7%、推理加速 1.8–2.6 倍、成本下降 2.7–3.7 倍。[论文](https://arxiv.org/abs/2610.18861)｜[代码](https://github.com/togethercomputer/HybridAgent) 这些是作者结果，尚需独立复现。
- **OpenCode 安全事件（10 月 18 日，新增）**：任何连接私有仓库、模型账号或终端的 Agent 都应具备会话撤销、凭据轮换、最小权限和可审计日志；事件热度不应代替完整技术复盘。[官方 X 通报](https://x.com/opencode/status/2111516673953935833)

### MCP / Agent Skills 更新

**结论：10 月 17–19 日未发现官方新版协议或 skill 更新。** 本次实际核验 MCP Versioning/Current Specification、Build with Agent Skills、`ext-skills` 官方仓库与提交历史、Anthropic `mcp-server-dev` 目录，以及 `ext-apps` 官方仓库；未对所有未合并 PR、Registry 条目或内部状态作全量否定断言。

- **协议基线：`2026-07-28`（Current）。** [Versioning](https://modelcontextprotocol.io/docs/2026-07-28/learn/versioning)｜[当前规范](https://modelcontextprotocol.io/specification/2026-07-28/)。日期版本代表最后一次向后不兼容变化；该版要求每次请求在 `_meta.io.modelcontextprotocol/protocolVersion` 携带协议版本，Streamable HTTP 还使用 `MCP-Protocol-Version`。服务器可多版本并存，不支持时返回 `UnsupportedProtocolVersionError`；客户端不应只在初始化时记住永久版本，应按请求发送并处理协商失败。

## 今天值得深入研究的 1 个主题

### 潜空间推理能否成为 Agent 的第二条“内循环”

Hybrid Reasoning Agents 值得深挖，不只是因为作者报告 token 与成本下降，而是它重新划分了 Agent 的可见边界：内部规划和记忆可以在连续潜空间中压缩，真正要调用工具、向人解释或留下审计证据时，再回到文本。若结论可复现，它可能缓解长任务里“所有思考都写进上下文”的成本和噪声；但也会放大不可解释、难调试与隐藏失败路径的问题。

建议做一个可证伪的小实验：从现有 coding/RAG Agent 选 30 个带工具调用的历史任务，用相同模型、工具、成功标准和预算分别运行纯文本 Agent 与 HybridAgent；记录任务成功率、工具错误、输出 token、墙钟时间、人工可解释性和失败恢复次数。只有当成本收益与可审计性同时达标，才考虑进入生产影子流量。
