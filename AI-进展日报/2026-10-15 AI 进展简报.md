## 今日最值得关注

### 1. PostgreSQL 原生向量检索开始挑战外置向量库，但现在仍是 alpha

- **结论**：Tiger Data 在 2026-10-13 开源 [`pg_vectorsearch`](https://github.com/timescale/pg_vectorsearch)，用 PRISM 分区、RaBitQ 与 SIMD 面向大规模向量检索；官方自测称在 1 亿向量、95% recall 时达到 6ms p50，并可在 128GB 机器上构建。
- **影响判断**：如果真实业务复测成立，RAG 数据层可能更多回流 PostgreSQL，减少独立向量库的运维面；但项目要求 PostgreSQL 18+ 且明确处于 alpha，厂商数字未独立复现。
- **行动建议**：仅在隔离测试环境，用自己的 embedding、过滤条件、recall 目标和硬件预算与 pgvector/HNSW 对照；暂不生产迁移。

### 2. 企业 Agent 的衡量方式正从“席位”转向“完成工作量”

- **结论**：OpenAI 在 2026-10-14 的[欧洲企业采用报告](https://openai.com/index/the-eus-next-chapter-in-ai-is-agentic/)中称，其 EU ChatGPT Enterprise/Business 样本里，Codex 与 ChatGPT Work 已贡献超过一半输出 tokens，SMB 周活跃用户自 5 月以来增长超过 8 倍。
- **影响判断**：这说明 Agent 已进入部分企业的实际产出流程；但数据只代表 OpenAI 客户样本，报告未给出完整逐日原始序列，不能外推整个欧盟或全部行业。
- **行动建议**：企业试点应跟踪 Agent 完成工作量、人工复核率、失败恢复成本和高风险操作拦截率，而不只看账号数。

### 3. Cursor 把编码 Agent 的竞争扩展到工作流插件生态

- **结论**：Cursor 于 2026-10-13 上线 [Origin App Marketplace](https://cursor.com/changelog/origin-app-marketplace)，官方称首批有 20+ Apps，覆盖部署、CI、代码审查、安全、监控和项目管理，并开放公众提交。
- **影响判断**：编码 Agent 不再只竞争编辑器体验，而是开始争夺 PR、检查任务、部署与监控的工作流入口；20+ 数量为官方表述，未逐个独立核验。
- **行动建议**：接入前先审权限范围、安装 token/JWT 生命周期、webhook 重放防护和 PR 写权限，优先只读或沙箱试点。

### 4. OpenCode 2.0 用共享后台与 Code Mode 换取效率，也改变权限边界

- **结论**：OpenCode 2.0 将 TUI、Web、Desktop 统一连接到本地后台服务，新增 MCP/OpenAPI Code Mode、后台子 Agent/命令、插件 API 与可嵌入 SDK；详见[官方发布说明](https://anoma.ly/notes/opencode-2-0/)与[仓库](https://github.com/anomalyco/opencode)。
- **影响判断**：脚本化组合可能减少多轮工具调用和上下文开销，但 1.x 插件不兼容、Server API 重做，共享后台也扩大了文件、网络和凭证边界。官方页面无内嵌发布日期，公开发布窗口交叉验证为 2026-10-12。
- **行动建议**：先在临时仓库升级，记录后台进程权限、调用日志、取消/超时行为和迁移成本，不直接覆盖生产开发环境。

### 5. 本地长上下文 Agent 的“可运行性”继续提高，质量仍需任务级验证

- **结论**：Liquid AI 于 2026-10-13 发布 [LFM2.5-24B-A2B](https://huggingface.co/blog/LiquidAI/lfm25-24b-a2b)：24B 总参数、2B 激活、131k 上下文，并支持 llama.cpp、MLX、vLLM、SGLang 与 ONNX。
- **影响判断**：官方自报 M5 Max 184 tok/s、Ryzen AI Max+ 395 为 114 tok/s，显示端侧推理潜力；速度依赖硬件和量化，质量 benchmark 也是作者自评，不能据此判断复杂编码能力领先。
- **行动建议**：适合离线摘要、检索编排、隐私敏感工具调用的小规模 A/B；用成功率、恢复能力和长上下文召回验证，而非只测 tokens/s。

### 6. YouTube 开始把 AI 音乐披露直接放进播放器

- **结论**：YouTube 于 2026-10-14 宣布，YouTube Music 将为“主要使用生成式 AI 制作”的歌曲增加播放器页标签，并计划扩展到主 YouTube App；见[官方公告](https://blog.youtube/news-and-events/youtube-music-ai-labels/)。
- **影响判断**：AI 音乐产品的竞争开始同时受生成质量、素材授权、披露规则和分发机制影响。识别依赖音乐合作方信息及平台检测；未获取到精确互动数据，也不是 YouTube 视频热榜结论。
- **行动建议**：音乐生成团队应保留生成链路、素材授权和披露元数据，并跟踪标签触发、申诉与推荐分发变化。

### 7. MCP 本期没有官方新版，生产实现应继续锁定稳定基线

- **结论**：截至 2026-10-15，未发现 MCP 官方新版/技能更新；协议基线仍为 [`2026-07-28`](https://modelcontextprotocol.io/specification/2026-07-28)，稳定 Skills 扩展仍为 [`io.modelcontextprotocol/skills`](https://skills.extensions.modelcontextprotocol.io/specification/stable/skills)。
- **影响判断**：Tasks、Skills over MCP、MCP Apps 仍应通过能力协商使用；工作组 issue/PR 不能当成稳定发布。官方开发技能清单仍为 mcp-server-dev 3 项、ext-apps 4 项。
- **行动建议**：无需因“新版本”迁移；生产端继续锁定 stable、做 capability negotiation，并把 draft 与第三方 skill 集合隔离评估。

## 今天值得深入研究的 1 个主题

### OpenCode 2.0 的 Code Mode 与共享后台服务：上下文压缩收益是否值得新的权限边界？

建议用同一个真实任务做四组对照：

1. 比较传统逐工具调用与 Code Mode 的 token、端到端延迟和成功率；
2. 核查 TUI 沙箱与后台服务实际拥有的文件、网络和凭证权限；
3. 量化 1.x 插件与 Server API 的迁移工作量和失败恢复成本；

研究价值在于，它把“少调用、少上下文”的效率收益与“长期后台、共享权限”的治理成本放在同一架构里。结论应来自隔离环境的真实任务，而不是只看 HN 热度或官方介绍。
