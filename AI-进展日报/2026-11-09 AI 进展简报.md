## 分领域进展

### 设计生成

#### Figma：从生成结果走向可编辑对象

Figma 11 月 6 日更新让 AI 图像编辑的 Select area 支持点击对象进行隔离或擦除，减少手工框选；当前仅在 macOS 桌面端提供。11 月 5 日的 Agent 矢量生成改进则让图层分组更具功能语义，支持附加参考图，并生成更规范的描边与可动画资产。[来源](https://www.figma.com/release-notes/)

值得关注的不是“又多一个生成按钮”，而是设计资产能否继续被设计师修改、复用和动效化。团队评估 AI 设计工具时，应把可编辑图层、组件化、描边语义、品牌一致性和设计到代码后的维护成本列为硬指标。

#### GitHub Trending 中的 agent-ready 设计系统

[meta/astryx](https://github.com/meta/astryx) 在本次 Daily 快照显示 **17,148 stars、875 stars today**。仓库将自身定位为可定制、面向 Agent 的开源设计系统，说明“生成 UI”之外，机器可理解和可调用的设计约束正在成为新基础设施。该数字来自 GitHub 页面标签，不是独立复算的自然日净增长。

### 数据采集 / RAG

#### Firecrawl：SEC 申报文件成为垂直数据入口

Firecrawl 11 月 6 日的 SEC Filings 更新覆盖 8,000 多家上市公司，以及 10-K、8-K、Forms 3/4/5、13F 等材料。[官方页面](https://www.firecrawl.dev/changelog/sec-filings) 没有给出完整 SLA、历史覆盖深度或更新延迟，因此仍需对照 SEC 原文做抽样验证。

这类更新体现了 RAG 数据层的下一步：从“把网页转成 Markdown”转向“提供有明确语义和高价值字段的领域入口”。财经、法务与投资研究场景可先检查表格、附件、页码/段落引用、修订文件与增量更新，再决定是否进入正式知识库。

#### 数据采集的实践建议

- 采集层保留原始 URL、抓取时间、文档版本与内容哈希，避免模型答案无法追溯。
- 对 10-K/8-K 等长文档做章节级切分，但不要丢失表格、脚注和附件关系。
- 用源站原文做小规模黄金集，分别测召回、引用准确率和更新时延，而不是只看“抓到了多少页”。

- **OpenAI Skills 文档：** 官方文档说明 hosted skills 是带版本的 bundle，可与 Responses API 的 shell 或 Agents API sandbox/capabilities 配合；本地与托管技能的执行、安全和版本边界不同。[官方指南](https://developers.openai.com/api/docs/guides/tools-skills) 本期未取得明确的 11 月 7—9 日发布日期，因此只作为生态基线，不声称为本窗口新品。

#### 适用与迁移建议

1. 新项目优先按当前 Core 版本实现协商与授权，不要用 Reference Servers 的包号替代协议版本。
2. 有 UI 的工具走 `build-mcp-app` / ext-apps 路径；本地可分发服务用 `build-mcpb`；纯工具/资源服务器则从 `build-mcp-server` 开始。
3. 升级前记录客户端、SDK、服务器和扩展的各自版本，并用 Reference Servers 做最小互操作测试。
4. 第三方 skill 集合、平台 MCP 功能或自动化产品的新连接器只能标为生态更新，不能冒充 MCP 官方发布。

## 今天值得深入研究的 1 个主题

### Agent 的“可操作性”如何同时做到可治理

今天的多个信号指向同一问题：agent-browser 和 OpenMausBot 让 Agent 更能操作，Activepieces 把工具连接做成工作流，Dropbox 强调审批/撤销/日志，GitHub Code Review 开始暴露 skills/MCP/custom instructions 来源，而公开仓库中的敏感信息事件又提醒我们，操作能力一旦越过权限边界就会放大风险。

建议用一个真实但低风险的任务做端到端评估，例如“读取指定资料—生成变更建议—等待人工批准—提交到测试仓库”，并记录五类证据：输入来源、调用工具、权限范围、人工批准、可逆/停止机制。比起只比较模型答案，能否重放这条证据链更能决定 Agent 是否适合进入生产。
