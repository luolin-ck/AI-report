## 今日判断

今天的主线不是“又多了几个模型”，而是 Agent 正在补齐生产环境最难的三层：更强的推理与生成能力、可执行的工具协议，以及身份、沙箱、网络、审计和恢复控制。最值得马上行动的变化是 MCP Reference Servers v2.5.0：它集中修复 8 个漏洞，而且版本号从日期制切到 semver 后，包管理器未必会自动升级，团队需要显式检查版本。

### 2. MCP Reference Servers v2.5.0 修复 8 个漏洞，升级不能等自动更新

- 11 月 18 日发布的 v2.5.0 修复 Git、filesystem、everything 等参考服务器中的 8 个漏洞，涉及 Git hooks / maintenance 执行、lazy fetch、submodule / driver、工作树外 index 路径、目录置换，以及 NAT64 私网地址绕过。
- 所有参考服务器现在都可通过 Streamable HTTP 提供服务；memory server 增加可选写入限制和锁清理，fetch server 会锁定已检查 IP 并拒绝通配 IP。
- TypeScript 参考服务器从日期版本转为 semver。由于包管理器会把 `2.4.0` 排在 `2025.x` / `2026.x` 之后，不能依赖自动升级；例如 filesystem server 需显式安装 `@modelcontextprotocol/server-filesystem@2.4.0`。
- 这是参考实现发布，不是 MCP 核心协议换版。当前核心协议仍是 2026-07-28；下一次协议发布日期计划为 2027-03-30。
- 来源：[Reference Servers releases](https://github.com/modelcontextprotocol/servers/releases) · [MCP release cycle](https://blog.modelcontextprotocol.io/posts/mcp-release-cycle/)

## 本期深研：生产级 Agent 控制面应如何搭建

一个可上线的 Agent，不应只由“模型 + MCP 工具”组成。今天几项发布拼出了一条更完整的控制链：

1. **身份**：为 Agent 分配独立身份和最小权限，不借用人的长期凭证。
2. **沙箱**：用 OS 级文件系统、进程和网络边界限制动作；stdio MCP 启动命令也要显式进入沙箱。
3. **出站控制**：域名白名单、DNS / IP 二次校验、代理审计，防止 SSRF、NAT64 和重绑定绕过。
4. **工具供应链**：锁定 MCP server 版本、校验来源，对 Git hooks、submodules、驱动和可执行程序单独设防。
5. **动作审批**：浏览器操作、发信、购买、部署、删除等真实世界动作采用分级审批和提交前预览。
6. **可观测与恢复**：记录 trace、工具输入输出和策略命中；长任务应有 checkpoint、幂等和可回滚路径。
7. **评测**：以真实任务完成率、越权率、失败恢复时间和单位任务成本为主，不再只看模型 benchmark。

### 48 小时行动清单

- 显式盘点并升级 MCP Reference Servers v2.5.0 涉及的组件。
- 搜索所有 stdio MCP 配置，确认启动命令是否处于沙箱或等效容器边界内。

## 噪音与风险提示

- “模型在某榜单第一”通常来自厂商或单一榜单，不等于你的任务上更好。
- GitHub Trending 的当日 stars 容易受传播事件影响，采用前仍需检查提交活跃度、许可证、依赖和安全历史。
- 研究自动化可显著提速，但自动生成引用、图表和论文段落必须回到原始来源核验。
- 能操作浏览器、消息、邮箱、购买和部署的 Agent，应默认被视为高风险执行主体，而不是更聪明的聊天机器人。
