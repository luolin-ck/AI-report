## 今日最值得关注

1. **OpenAI 的 GPT-5.6 与 ChatGPT Work 已成为本周 AI 应用主线。** Axios 报道 2026-07-09 发布 GPT-5.6 与 ChatGPT Work，The Verge 将其描述为把 ChatGPT 与 Codex 能力推向更通用工作代理。影响：办公、代码、文档和轻量应用生成会继续合流。行动：选 2-3 个真实任务分别测 Sol/Terra/Luna 成本与稳定性。来源：[Axios](https://www.axios.com/2026/07/09/ai-openai-gpt-release)、[The Verge](https://www.theverge.com/ai-artificial-intelligence/963464/openai-gpt-5-6-codex-chatgpt-work)。
2. **Figma Make 已接入 GPT-5.6，设计到代码的第一稿质量成为竞争点。** Figma 官方 2026-07-09 称 GPT-5.6 能提升 Make 的首轮原型质量、响应式布局和错误自修复。影响：AI 设计生成从“出图”转向“可运行、可交互、可继承已有设计”。行动：拿一个真实 Figma 设计稿测试“静态设计转可运行原型”。来源：[Figma Blog](https://www.figma.com/blog/gpt-5-6-is-now-available-in-figma-make/)。
3. **设计系统正在变成 Coding Agent 的上下文层。** Figma 2026-07-10 Decagon 案例显示，Figma MCP + Storybook + agent skill 能让编码代理读取组件库并生成更贴近设计系统的实现。影响：设计团队的资产结构会直接影响 AI 生成代码质量。行动：把组件状态、变量、用法约束整理成 agent 可读文档。来源：[Figma Decagon case](https://www.figma.com/blog/how-decagon-uses-ai-for-design-system-saturation/)。
4. **Firecrawl 的 web-scale `/monitor` 把抓取从“已知 URL 巡检”推进到“全网发现”。** 官方文档描述它用 queries + goal + recency window 持续搜索新结果，并由 AI judge 判断是否提醒。行动：给关键主题设置 24h monitor，并把 goal 写清楚。来源：[Firecrawl Docs](https://docs.firecrawl.dev/features/monitoring-web-scale)。
5. **Agent 安全风险正在从 prompt injection 扩展到数据注入、仓库名幻觉和审批绕过。** 近一周公开报道/论文集中讨论 GhostApproval、HalluSquatting、Agent Data Injection。影响：只让人点“确认”不够。行动：限制写盘/联网权限，固定依赖 URL，执行前做独立校验。来源：[ITPro](https://www.itpro.com/security/flaws-in-some-of-the-most-popular-ai-coding-tools-left-developers-wide-open-to-attack)、[ADI](https://arxiv.org/abs/2607.05120)、[HalluSquatting](https://arxiv.org/abs/2607.07433)。
6. **GitHub 今日 AI 热榜偏向“agent skill、知识图谱、spec 工作流”。** Graphify、Vibe-Trading、awesome-llm-apps、hallmark、spec-kit 均进入本次 AI 相关筛选。影响：开发者不只追模型，也在追可复用的工作流资产。行动：优先试能沉淀团队流程的 skill/kit，而不是一次性 demo。
7. **YouTube 近几天的公开热度集中在 GPT-5.6/ChatGPT Work 与 Codex+Claude Code 工作流。** OpenAI 官方 “Meet ChatGPT Work” 抓取时可见 162,606 views；Riley Brown 的 Codex/ChatGPT Work 视频 1 天 42,000 views。影响：大众关注点从“会不会写代码”转向“能不能完成整段工作”。行动：复盘这些视频的任务拆解方式，而不是照抄标题党承诺。

## 分领域进展

### 设计生成

- **Figma Make + GPT-5.6**：官方强调从 prompt 到 working build 的速度、从已有 Figma 文件生成交互原型、以及错误自修复。适合产品经理/设计师快速验证复杂交互，但仍要人工检查响应式、状态和可访问性。
- **Figma MCP + 设计系统**：Decagon 案例的重点不是“AI 画得更好”，而是让 agent 访问组件库、Storybook 和设计上下文，减少设计/开发来回解释。值得关注的落地点是 `design.md`、组件用法约束和可复用 skill。
- **Claude Design / OpenDesign 类工具**：近期社区讨论集中在“导入设计系统生成 landing page、slides、培训材料”。口径限制：我未拿到 Anthropic 官方 Claude Design 页面，本日报只把它作为社区实践趋势，不当作今日官方发布。
- **Hallmark**：GitHub 今日热榜中的 [Nutlope/hallmark](https://github.com/Nutlope/hallmark) 是给 Claude Code、Cursor、Codex 使用的 anti-AI-slop design skill，说明“审美/设计质量约束”正在被工程化成 agent skill。

### 数据采集 / RAG

- **Firecrawl web-scale `/monitor`**：从 URL diff 扩展为全网查询发现；支持 `searchWindow`、`maxResults`、domain filters、goal judging。适合 RAG 增量入口。
- **Firecrawl 动态抓取定位**：官方 2026 dynamic scraping 文章强调 JS rendering、Markdown/JSON 输出和 RAG-ready 内容。对 AI 应用来说，抓取工具的价值不再只是拿 HTML，而是减少清洗和 chunk 前处理。
- **Graphify**：今日热榜的 [Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify) 把代码、SQL schema、文档、论文、图片、视频转成可查询知识图谱，适合大型代码库问答和跨资料 RAG。

### Agent 工作流

- **ChatGPT Work**：媒体报道定位为更通用的多步骤工作代理，和 Codex 的代码执行能力形成连通。建议把它当“任务执行环境”评估，而非普通聊天模型。
- **Loop engineering**：近期视频和论文都在强调“少手写 prompt，多设计 trigger、goal、verification、stopping rule、memory”。适合日报、CI 修复、资料监控。
- **Spec-driven development**：[github/spec-kit](https://github.com/github/spec-kit) 今日仍在热榜，README 将规格说明提升为可执行输入，适合和 Codex/Copilot 类工具配合，减少“需求没写清导致 agent 自由发挥”。

### 热门应用

- **OpenAI GPT-5.6 / ChatGPT Work**：适合希望把文档、表格、轻应用、代码任务放进同一代理工作流的用户；值得尝试，但要设预算和人工验收。
- **Figma Make**：适合设计到代码、原型验证、已有 Figma 文件转可交互 demo；不建议直接把输出当生产代码合并。
- **OpenCut**：[OpenCut-app/OpenCut](https://github.com/OpenCut-app/OpenCut) 今日 GitHub daily 有 1,229 stars today，总 stars 66,860；开源 CapCut 替代品，规划 MCP server 和 headless mode。偏创作者工具。
- **AIRI**：[moeru-ai/airi](https://github.com/moeru-ai/airi) 是自托管 AI companion / AI VTuber 项目，适合研究实时语音和角色人格。

5. **[github/spec-kit](https://github.com/github/spec-kit)**：543 stars today，总 stars 120,689。帮助团队实践 Spec-Driven Development 的工具包。增长原因：agent 工作越自主，前置规格和验收标准越关键。适合尝试：把 PRD、任务拆解、验收测试和编码代理串成闭环。

## 今天值得深入研究的 1 个主题

**把设计系统做成 agent context。**  
建议用一个真实产品页做实验：整理 tokens、组件状态、Storybook 链接、Figma 文件链接、可访问性规则和禁用样式，分别交给 Codex/Claude Code/Figma Make 生成实现，再比较首轮还原度、可维护性和返工次数。这个主题最容易沉淀为团队资产。
