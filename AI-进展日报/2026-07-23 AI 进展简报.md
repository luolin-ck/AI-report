### Agent 工作流

OpenAI Presence 把 agent 的生产问题拆成 policy、approved actions、simulations、evaluations、guardrails、escalations 和持续改进。值得注意的是，OpenAI 官方写到 Presence 已用于英文电话支持渠道，并称几周内达到或超过其一线人工支持质量 benchmark，当前自动解决 75% inbound issues，Codex-powered improvement loop 在 10 天内让 human handoffs 降低 15 个百分点。行动含义：企业 agent 的价值在持续评测和 SOP 调整，而不是一次 prompt 写好。

VS Code Agent Host 则代表开发工具层面的相同趋势：agent session 不再绑死在 editor 窗口，host 是 source of truth，客户端只是 viewer/controller；远程 host 可通过 WebSocket 暴露 AHP，并让 workspace 操作跑在远端机器。适合团队关注远程 coding agent、CI 前验证、浏览器工具和长任务恢复；安全重点是 host token、远端命令边界和 extension-contributed tools 的来源。

Kimi Work 在 [HN 条目 48981703](https://news.ycombinator.com/item?id=48981703) 上继续有讨论，本次 Algolia 抓取显示 671 points，创建于 2026-07-20T17:13:23Z；Kimi K3 官方帖 [HN 条目 48935342](https://news.ycombinator.com/item?id=48935342) 本次抓取显示 2101 points、1214 comments。结论：Kimi 的热度不只是模型参数，而是“开放权重 + agent 产品层 + 低成本 API + 前端/coding benchmark”形成了完整传播链。

### 热门应用

值得尝试的应用/工作流有四组。第一组是 OpenAI Presence 这类企业级生产 agent，只适合有明确流程、审计和人工升级的组织，不适合个人自助试用。第二组是 Kimi Work/Kimi Agent，适合调研长上下文、文档、网页、代码和多工具 agent 的边界。第三组是 OpenDesign/Figma Make/Buddy Figma Agent，适合做视觉原型、营销页、deck 和设计系统约束下的生成。第四组是 Context.dev/Firecrawl/AnySearch/Wigolo/Crawl4AI，适合 RAG 数据入口和 agent research。

暂时不要被“完全自动化公司/替代设计团队/无限免费 agent”这类短视频带跑。能进入真实流程的工具通常有三个共同点：产物是可审查文件或结构化数据，权限和来源能追踪，失败时能安全中断并留下日志。

### 模型 / 平台更新

Kimi K3 官方技术博客称其为 open 3T-class model，2.8T parameters，基于 Kimi Delta Attention 和 Attention Residuals，MoE 每 token 激活 16/896 experts，并计划在 2026-07-27 发布 full weights。X 趋势、HN 和媒体讨论把它放在“开放模型挑战闭源模型经济学”的框架里；今天最值得关注的不是参数数字本身，而是能否在 agent/coding/前端生成上稳定复现。

OpenAI Presence 和 OpenAI/Hugging Face 安全事件形成同一天的鲜明对照：一边是企业 agent 生产化，一边是长任务模型在评估环境中暴露的真实风险。对平台团队而言，这说明“agent 可以上线”和“agent 必须被约束”要同步推进。

Firecrawl `/search`、VS Code Agent Host、Product Hunt 上 Context.dev/AnySearch/CartAI 的聚集，则说明 agent 平台的底层能力正在分化成三层：数据入口、执行 host、动作/审批闭环。真正能进入生产的产品会围绕这三层交代清楚成本、权限、日志和失败处理。

## 今天值得深入研究的 1 个主题

**生产级 agent 的闭环：数据入口、执行环境、评测和持续修复。**

今天的四条线索可以放在一张图里看：Firecrawl 负责把外部网页变成可引用证据，VS Code Agent Host / Kimi Agent / OpenDesign 负责把 agent 放进可持续执行的工作台，OpenAI Presence 负责把企业流程、审批、guardrails 和 evals 产品化，OpenAI/Hugging Face 事件提醒我们运行时隔离会被真实攻击路径检验。建议本周做一个小型内测：选一个真实工作流，让 agent 检索资料、读取 repo、生成变更、跑验证、写总结，再记录每一步的权限、网络、来源引用、token 成本、失败恢复和人工审批点。
