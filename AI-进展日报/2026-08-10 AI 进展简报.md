## 分领域进展

### 设计生成

- **Figma Make：AI 设计进入“直接编辑 + 批注 + 响应式查看”阶段。** Figma release notes 显示，7 月 30 日 Figma Make 新增 editing panel，用户可以细调 spacing、type、layout，用 annotations 指向局部并让 agent 修改，还能在不同 device frame 中查看效果；7 月 16 日还强调 code-backed screens 进入 canvas 时绑定变量、更多 auto layout。适合尝试：产品原型、设计系统回流、现有页面转可编辑图层。注意：团队试用时要记录 AI credit 使用和人审成本，8 月 5 日新增的 AI credit limit 正是企业使用量治理信号。
- **Open Design 0.18.0：把 agent-native 设计工作台带进 Codex。** Open Design 官方博客称 0.18.0 在两天内合并 115 个 PR，目标是 design team workspace：项目、评论、设计系统、插件、skills、workspace billing，并把创作引擎带进 Codex。适合尝试：希望在 coding agent 里完成 UI/UX、PPT、dashboard、prototype 的团队。注意：这类工具适合探索“设计系统 + 代码生成”的工作流，不应只看单次视觉输出。
- **Claude Design：从好看的 demo 转向品牌一致性和设计到代码。** Anthropic 6 月 17 日发布的 Claude Design 更新强调导入 design system、与 Claude Code 同步、直接在 canvas 编辑，并连接 Adobe、Canva、Gamma、Lovable、Miro、Replit、Vercel、Wix 等工具；虽然不是 48 小时内发布，但 YouTube 最近一周仍有教程传播。适合尝试：产品经理、设计师和独立开发者快速做多方向探索。注意：落地时要校验 design token、组件命名、状态和响应式约束。
- **设计生成的判断标准正在变化。** 2026 年的关键问题不再是“AI 能不能画一个首页”，而是能不能把设计转成团队能维护的组件和代码，能不能回到 Figma/代码仓库继续编辑，能不能被预算和权限控制。行动建议：建立一份 AI 设计验收表，至少包含视觉方向、组件结构、变量绑定、交互状态、可访问性、移动端、导出路径和二次编辑成本。

### 数据采集 / RAG

- **Firecrawl `/search`：从整页抓取转向相关片段。** Firecrawl changelog 显示 7 月 22 日升级 `/search`，返回最能回答 query 的 excerpts，并声称在 SimpleQA 上提高准确率、减少上下文 tokens。适合场景：agent 先搜再答、RAG 引文片段、市场/竞品监控。行动建议：不要把整页塞进模型，优先让搜索层输出可引用片段，并保留 URL、时间、片段来源。
- **Firecrawl `/monitor`：RAG freshness 成为产品能力。** 7 月 1 日 web-scale `/monitor` 支持按 query 和 goal 监控新内容，5 月版本已支持 webhook/email、diff permalink 和成本预估。适合场景：AI 日报、竞品变更、文档 release note、招聘/价格页监控。行动建议：给知识库增加 freshness 字段和失效策略，避免旧文档长期占据召回。
- **文档解析链路继续升温。** Firecrawl `/parse`、Fire-PDF、`pdf-inspector` 解决 PDF、Word、表格文档转 Markdown/JSON 的高频痛点；YouTube 官方搜索显示 Firecrawl 官方 PDF Inspector 视频 3 天约 11,478 views。适合场景：技术文档、合同、论文、产品手册入库。行动建议：评测时用复杂表格、双栏论文、页眉页脚、扫描件、公式和跨页段落，而不是只测纯文本 PDF。
- **抓取工具的开源热度来自“AI-ready data”。** GitHub 今日可见 `NanmiCoder/MediaCrawler`、`apify/crawlee`、`brightdata/cli`、`scrapy/scrapy` 等抓取/自动化项目仍在 Trending 或语言分榜出现。适合场景：中文社媒公开内容研究、浏览器自动化、RAG 增量采集。注意：采集前要确认 robots、平台条款、个人信息和版权风险。
- **代码仓库 RAG 出现专门项目。** `vitali87/code-graph-rag` 今日在 GitHub Trending Python 页显示约 682 stars today，定位为 monorepo 的 code graph RAG。适合尝试：跨语言代码理解、遗留系统问答、agent 修改代码前的结构检索。行动建议：评测时重点看 symbol graph、跨文件引用、增量索引、编辑后同步，而不是只看 README 演示。

### Agent 工作流

- **Prime Agent：self-improving RLM agent 成为今日最强开源叙事。** GitHub Trending TypeScript 页显示 `PrimeIntellect-ai/prime-agent` 约 2,655 stars today；YouTube 1-3 天内有多条教程视频。适合尝试：长时 coding workflow、自动改错、agent harness 研究。注意：在生产仓库前先用只读 repo、无密钥环境和可回滚 branch 测试。

- **Claude Code 自托管环境是企业 agent 的重要部署信号。** Anthropic 8 月 6 日宣布 public beta：session 从 web/mobile/desktop/routine 发起，但执行跑在企业自己的 runner 内，靠近内部网络与安全控制。适合场景：需要访问内部服务、私有 registry、数据库、CI 和合规边界的工程组织。行动建议：先定义 runner 镜像、隔离策略、日志保留、密钥注入和升级责任，再让 agent 接触内网。
- **OpenAI Responses API 的 agent runtime 给自研平台提供设计参考。** OpenAI 把 shell tool、hosted container、egress proxy、domain-scoped secrets、skills 和 compaction 组合成可重复任务运行环境。适合场景：报告生成、数据处理、代码修改、自动化运营。行动建议：自研 agent 平台也应把文件系统、网络、凭据、日志、输出截断和长上下文压缩做成基础设施，而不是散落在 prompt 里。

## 今天值得深入研究的 1 个主题

**主题：把 AI 设计生成接入工程工作流，而不是停在视觉 demo。**

建议研究路径：

1. 选择一个真实页面或功能，不要用空白 landing page demo。

4. 交给前端工程师评估：组件结构、状态覆盖、响应式、可访问性、依赖选择、测试可写性。
5. 计算总成本：AI credit/token、人工修正时间、二次返工、设计系统污染风险。

这个主题值得深入，是因为 2026 年设计生成工具已经足够“好看”，但团队真正缺的是从原型到可维护产品的交付路径。
