## 先解释几个高频词

- **Agent**：可以自己分步骤完成任务的 AI。它不只是回答问题，还能调用工具、看网页、写代码、改文件、反复检查结果。
- **MCP**：一种让 AI 连接外部工具和业务系统的标准接口。可以理解成“AI 调用公司内部系统的插座”。
- **RAG**：让 AI 先读取外部资料，再回答问题。常见场景是企业知识库、网页资料库、客服知识库。
- **设计生成**：用 AI 生成页面、原型、PPT、交互稿，甚至可以继续交给代码工具实现。

## 今日最值得关注

1. **企业 AI Agent 的重点，正在从“能不能做事”变成“能不能安全地用公司数据”。**  
   Microsoft 7 月 6 日发布 Dataverse 更新，把 Dataverse 插件扩展到 Claude、Cursor、GitHub Copilot 等工具，并强调 MCP 工具目录、MCP 认证、内部 MCP 管理。[来源](https://www.microsoft.com/en-us/power-platform/blog/2026/07/06/dataverse-july2026/)  
   这件事说明：企业真正要用 Agent，不只是看模型有多聪明，还要解决权限、审计、数据来源、工具调用记录这些问题。  
   **建议**：如果你在做内部 Agent，先列清楚它能访问哪些系统、能做哪些操作、谁来审批、出错后怎么追溯。

2. **Claude Sonnet 5 更像一个“便宜但能干活的执行模型”。**  
   Anthropic 6 月 30 日发布 Claude Sonnet 5，强调它更适合计划任务、使用浏览器和终端、写代码、处理知识工作。到 2026-08-31 前，它的 API 引导价格是每百万输入 token 2 美元、每百万输出 token 10 美元。[来源](https://www.anthropic.com/news/claude-sonnet-5)  
   简单说，它不是只用来聊天，而是更适合放进自动化工作流里跑任务。  
   **建议**：把你的 Agent 流程拆成三段：先规划、再执行、最后验收。Sonnet 5 可以优先放在“执行”这一段测试成本和成功率。

3. **AI 设计工具正在从“生成漂亮图”变成“生成可交付的产品材料”。**  
   Claude Design 官方说明显示，它可以通过对话生成设计、交互原型和演示文稿，可以导入设计系统，也能和 Claude Code 配合，把设计交给代码工具继续实现。[来源](https://support.claude.com/en/articles/14604416-get-started-with-claude-design) Open Design 则是开源替代方案，支持 HTML、PDF、PPTX、MP4 导出，也能接入 Codex、Cursor、Claude Code 等工具。[来源](https://github.com/nexu-io/open-design)  
   这说明 AI 设计生成已经不只是“出一张图”，而是在靠近真实产品流程。  
   **建议**：试这类工具时，不要只输入一句“做个漂亮首页”。最好准备真实页面、品牌颜色、组件库和业务文案，看它能不能持续迭代。

4. **网页抓取和 RAG 采集正在变得更复杂：不只是抓 HTML，而是要能点按钮、翻页、提取字段。**  
   Firecrawl 的 OpenClaw 文章强调了网页交互、浏览器沙箱、结构化抽取、缓存控制等能力。[来源](https://www.firecrawl.dev/blog/best-openclaw-search-providers) Firecrawl 另一篇文章也强调，Agent 要做真实任务，必须能拿到新的网页上下文。[来源](https://www.firecrawl.dev/blog/ai-agents)  
   这意味着只会抓静态网页的 RAG 管线会越来越不够用，尤其是遇到登录、筛选、分页、JS 渲染页面时。  
   **建议**：做 RAG 采集时，把流程拆成搜索、抓取、交互、字段抽取、缓存五层，每层都要有失败重试和质量检查。

5. **Vercel 的数据说明：AI 写代码已经开始影响真实部署流程。**  
   TechCrunch 7 月 6 日采访 Vercel CEO，文中提到 Vercel 每天约 600 万次部署，其中大约一半由 coding agents 触发，AI Gateway 每天处理超过 1 万亿 tokens。[来源](https://techcrunch.com/2026/07/06/vercel-ceo-guillermo-rauch-on-the-fight-to-split-off-models-from-agents/)  
   这说明 AI 编程工具已经不只是写 demo，它开始进入真实上线流程。  
   **建议**：团队如果让 AI 生成代码，必须接上自动测试、预览环境、截图验收、人工确认和回滚机制。

6. **Agent 安全问题会越来越重要。**  
   Carnegie 7 月 6 日发布报告，讨论自主 AI Agent 在网络安全里的治理缺口，重点是这些系统能计划、调用工具、记忆上下文并根据结果继续行动。[来源](https://carnegieendowment.org/research/2026/07/when-ai-agents-attack-autonomous-cyber-operations-and-europes-governance-gap)  
   如果一个 Agent 能访问浏览器、终端、邮箱、CRM、代码仓库，它就不只是聊天机器人，而是一个有实际操作能力的软件账号。  
   **建议**：高权限 Agent 一定要有最小权限、工具白名单、操作日志、人工审批和 prompt injection 测试。

7. **GitHub 热榜显示：开发者更喜欢“能直接塞进现有 AI 编程工具的小插件/小技能”。**  
   Star History 周榜显示，agency-agents、ponytail、strix、skills、caveman 是本周增长最高的 5 个 Coding AI 项目。[来源](https://www.star-history.com/)  
   它们的共同点不是做一个巨大平台，而是帮 Claude Code、Codex、Cursor、OpenCode 这些工具变得更有章法：少写废代码、更安全、角色更清楚、输出更短。  
   **建议**：如果你每天用 AI 写代码，可以先试一个“约束类”技能，比如让 Agent 少改代码、少说废话、先写测试。

## 分领域进展

### 设计生成

- **Claude Design：适合把想法快速变成原型、页面或演示稿。**  
  它的工作方式是左边聊天、右边画布。你描述需求，它生成设计；之后可以继续用聊天、评论或画布编辑来修改。它还支持导入设计系统和代码库，并把结果交给 Claude Code。[来源](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)  
  **适合谁**：产品经理、设计师、设计工程师、需要快速做内部工具原型的人。  
  **注意**：它还在 beta，复杂协作和大代码库导入不一定稳定。

- **Open Design：更偏开发者和本地工作流。**  
  Open Design 是开源的 Claude Design 替代方案，GitHub 页面显示约 75.6k stars。它支持本地桌面应用、设计系统、插件、多格式导出，并能接入 Claude Code、Codex、Cursor、OpenCode、Qwen 等工具。[来源](https://github.com/nexu-io/open-design)  
  **适合谁**：想把设计生成接入本地文件、代码仓库和 AI 编程工具的人。  
  **建议试法**：不要只看 demo，直接拿一个真实业务页面测试。

- **AI 原型工具的选择标准：看原型最后会不会变成产品。**  
  Open Design 的指南把工具分成几类：有些适合快速做可点击 mockup，有些适合生成可运行代码，有些适合做完整的 Agent 工作流。[来源](https://open-design.ai/blog/ai-prototyping-tools/)  
  **判断方法**：如果只是拿去开会讨论，用 mockup 工具就够；如果后面要继续开发，就要看代码质量、组件复用和是否遵循设计系统。

### 数据采集 / RAG

- **Firecrawl / OpenClaw：核心价值是把复杂网页变成 AI 能用的结构化资料。**  
  它强调搜索、抓取、浏览器交互、字段抽取、缓存控制等能力。[来源](https://www.firecrawl.dev/blog/best-openclaw-search-providers)  
  **为什么重要**：很多网页不是一打开就能看到全部内容，需要点击、筛选、翻页、等待 JS 加载。  
  **建议**：如果你做 RAG 或研究 Agent，要把“抓到了多少页面”升级成“字段是否准确、来源是否可靠、内容是否新鲜”。

- **不是所有自动化都需要 Agent。**  
  Firecrawl 对 chatbot、copilot、workflow、agent 做了区分：Agent 的特点是能根据观察结果继续选工具和调整计划。[来源](https://www.firecrawl.dev/blog/ai-agents)  
  **判断方法**：如果流程固定，用普通自动化更便宜、更稳定；如果任务需要查资料、处理异常、动态决策，再用 Agent。

### Agent 工作流

- **Microsoft Dataverse：企业 Agent 需要数据、权限和审计一起设计。**  
  Dataverse 插件进入 Claude、Cursor、GitHub Copilot 等市场，说明企业系统正在主动接入 AI 编程工具。[来源](https://www.microsoft.com/en-us/power-platform/blog/2026/07/06/dataverse-july2026/)  
  **建议**：企业内部不要让 Agent 直接“裸连”业务系统，先做好 MCP 管理、权限控制和日志。

- **Vercel：Agent 写代码之后，部署和验收会成为新重点。**  
  Vercel 的部署数据说明 coding agent 已经在影响真实软件交付。[来源](https://techcrunch.com/2026/07/06/vercel-ceo-guillermo-rauch-on-the-fight-to-split-off-models-from-agents/)  
  **建议**：AI 生成代码后，必须自动跑测试、生成预览链接、截图检查关键页面，最后再让人确认合并。

### 热门应用和工作流

- **Claude Design**  
  为什么火：它把聊天、画布、设计系统、代码交接放在一起。  
  适合场景：产品原型、内部工具、活动页、汇报 PPT。  
  是否值得试：值得，但要用真实品牌和真实页面测试。

- **Open Design**  
  为什么火：开源、本地优先、能和多个 AI 编程工具连接。  
  适合场景：设计工程、可导出的 HTML/PDF/PPTX/MP4、多 Agent 工作流。  
  是否值得试：值得作为 Claude Design 的开源对照组。

- **Firecrawl / OpenClaw 采集流**  
  为什么火：Agent 越做越多，大家都需要可靠的网页资料输入。  
  适合场景：RAG、竞品监控、网页数据采集、AI 研究助手。  
  是否值得试：如果你的资料来源主要是网页，值得试。

## 今天值得深入研究的 1 个主题

**主题：AI 设计生成如何进入真实产品流程。**

过去很多 AI 设计工具更像“灵感生成器”：给你一张好看的图，真正开发时还要重做。现在 Claude Design 和 Open Design 指向一个新方向：AI 先读取你的设计系统和代码库，再生成可预览、可导出、可交给代码工具继续实现的产物。

可以这样研究：

1. 选一个真实业务页面，不要用虚构 demo。
2. 准备品牌颜色、字体、组件库、业务文案。
3. 分别用 Claude Design、Open Design、v0/Lovable/Bolt 跑同一需求。
4. 比较四件事：看起来是否像你的品牌、交互是否完整、导出物能不能继续开发、工程师需要返工多少。

## 可忽略的噪音

- **没有来源的模型传言**：只来自社交媒体的跑分、泄露、截图，不适合做选型依据。
- **把总 stars 当近期增长**：总量高不等于最近增长快。本期 GitHub 热榜只采用 Star History 周榜口径。
- **万能 AI 设计 prompt 包**：没有设计系统、真实页面和导出验收，价值有限。
- **把所有自动化都叫 Agent**：流程固定时，用普通自动化通常更可靠、更便宜。
