6. **开源 Agent Skills 进入热榜主线。** 9 月 21 日 GitHub Trending 日榜中，Cloudflare `security-audit-skill`、`ECC`、`agent-skills` 同时高位出现；这说明“可读、可版本化的执行知识”正成为 Agent 工具链的重要分发单元。[GitHub Trending](https://github.com/trending?since=daily)。**影响：** 团队最佳实践正在从 wiki 迁移为可执行 skill。**行动：** 优先挑一个高频、可验收流程试做，不要先建庞大 skill 平台。

## 今天值得深入研究的 1 个主题

### 从“接工具”升级为“访问、流程、证据”三层 Agent 架构

今天的多个信号指向同一件事：MCP 解决访问层，Skills 解决流程层，trace / findings / evaluation 解决证据层。只接 MCP 会让 Agent “能做”但不一定“会正确地做”；只写 Skill 会得到可读流程但缺少稳定接口；没有证据层，就无法证明 Agent 做了什么、为什么这么做、结果是否被独立验证。

最小实践路径：

1. 选一个边界清楚的任务，例如“抓取 20 个官方发布页并生成带来源的变更摘要”。
2. MCP/工具层只暴露必要的 search、read、write 动作，并区分只读与写入。
3. Skill 写清来源优先级、时间窗、失败处理、禁止编造和验收条件。
4. 输出保留 URL、时间、工具调用、失败记录和可机器读取的 verdict。
5. 用一个独立 reviewer 检查引用、数字和结论，而不是让同一个 Agent 自证。

这条路线比先搭建“大一统 Agent 平台”更快得到可验证收益。
