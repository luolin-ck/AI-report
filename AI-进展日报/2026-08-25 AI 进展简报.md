## 今日最值得关注

### 1. OpenAI 在 8 月 24 日废弃 `codex mcp-server` 命令

- 来源：[OpenAI Release Notes](https://openai.com/products/release-notes/)
- 发生了什么：OpenAI 的 Codex 发布说明在 2026-08-24 标注 `codex mcp-server` 命令已 deprecated，建议改用 Codex app server；从 Claude Code 使用 Codex 时走 Codex plugin for Claude Code。
- 影响判断：这是一个小更新，但方向很明确：Codex 不再鼓励把本地 CLI 命令当作长期 MCP server 入口，而是把跨产品接入收敛到 app server / plugin 形态。
- 行动建议：如果你在 Claude Code、Cursor 或自建 MCP 客户端里接了旧 `codex mcp-server`，本周应该排查配置，准备迁移；不要等命令真正移除后再处理。

### 2. GitHub 今日趋势仍由 Agent / Skills / Coding 工具主导

- 来源：[GitHub Trending](https://github.com/trending)、[OrangeBot GitHub Trending Today](https://orangebot.ai/github-trending-today)、[whatstrending.ai Repos](https://whatstrending.ai/repos)
- 发生了什么：OrangeBot 2026-08-25 日榜显示，今日 GitHub Trending 前列包括 `Alishahryar1/free-claude-code`、`openai/codex`、`MadsLorentzen/ai-job-search`、`multica-ai/andrej-karpathy-skills`、`NousResearch/hermes-agent`、`anthropics/claude-plugins-community` 等。
- 影响判断：开发者正在追逐的不是单一模型，而是“把模型接入工作流”的工具：免费/替代入口、技能包、上下文系统、求职自动化、coding agent。
- 行动建议：工程团队可把这些项目分成三类评估：能马上提效的 CLI/agent、能沉淀流程的 skill、需要安全审查的自动化工具。

### 3. Figma 的近期更新说明设计生成正在技能化

- 来源：[Figma Release Notes](https://www.figma.com/release-notes/)、[Figma MCP Blog 标签页](https://www.figma.com/blog/figma-mcp/)、[Claude Design](https://claude.com/product/design)
- 发生了什么：Figma 8 月中旬连续更新 Agent Skills、Figma MCP / Weave tools；8 月 21 日又发布 responsive spacing across design and CSS，让 Auto Layout 与 CSS 间距语义更一致。Claude Design 仍在强调设计系统导入、编辑器与 Claude Code 同步、品牌一致性。
- 影响判断：设计生成的竞争点从“能不能出图”转到“能不能遵守设计系统、复用品牌上下文、交付到代码/原型链路”。
- 行动建议：设计团队不要只试 prompt-to-UI；更应把组件库、品牌规范、评审规则写成 skills / MCP 上下文，让 Agent 每次生成都带约束。

### 4. Firecrawl Developer Index 把网页抓取推向 coding-agent 专用上下文

- 来源：[Firecrawl Product Updates](https://www.firecrawl.dev/blog/category/product-updates)、[Firecrawl Monitor](https://www.firecrawl.dev/monitor)
- 发生了什么：Firecrawl 8 月 20 日发布 Developer Index，面向 coding agents 提供 README、docs、issues、PR 等开发上下文，官方称覆盖 70M+ artifacts 且多数来源每日刷新；此前 /monitor 也已强调全网监控、diff、judge、push。
- 影响判断：RAG/抓取工具的下一步不是“把网页转 Markdown”这么简单，而是按 Agent 任务结构预整理上下文，并能持续监控变化。
- 行动建议：如果你在做 coding agent 或知识库，优先评估“索引是否覆盖 issue/PR/版本变更、是否可增量刷新、是否能给出可引用证据”，而不是只看抓取速度。

### 5. Nvidia 与 Poolside 的大额交易强化开源权重模型竞争

- 来源：[WSJ 报道](https://www.wsj.com/tech/ai/nvidia-is-spending-6-billion-to-build-a-powerful-u-s-alternative-to-chinese-ai-c51c38cc)
- 发生了什么：WSJ 报道 Nvidia 计划投入约 60 亿美元，与 Poolside 团队和技术结合，推进 Nemotron 开源权重模型项目，以应对 DeepSeek、Kimi 等开放模型带来的竞争。
- 影响判断：算力厂商不只卖 GPU，也在向“模型生态控制权”推进；这会影响企业在闭源 API、自建推理、开源权重模型之间的选择。
- 行动建议：平台团队可把 Nemotron、DeepSeek、Kimi、Claude/OpenAI API 放在同一评测矩阵：成本、延迟、工具调用、部署约束、数据边界，而不是只看榜单分数。

### 6. Agent 网络安全风险继续进入主流媒体议程

- 来源：[The Guardian 2026-08-23](https://www.theguardian.com/technology/2026/aug/23/openai-cyber-attacks-threat-chris-lehane)、[OpenAI Deployment Safety Hub](https://deploymentsafety.openai.com/gpt-5-6-august-update)
- 发生了什么：Guardian 继续报道 OpenAI 管理层对持续性 AI cyber-attacks 的警告；OpenAI 的 GPT-5.6 安全材料也把 cyber capability evaluations、safeguards、model safety training 等作为重点。
- 影响判断：企业试用 Agent 时，风险边界不能只靠“模型会听话”；需要沙箱、权限、审计、网络边界、密钥隔离和人工审批。
- 行动建议：凡是能访问浏览器、shell、仓库、云账号或内部数据的 Agent，都应先做最小权限清单和失败演练。

### 7. MCP / Agent Skills 官方基线未发现新版本，但生态接入方式在迁移

- 来源：[MCP 2026-07-28 变更日志](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/changelog.mdx)、[MCP 2026-07-28 Blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)、[Build with Agent Skills](https://modelcontextprotocol.io/docs/develop/build-with-agent-skills)、[Agent Skills Specification](https://agentskills.io/specification)
- 发生了什么：本次检索未发现 MCP 官方协议版本超过 `2026-07-28`；`mcp-server-dev` 官方技能仍是 `build-mcp-server`、`build-mcp-app`、`build-mcpb`。但 OpenAI 的 Codex MCP server 命令废弃，说明具体工具接入在继续收敛。
- 影响判断：协议层稳定，产品层迁移；现在适合升级 SDK 和接入方式，但不必追逐不存在的新协议版本。
- 行动建议：新 MCP server 默认按 2026-07-28 stateless / modern era 思路设计；旧 2025-era server 要保留兼容路径并规划升级。

## 分领域进展

### 设计生成

本节结论：设计生成正在从“单次产图/产页面”走向“设计系统 + Agent Skills + MCP 工具调用”。

- Figma 的 8 月更新把三个层面连了起来：Figma Community 里可发现/发布 agent skills；Weave tools 可通过 Figma MCP 由 ChatGPT、Claude、Cursor 等客户端调用；responsive spacing 把设计布局语言和 CSS 语义对齐。来源：[Figma Release Notes](https://www.figma.com/release-notes/)
- Product Hunt 的 AI Designer 分类在 8 月仍把新工具描述为端到端资产生成、设计到代码、设计系统复用、UI prototyping。来源：[Product Hunt AI Designer](https://www.producthunt.com/categories/ai-designer?order=recent_launches)
- Claude Design 的产品页强调 on-brand visual work、设计系统导入、Claude Code sync、Gamma 等外部工具连接。来源：[Claude Design](https://claude.com/product/design)

建议动作：

- 设计团队：沉淀一套“生成前约束”，包括品牌 tokens、组件禁用项、文案语气、响应式规则、可访问性要求。
- 前端团队：把 Figma MCP / Code Connect / skills 当作设计到代码的上下文桥，而不是单独的自动生成按钮。
- 创业团队：如果做 AI 设计工具，不要只做“prompt 出图”；更有价值的是垂直场景闭环，例如电商素材、B2B 产品原型、设计系统迁移、品牌批量生产。

### 数据采集 / RAG

本节结论：抓取工具正在围绕 Agent 的“持续上下文需求”重构。

- Firecrawl Developer Index 的关键不是覆盖量本身，而是覆盖对象：README、docs、issues、PR 这些才是 coding agent 修 bug、接 API、理解仓库变化时最需要的上下文。来源：[Firecrawl Product Updates](https://www.firecrawl.dev/blog/category/product-updates)
- Firecrawl Monitor 把网页监控包装成 watch / diff / judge / push，这适合监控模型文档、价格页、竞品 changelog、政策条款、GitHub release。来源：[Firecrawl Monitor](https://www.firecrawl.dev/monitor)
- `unclecode/crawl4ai` 在 whatstrending.ai 快照中仍有 79.3k stars、153 stars today，说明开源 LLM-friendly crawler 仍有稳定需求。来源：[whatstrending.ai Repos](https://whatstrending.ai/repos)、[crawl4ai GitHub](https://github.com/unclecode/crawl4ai)

建议动作：

- RAG 团队：把“文档是否新鲜、是否能追溯来源、是否能按任务切片”作为评估标准。
- 运营/研究团队：把监控对象从单网页扩展到“主题 + 来源集合”，让 Agent 只在真实变化时提醒。

### Agent 工作流

本节结论：Agent 工作流的热点集中在 skills、context database、coding CLI、个人/团队自动化。

- `openai/codex` 今日仍位居 GitHub Trending 前列；OpenAI Help Center 对 Codex CLI 的定位是本地运行的 lightweight coding agent。来源：[openai/codex GitHub](https://github.com/openai/codex)、[OpenAI Codex CLI Help](https://help.openai.com/en/articles/11096431)
- `DietrichGebert/ponytail`、`obra/superpowers`、`multica-ai/andrej-karpathy-skills` 都说明一件事：开发者愿意给 Agent 装“行为约束和工程方法论”，而不只是换模型。来源：[ponytail](https://github.com/DietrichGebert/ponytail)、[superpowers](https://github.com/obra/superpowers)、[andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills)
- `volcengine/OpenViking` 关注 context database，把 memory、resources、skills 用类文件系统范式统一起来。来源：[OpenViking](https://github.com/volcengine/OpenViking/)

建议动作：

- 团队引入 Agent 前，先选 2-3 个高频流程做 skills：代码评审、bug 定位、发布检查、PRD 到任务拆解。
- 不要把所有知识都塞进一个长 `AGENTS.md`；更适合按技能拆分，按需加载。

## 今天值得深入研究的 1 个主题

### Agent Skills 从“提示词文件”到“工作流分发层”

为什么今天值得研究：

- GitHub 热榜里 skills/rules/plugin 仓库持续高热；

- Skills 的低门槛会带来爆发，也会带来质量、安全、权限、重复包装问题。

建议研究路径：

1. 读官方规范：[Agent Skills Specification](https://agentskills.io/specification)
2. 看官方示例：[anthropics/skills](https://github.com/anthropics/skills)
