## 阅读导览

今天的 AI 进展可以先按三条主线理解：

1. **Agent 正在从“会聊天/会写代码”变成可部署工作台。** OpenAI/Codex、Claude Platform、GitHub 上的 agent harness、Skills 仓库都指向同一个方向：开发者不再只比较模型，而是在搭建能连接文件、浏览器、终端、技能库和审计日志的工作系统。
2. **安全治理正在变成 agent 产品的默认门槛。** OpenAI 放慢 cyber-critical 能力训练、Anthropic 把 Mythos 5 放进受控安全产品、MCP 强调 stateless 和 capability negotiation，本质上都在解决同一个问题：高能力 agent 不能默认拥有高权限。
3. **设计生成和 RAG 都在走向“垂直化、可复用、可治理”。** Figma 把 skills、Weave 和 MCP 接到组织流程；Firecrawl 把抓取从网页拓展到 developer artifacts。工具价值从“生成一次结果”转向“稳定服务团队流程”。

## 今日最值得关注

### 1. OpenAI 安全节奏继续成为 24-48 小时核心议题

- **发生了什么**：The Guardian 8 月 23 日报道 OpenAI 高管警告 AI cyber-attack 已进入 persistent 阶段；OpenAI 8 月 18 日也公开说明，因 OpenAI-Hugging Face 事件和 Astra 达到 cyber-critical threshold 的内部信号，临时放慢相关训练节奏。
- **为什么重要**：这不是单一安全新闻，而是高能力 agent 上线方式的变化。未来模型如果能自主写代码、联网、操作浏览器、调用工具，就必须同时有沙箱、联网边界、凭据隔离和审计。
- **谁应该关注**：做 agent 平台、AI coding、企业内部自动化、安全评测的人。
- **行动建议**：本周先检查内部 agent eval 是否能访问真实 token、生产网络、共享文件或内部系统；如果能，先收紧权限，再谈扩大使用范围。
- **来源**：[The Guardian](https://www.theguardian.com/technology/2026/aug/23/openai-cyber-attacks-threat-chris-lehane)、[OpenAI](https://openai.com/index/pacing-model-development-cyber-capabilities/)

### 2. GitHub 今日热榜被 Codex、Skills 与 agent harness 占据

- **发生了什么**：GitHub Trending 今日页集中出现 Codex、Skills、free Claude/Codex、Hermes Agent、ECC 等 agent 相关项目；具体 star 数据统一放在后文“GitHub 开源热榜”，这里不重复。
- **为什么重要**：开发者热点已经从“哪个模型更聪明”转向“怎样把模型放进可重复、可审计、可安装的工作流”。Skill、插件、harness、memory、CLI 正在成为 agent 产品的基础层。
- **谁应该关注**：高频使用 Codex、Claude Code、Cursor、OpenCode 的开发者和工程负责人。
- **行动建议**：不要只收藏热门仓库。更实用的做法是挑一个团队高频流程，例如 PR 评论处理、线上问题排查、竞品研究，写成 skill，并明确输入、输出、权限、验证和禁止动作。
- **来源**：[GitHub Trending](https://github.com/trending)

### 3. Anthropic 把 agent 平台能力正式推到 GA

- **发生了什么**：8 月 20 日 Anthropic 宣布 computer use、browser use、Skills API、Files API 在 Claude Platform GA。Browser use 强调页面结构定位，Skills API 支持上传和版本化团队技能，Files API 提供组织级文件能力。
- **为什么重要**：这意味着 Claude Platform 不再只是模型 API，而是在补齐生产 agent 需要的执行环境：浏览器、文件、技能、版本管理和企业存储。
- **谁应该关注**：正在做浏览器自动化、后台运营自动化、客服/销售辅助、企业知识工作流的团队。
- **行动建议**：如果已经在用 beta computer use，不要只看动作成功率；还要检查 request shape 是否变化、文件保留策略、rate limits、浏览器动作日志、失败回滚和人工确认点。
- **来源**：[Claude Blog](https://claude.com/blog/computer-use-skills-api-files-api)

### 4. Claude Mythos 5 显示高风险能力会以“受控产品形态”开放

- **发生了什么**：8 月 21 日 Anthropic 宣布 Mythos 5 进入 Claude Security，并推出 3500 万美元开源安全 credits。Anthropic 明确强调它面向防守者，并且扫描结果仍需要人工审查。
- **为什么重要**：这给高能力模型的开放方式提供了一个样板：能力不一定直接作为通用聊天模型开放，而可能被封装成特定场景、特定输出、特定权限边界的产品功能。
- **谁应该关注**：安全团队、模型平台团队、做自动代码审计或漏洞修复的团队。
- **行动建议**：可以关注代码扫描和补丁建议，但不要把模型输出直接当漏洞结论；至少保留复现、CWE/严重度校验、误报处理和人工审批。
- **来源**：[Claude Blog](https://claude.com/blog/bringing-claude-mythos-5-to-more-defenders)

### 5. Firecrawl Developer Index 是 RAG/抓取方向本周最重要官方更新

- **发生了什么**：8 月 20 日 Firecrawl 发布 Developer Index，面向 coding agents 索引 README、docs、issues、PR、OpenAPI specs，并同步发布 DevDex 评测基准。
- **为什么重要**：RAG 的关键对象不再只是网页正文，而是开发者真正需要的 artifacts：issue 里的报错、PR 里的修复、OpenAPI 里的参数、README 里的集成路径。
- **谁应该关注**：做 coding agent、文档问答、开源项目支持、SDK 支持、技术客服的团队。
- **行动建议**：如果你的 agent 经常回答“某个 API 怎么用”“这个报错有没有已知 issue”，优先测试 Developer Index，而不是自己拼 GitHub API、搜索引擎和网页抓取。
- **来源**：[Firecrawl Blog](https://www.firecrawl.dev/blog/developer-index-launch)

### 6. Figma 近期 AI 更新强调组织内推荐 skills 与外部 agent 调 Weave

- **发生了什么**：Figma Release Notes 显示，8 月 17 日管理员可推荐 skills、templates、libraries、Make kits；8 月 13 日开放 Figma agent skills 社区；8 月 11 日通过 Figma MCP 让 ChatGPT、Claude、Cursor 等运行 Weave tools。
- **为什么重要**：AI 设计生成正在从“个人临时 prompt”进入“团队可推荐、可复用、可治理”的阶段。对设计系统团队来说，这比单次生成漂亮页面更重要。
- **谁应该关注**：设计系统团队、品牌团队、增长素材团队、产品原型团队。
- **行动建议**：先挑三个高频动作做 skill 化：品牌 mockup、批量尺寸适配、handoff 检查。每个 skill 都要记录适用场景、输入素材、输出格式和人工验收点。
- **来源**：[Figma Release Notes](https://www.figma.com/release-notes/)、[Figma MCP Catalog](https://www.figma.com/mcp-catalog/)

建议本周做一个小研究：选 5 个高热 skill 仓库，逐个检查 `SKILL.md` 触发条件、脚本、网络调用、权限要求、是否读取 secrets、是否要求执行未知命令、是否有验证步骤。输出一份团队 skill 安装规范：默认只读、先审后装、禁止自动执行高危动作、所有外部网络和凭据访问必须显式批准。
