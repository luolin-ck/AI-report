## 今日最值得关注

### MCP / Agent Skills 更新

#### 本次结论

**发现 Reference Servers 新版；未发现核心协议新版，也未发现 `mcp-server-dev` 官方技能目录新增。** MCP 核心协议当前基线仍为 **2026-07-28**，[官方版本说明](https://blog.modelcontextprotocol.io/posts/2026-07-28/)未在本窗口出现后继版本。11 月 4 日发布的 **Reference Servers v2.3.0** 是参考实现升级，不应表述成协议版本升级。

#### Reference Servers v2.3.0（2026-11-04）

- **更新来源：** [modelcontextprotocol/servers v2.3.0](https://github.com/modelcontextprotocol/servers/releases/tag/v2.3.0)。涉及 `server-everything 2.2.1`、`server-filesystem 2.2.0`、`server-memory 2.1.0`、`server-sequential-thinking 2.1.1`，以及 `mcp-server-fetch/git/time 2026.11.4`。
- **能力变化：** filesystem 新增 `append_file`、`copy_file`、可选深度的 `directory_tree`、文件资源、只读模式与 `--confine-roots`；fetch 新增 `--allowed-hosts`、可配置超时、原生 Markdown 协商和有界 Readability 子进程；git 新增 `git_merge`、只读 `git_remote`、revision range 与包含仓库变更的 prompts；memory 增加轻量读取模式和幂等提示。
- **迁移影响：** 工具数量、参数和可见资源会改变客户端能力发现结果；安全默认值与路径/主机允许清单需要重新审核。核心协议没变，因此不是协议层破坏性迁移，但依赖旧工具列表的测试可能需要更新。
- **适合场景与建议：** 适合自托管 MCP 服务、IDE/Agent 集成和安全基线团队试用。先在测试环境开启只读模式、`--confine-roots` 与 `--allowed-hosts`，执行能力枚举和拒绝用例，再逐步开放 append/copy/merge 等写操作。

#### Build with Agent Skills 当前基线

- **适合谁：** MCP 客户端、交互式工具和已有 Web 产品团队。建议先验证目标客户端对扩展的支持，再决定迁移范围。

## 今天值得深入研究的 1 个主题

### 从“更强 Agent”转向“可证明受控的 Agent harness”

今天最值得串联的不是某个单一模型，而是三条同时发生的变化：GPT-6 Cyber 用明确范围约束高能力安全模型，MCP Reference Servers v2.3.0 把只读、目录约束和主机白名单做进参考实现，开发者社区则集中讨论 Agent 是否外发身份信息、是否因任务表述改变行为。共同结论是：**模型能力越强，执行层就越需要可验证的边界。**

一个可复用的落地框架是：输入侧做敏感字段分类和来源标记；工具侧做最小权限、只读优先、路径/主机允许清单；执行侧记录每次调用、范围判断和拒绝原因；评测侧同时跑正常任务、越权任务、表述扰动和恢复测试；输出侧保留证据链接、人工审批与回滚点。对准备上线桌面操作、浏览器 Agent、RAG 采集或安全 Agent 的团队，这套 harness 比追逐单次 benchmark 更值得投入。
