### Agent 工作流

- **Google Home MCP 是今天最值得警惕的 Agent 工作流。** 它让 Agent 查询实时设备状态、历史事件并执行设备命令，官方也写明 real-life home 接入 Agent 有意外行为风险。最小安全实践：只连测试环境、禁高风险动作、保留 OAuth 撤销入口、所有执行动作留审计。

## MCP / Agent Skills 更新

- **官方主规范基线：MCP 2026-07-28。** 本次打开 [MCP specification](https://modelcontextprotocol.io/specification/2026-07-28) 仍重定向到 2026-07-28；该页把 MCP 定义为 LLM 应用与外部数据/工具的开放协议，并列出 Resources、Prompts、Tools、Elicitation，以及 Tasks、Skills over MCP、MCP Apps 等扩展。

- **关键更新：Skills over MCP 已经进入 Final。** `modelcontextprotocol/ext-skills` README 明确写到：官方 Skills extension `io.modelcontextprotocol/skills` 的 source of truth 是 `specification/stable/skills.mdx`，写在 base protocol revision `2026-07-28` 上；SEP-2640 为 accepted SEP，Status: Final，PR #2640 merged 2026-09-13。昨天仍按草案/决策日志跟踪，今天应把它升为可执行基线。

- **能力变化：从“下载 skill 包”变成“声明扩展 + list/get + resources/read + manifest 校验”。** 官方 overview 要求支持 Skills 的 server 在 `server/discover` 里声明 `resources` 能力和 `io.modelcontextprotocol/skills` 扩展；必须实现 `skills/list` 与 `skills/get`，文件内容通过 `resources/read` 读取，可选 `resources/directory/read`。`skills/list` 条目包含 `uri`、`frontmatter`、`resources` manifest；manifest 必须包含 `SKILL.md` 和所有 supporting files 的 uri、SHA-256 digest 和 byte size。

- **迁移影响：旧 `skill://index.json` 与 archive 路径不应继续作为新实现目标。** Final 版强调 list/get、完整 manifest、按需读取和 digest/size/frontmatter 校验。Host 必须保留 originating server identity + skill URI，不能只按 skill name 去重；同名 skill 不得静默替换。

- **安全要求更具体：skill 内容是 untrusted input，代码执行和 allowed-tools 需要 per-skill 明确批准。** Overview 写明 Host 必须限制读取到 manifest 内 URI，验证每个文件的 byte size 和 SHA-256 digest，比较 `SKILL.md` frontmatter；跨 server 读取需要逐次批准；nested skill 读取不等于激活。

- **Build with Agent Skills 页面仍推荐 `mcp-server-dev` 作为 MCP 开发技能集。** 官方 docs 中 `build-with-agent-skills.mdx` 写到参考 skill set 有 `build-mcp-server`、`build-mcp-app`、`build-mcpb`：前者做 use case discovery 和部署/工具模式选择，后两者分别面向 MCP Apps 和 MCPB 本地打包。行动建议：如果要做 MCP server，优先从这三个 skills 的路径拆需求，不要直接生成一堆通用工具。

- **适合谁试用：MCP server 作者、企业 skill registry、coding agent 平台、安全审计团队。** 最小实现清单：`server/discover` 扩展声明、`skills/list` 分页/缓存字段、`skills/get` 直取、`resources/read` 按源 server 读取、完整 manifest、digest/size/frontmatter 校验、同名 skill 消歧、per-skill tool/code approval。

## 今天值得深入研究的 1 个主题

**MCP/Agent Skills 从草案到 Final 后，内部 Agent 平台应该怎么改。**  
最值得做的不是再收集 skill 列表，而是把 skill 作为“可验证的执行资产”管理：每个 skill 有 source server、URI、frontmatter、manifest、digest、size、版本/缓存策略、审批记录和工具权限。Host 只在需要时读取文件，不预取；读取时校验 digest 和 size；同名 skill 必须显示来源；包含脚本或要求工具权限时做 per-skill 审批；skill 更新后撤销旧批准。这个主题会直接影响企业内部 Agent 的安全、复用、审计和分发。
