## 分领域进展

### 设计生成

- **Figma MCP + Weave 是今天最值得做实验的设计生成更新。**Figma release notes 写明，2026-08-11 起，用户可以从 ChatGPT、Claude、Cursor 等 agent 客户端运行 Figma Weave 工具；agent 会找到工具、运行工具、跟踪进度并在对话中返回结果。Figma 还提示下一步是“在 agent 内直接构建新的 Weave workflows”。这意味着品牌 mockup、商品图、社媒素材、视频/音频创意等 workflow 可以被纳入跨工具 agent 编排。
- **Figma MCP Catalog 显示生态接入面已经很宽。**Catalog 页面列出 Claude、Claude Code、ChatGPT、Codex、Cursor、VS Code、GitHub Copilot CLI、Grok、Devin、Warp、Factory、Augment 等客户端，且多数组合支持 Figma Design/FigJam/Figma Weave 的读写或读访问。对团队来说，核心问题不再是“能不能接”，而是“哪些客户端允许写入、谁批准、写入哪些文件、是否污染设计系统”。
- **Figma 近期设计到代码方向仍值得作为基线。**7 月以来的 release notes 还包括 Figma Make 编辑面板、Auto Layout 与 CSS 更接近、code-backed screens 带变量回到 canvas、GPT-5.6 进入 Figma Make 等。今天的 Weave MCP 更新把这些能力从 canvas 内部延展到 agent 外部，形成“设计系统 -> agent -> Weave 工具 -> 结果回到对话/画布”的链路。
- **Claude Design / AI 设计教程仍有长尾传播，但本轮没有拿到 24-48 小时官方新发布。**YouTube 官方页面在本轮检索中没有稳定返回可核验播放/点赞指标；Figma 官方 release notes 链接了 Weave MCP 教程视频，但本报告不把它写成 YouTube 热榜。行动上，设计团队更应关注是否能复用变量、组件、tokens、品牌素材和导出链路，而不是单次截图质量。
- **适合本周试点的最小实验：**选一个已存在的品牌素材库，创建一个 Figma Weave mockup 工具；用 ChatGPT/Codex/Claude Code 经 Figma MCP 调用；记录生成时间、品牌一致性、人工修改次数、输出是否能回到设计系统、失败时是否泄漏素材或上下文。

### 数据采集 / RAG

- **Firecrawl `/search` 升级仍是 RAG 工程的实用参考。**官方 changelog 2026-07-22 更新表示，`/search` 会返回最能回答 query 的 excerpts，而不是让 agent 处理整页内容；相关性模型会评分段落、列表和表格。官方指标显示 SimpleQA 94.7%、少用 10x token。口径限制：这是厂商官方指标，需用自有任务集验证。
- **Firecrawl 的产品线已经覆盖 search、scrape、interact、parse、monitor、Research Index。**这说明 RAG/AI 搜索供应商不再只是“抓取器”，而是朝 agent context API 发展：找到网页、提取证据、解析 PDF/文档、监控变化、处理动态页面、减少 token 和保留 citation。
- **GitHub 上中文内容采集项目仍有高关注。**`NanmiCoder/MediaCrawler` 继续在 GitHub Trending 中出现，覆盖小红书、抖音、快手、B 站、微博、贴吧、知乎等内容/评论采集。适合做合法合规的研究与数据实验，但不能绕过平台条款、隐私边界或授权限制。
- **RAG 方向的行动建议：**建立一个固定测试集，至少包括新闻页、文档页、PDF、登录前动态页、表格页、长页面和多语言页面；每次工具更新后记录 freshness、召回率、可引用性、token cost、解析失败率和 prompt injection 抵抗能力。

### Agent 工作流

- **GitHub 日榜显示 agent 工作流正在“产品化 + 模板化”。**`stablyai/orca` 定位为管理并行 coding agents 的 ADE，`earendil-works/pi` 提供 unified LLM API、agent loop、TUI、coding agent CLI，`msitarzewski/agency-agents` 提供岗位型 agent 模板，`anthropics/skills` 提供 Agent Skills 参考实现。这些都指向一个趋势：用户不满足于单个聊天窗口，需要能复用、能并行、可审计、能跨会话恢复的工作台。
- **企业 MCP 进入基础设施自动化。**Nutanix MCP server 报道中最重要的不是“用自然语言管云”，而是它强调 RBAC、API throttling、auditing、异步任务管理和人类监督。这是基础设施 agent 落地的正确方向：MCP server 必须继承原系统的权限和审计，而不能绕过平台控制面。
- **OpenAI Atlas 向 ChatGPT/Codex browser-based agentic work 迁移仍是近期平台背景。**OpenAI Help Center 页面显示 Atlas 已计划在 2026-08-09 停止工作，并将浏览器式 agent 能力并入 ChatGPT 与 Codex，强调多标签、下载、导航和登录支持。行动建议：如果内部流程依赖浏览器 agent，应该迁移到受支持客户端，并重新审查 cookie/session 文件处理规范。来源：[OpenAI Help Center](https://help.openai.com/en/articles/20001371-evolving-atlas-into-chatgpt-for-browser-based-agentic-work)
- **工作流落地标准：**任何 agent 工作流都至少要说明输入、工具、权限、状态保存、重试策略、人工确认点、日志位置和回滚方式。没有这些，agent 越强，生产风险越高。

### 热门应用

- **AI 设计与创意生产：**Figma MCP + Weave 是今天最清晰的新进展，适合品牌素材、活动海报、电商 mockup、短视频/音频创意 workflow 做小规模试点。值得尝试，但要先设置资产访问范围和输出审查。
- **AI app builder / chat-to-build：**Product Hunt AI topic 本轮列出 Assembly、Raydian、LaraCopilot、CatDoes v4、Framer AI Agents 等方向，说明“用聊天生成真实应用”仍热。评估时重点看是否能导出代码、接入真实数据库、支持 GitHub 同步、测试失败是否自动修复，以及是否存在平台锁定。
- **Agentic browser automation：**Product Hunt 的 AI Browser、No-Code AI Agent Builder 类目的 Airtop 都指向浏览器自动化。适合增长运营、表单处理、网页数据采集、非 API 系统操作，但需要强审计和登录态隔离。
- **AI coding cost observability：**Product Hunt recent launches 中 CodeBurn 的定位是查看 AI coding spend。随着 coding agent 从单轮补全走向长任务和并行 agent，成本可见性会成为真实痛点。适合使用多个 coding agent 订阅、API key 或团队额度的工程组织。
- **Enterprise agent control plane：**Cohesor、Nutanix MCP、Figma MCP Catalog、X MCP docs 都显示控制面正在变重要。适合平台团队关注，而不是只看单个 agent 客户端。

## 今天值得深入研究的 1 个主题

**把设计生成工具接进可审计 agent 工作流。**

今天最有行动价值的主题不是“哪个 AI 画图更好看”，而是 Figma Weave、Figma MCP、diagram-design、Agent Skills、MCP Catalog 同时指向的一条生产链：设计/创意能力正在被包装成 agent 可以调用的工具和技能。

建议做一次内部小研究：

- 输入层：品牌指南、设计系统 tokens、组件库、产品图、PRD、竞品截图、营销文案是否有明确访问范围。
- 编排层：agent 是 ChatGPT、Codex、Claude Code 还是 Cursor；工具通过 MCP、skill、CLI 还是浏览器自动化暴露。
- 生成层：生成的是 Figma layer、Weave 结果、HTML/SVG、PPT、图片还是代码；是否可编辑、可版本化、可复用。
- 审计层：每次读取了哪些素材，调用了哪些工具，输出到哪里，谁批准写入，失败时是否保留日志。
- 评测层：品牌一致性、设计系统复用率、响应式质量、人工返工时间、素材泄漏风险、计费可预测性。

最小实验可以是一条“商品图 -> Figma Weave mockup -> landing page diagram -> 设计评审 checklist”的工作流，要求全程保留来源链接、版本号和人工确认点。
