## 分领域进展

### 设计生成

- 过去 24-48 小时没有检索到 OpenDesign 或“Claude Design”级别的明确官方新品发布；更强的信号来自社区对 GPT Image 2、Claude Code 设计/原型流程的使用扩散。GitHub Trending 的 [awesome-gpt-image-2](https://github.com/SenYue0419/awesome-gpt-image-2) 以 1,698 stars today 进入榜首，说明多模态图像生成的提示词、案例和工作流仍有强需求。
- 对 UI/UX 团队来说，近期值得复盘的不是“又一个设计生成器”，而是“设计稿、代码、截图、prompt、品牌规范”能否被 agent 串成可重复流程。Anthropic 的 Skills API 把团队经验封装为可上传、可版本化 skill，这对设计系统、品牌模板、提案文档生成更实际。
- 建议：把设计生成工具分成三层评估：视觉探索、设计到代码、品牌一致性校验。只看首屏生成效果会高估工具成熟度。

### 数据采集 / RAG

- Firecrawl Developer Index 不是新抓取 API，但它把 AI 开发者工具按社区和开发者使用信号做了公开榜单化包装。对 RAG 团队有用的点是：抓取工具正在从“网页转 Markdown”进入“数据入口 + 评测 + 生态发现”阶段。
- Firecrawl 今年的 Search API 也值得一起看，它强调可面向 AI agent 的检索与网页抽取组合。评估时应关注三件事：是否能稳定返回正文结构、是否保留来源 URL/时间、是否能处理动态页面和反爬限制。来源：[Firecrawl Search API](https://www.firecrawl.dev/blog/search-api)。
- 建议：RAG 数据采集流水线不要绑定单一抓取服务；保留抽取质量回归集，至少覆盖官网、文档、博客、论坛、登录墙边界页面。

### Agent 工作流

- Claude Platform 的 browser use + Skills API + Files API 是本周最明确的 agent 工程化信号。它将“看屏幕操作网页”“按团队 SOP 执行”“读写文件产物”放进同一平台能力里。
- OpenAI 开发者社区近期也在围绕 Codex/agent harness 做平台化讨论，趋势是把 coding agent 从单次 CLI 调用，升级为可编排、可审计、可复用的自动化执行器。来源：[OpenAI Developers](https://developers.openai.com/blog/codex-as-a-platform/)。
- 建议：不要一上来做通用 agent。先选一个状态清晰、输入输出文件明确、失败可回滚的任务，如日报、PR 评论处理、客服工单摘要。

#### 解读

- 黄金维持高位并接近 1,000 元/克折算区间，说明避险和财政/美元信用担忧还没有退潮。它和 AI 资产不是同一类风险暴露：VXN 上行通常压制高估值成长股，黄金上行通常代表避险或实际利率/美元预期变化。

#### 交叉验证后的操作建议

- 对已有黄金配置：核心仓位可以继续持有，不建议因为短期上涨一次性抛售；但也不建议在 4,650-4,700 美元/盎司、约 1,000 元/克上方追高加仓。若仓位已明显高于长期配置或属于短线交易仓，可分批止盈一部分。
- 为什么不是直接抛售：现货金、COMEX 结算价和 WSJ 报道方向一致，均显示黄金仍在上行趋势附近；驱动因素包括美国财政担忧、美元信用再定价、地缘风险和央行/避险需求。
- 为什么也不是追高买入：价格已经接近 4,700 美元/盎司与 1,000 元/克心理位，短线拥挤度高；如果后续美元反弹、长端美债收益率继续上行，或避险情绪降温，黄金容易回撤。
- 更实用的规则：长期避险仓位可继续持有；超配部分可在 4,700 美元/盎司附近或人民币 1,000 元/克上方分批锁定利润；若回落到 4,550-4,600 美元/盎司附近且宏观避险逻辑仍成立，再考虑分批补回。国内实物金、首饰金、纸黄金会叠加工费、品牌溢价、税费、点差和流动性影响，不能直接等同于国际金价折算。

### MCP / Agent Skills 更新

- 当前官方规格基线：MCP `2026-07-28`。核心变化是 stateless 协议核心、移除旧的 initialize/initialized 握手和 `Mcp-Session-Id` 依赖、引入 `server/discover`、Tier 1 SDK（TypeScript、Python、Go、C#）同步支持，Rust SDK beta 支持。来源：[The 2026-07-28 Specification](https://blog.modelcontextprotocol.io/posts/2026-07-28/)。
- 8 月 26 日运行时检查结果：未发现 2026-08-24 至 2026-08-26 期间新的官方 MCP 规格版本；保留 `2026-07-28` 作为当前基线。
- 官方新路线图（2026-08-22）仍值得跟踪：agentic messaging primitives、HTTP-native transport unification and hardening、agent identity and enterprise-ready security、improved primitives、SDK developer experience。迁移影响：旧 server 如果依赖会话粘性、单实例状态或旧 header，需要改为请求自包含、可横向扩展的设计。来源：[The New MCP Roadmap](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)。
- Agent Skills 侧，Anthropic 8 月 20 日宣布 Skills API 一般可用：skill 是包含指令、脚本和模板的文件夹，可上传、版本化，并在 Claude 的代码执行沙箱中按任务加载。适合场景：行业 SOP、文档生成、审查清单、设计系统规范、表格/幻灯片模板。迁移建议：先把稳定 SOP 抽成小 skill，不要把全部业务知识塞进一个巨型 skill。来源：[Claude Skills API announcement](https://claude.com/blog/computer-use-skills-api-files-api?query=Uplead&sort_date=desc)。
- `mcp-server-dev` / 官方 skill 目录检查口径：本次以 MCP 官方博客、规格页、Build with Agent Skills 页面和可公开检索到的官方/权威目录为准；未发现 24-48 小时内新增官方 skill 名称。当前可用做法是围绕 `build-mcp-server`、`build-mcp-app`、`build-mcpb` 这类开发技能拆分职责：server 实现、客户端集成、插件打包分别维护。
