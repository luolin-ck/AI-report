# 2026-10-22 AI 进展简报

> 采集窗口：优先 2026-10-20—2026-10-22，必要处补充近 7 日；动态榜单访问于 2026-10-22 11:12—11:20 CST。涉及厂商 benchmark、GitHub `stars today` 和社区热度的数字均保留原始口径，不把它们改写成独立测得的生产效果、滚动 24 小时净增或全平台排名。

## 今日最值得关注

1. **Claude Duet 把“主动来找你”的常驻 Agent 带入消费级产品。** [Anthropic 10 月 21 日公告](https://claude.com/resources/articles/claude-duet)显示，它可在云端虚拟机持续处理连接应用中的任务、发送晨报，并在发消息、付款、签署或删除前等待批准；目前仅面向美国 Pro / Max 用户候补测试。**影响：** Agent 的竞争从一次性对话转向持续监测、判断与审批。**行动：** 只接入低敏感账号，记录后台检查消耗、误报/漏报和人工批准率，再决定是否扩大权限。
2. **OpenAI 模型与 Codex 将进入 Google Cloud Model Garden、Marketplace、Antigravity 和 Gemini Agent。** [OpenAI 官方公告](https://openai.com/index/openai-models-google-cloud/)称 GA 计划在未来数周推出，企业可用既有 GCP 承诺采购。**影响：** 模型竞争进一步变成“谁能进入客户已有的治理、采购和数据边界”。**行动：** Google Cloud 用户应提前设计同一任务的多模型评测，而不是把云内可购买等同于可直接替换。
3. **OpenAI 用 Agent 发现 PHP 关键漏洞，并把版本核验做成两个可安装 Codex Skills。** [Patch the Planet 公告](https://openai.com/index/coordinated-disclosure-of-critical-vulnerabilities/)和 [php2shell-checker 仓库](https://github.com/openai/php2shell-checker)提供 `phpcheck-server` 与 `phpcheck-url`，支持本机或 URL 检查及机器可读结果。**影响：** “模型发现漏洞→维护者协调→用户自查 skill”形成完整防御链。**行动：** PHP 运维先按官方安全版本升级；skill 的 `UNKNOWN` 不代表已修复，发行版回补也需人工核验。
4. **MCP Skills 从稳定扩展规范进入官方 TypeScript SDK 实现。** [PR #3047](https://github.com/modelcontextprotocol/typescript-sdk/pull/3047)于 10 月 20 日合并，为客户端和服务端新增 `ext/skills` 子路径：服务端可发布 skills 文件夹，客户端可列举并按大小、摘要和 frontmatter 约束读取。**影响：** Skills over MCP 从“自行实现协议”迈向标准 SDK 能力。**行动：** MCP 作者可在试验分支验证，但先保留旧客户端降级路径；包根导出未变化，不要把它误写成核心协议新版。
5. **Claude Security 从一次性扫描升级为持续项目状态。** [Anthropic 10 月 21 日公告](https://claude.com/resources/articles/claude-security-now-scans-continuously-and-tracks-fixes)新增按代码变化持续扫描、修复状态追踪、跨仓库分析、可编辑威胁模型，以及 API、Webhook 和 MCP 连接器。**影响：** 安全 Agent 开始进入发现—分流—修复—复开的闭环。**行动：** 企业先用一个多仓库服务验证误报、跨服务信任边界与 RBAC，再接入自动工单。
6. **Voxtral 3 把听、推理、工具调用和说话合进低延迟语音 Agent 管线。** [Mistral 10 月 20 日发布](https://mistral.ai/news/voxtral-3/)覆盖 50+ 语言转写、35+ 语言语音合成、端点检测、打断、电话/WebRTC 与自部署。**影响：** 语音 Agent 的关键不再只是 ASR/TTS，而是实时工具执行与数据主权。**行动：** 用真实口音、噪音、专有名词、打断和敏感操作审批做端到端测试，厂商 benchmark 只作起点。
7. **聊天式“生成工具”正在越过静态原型。** [Jotform App Builder](https://www.jotform.com/products/apps/)可从 ChatGPT / Claude 对话生成带表单、权限和工作流的应用；[Superhuman Docs AI Views](https://connect.superhuman.com/t/exciting-news-ai-views-opens-for-everyone-in-beta-today/61851)于 10 月 20 日开放 beta，可在实时表格上生成交互视图。**影响：** 设计生成从画界面转向构造可运行数据工具。**行动：** 评测时增加数据权限、状态同步、可编辑性和失败恢复，不只比较首屏视觉。
8. **检索/RAG 竞争转向“更小上下文、更强排序”。** [Exa 3.0](https://exa.ai/blog/exa-3)用更大 embedding 模型、扩展索引和已 GA 的 Dynamic Highlights 提升检索，并称 highlights 相比全文少 95% token；这些成绩来自厂商评测。**影响：** RAG 成本优化越来越依赖在检索层先裁剪证据。**行动：** 用自家问题集同时测召回、引用可追溯、时间敏感性和最终答案，不要只看单项 benchmark。

## 分领域进展

### 设计生成

- **Jotform App Builder for ChatGPT / Claude（10 月 20 日）**把聊天中的需求直接变成可发布的无代码应用，并支持页面、表单、品牌、访问控制、付款与工作流。[官方产品页](https://www.jotform.com/products/apps/)的价值在于“从原型到可用业务壳”更短；但复杂交互、无障碍、设计系统命中率和数据治理仍需人工验收。
- **Superhuman Docs AI Views（10 月 20 日开放 beta）**允许用自然语言在实时表格上生成 roadmap、座位图、反馈分流板等交互视图，数据变化会同步到共享视图。[官方社区公告](https://connect.superhuman.com/t/exciting-news-ai-views-opens-for-everyone-in-beta-today/61851)也记录了关系行跳转和公式选项初值等早期问题，说明“能生成”仍不等于边界行为可靠。
- **Figma / OpenDesign / Claude Design 基线：** 10 月 20—22 日未发现新的重大官方发布；Figma 最新显著节点仍是 10 月 15 日 Code Layers、Specs、Payload、代码来源与设计系统 Guidelines。[Figma Release Notes](https://www.figma.com/release-notes/) 本期不把这些旧闻再次包装为新品。
- **行动建议：** 用同一个真实内部工具做对照：首版时间、设计系统命中、权限正确性、状态同步、键盘/屏幕阅读器、导出/回流和二次修改成本；只有能继续维护的产物才算有效设计生成。

### 数据采集 / RAG

- **Exa 3.0（10 月 19 日）**升级排序模型、索引和 Dynamic Highlights，并新增低价 Exa Lite。[官方发布](https://exa.ai/blog/exa-3)给出了 BrowseComp、DSQA、WideSearch、WebCode 等厂商评测，但未提供本文可独立复算的生产数据。适合需要代码、金融、公司与深研检索的 Agent 团队做小流量对照。
- **工具参数完整性是隐蔽的数据质量问题。** [Composio 10 月 20 日 changelog](https://docs.composio.dev/reference/changelog)修复 AutoGen、Google ADK 和 OpenAI Agents 中自由对象参数可能被传成空对象、却仍执行工具的问题。对抓取/RAG 流程，这类 bug 会造成查询条件丢失而结果“看起来成功”；应对实际执行参数做审计和断言。
- **Firecrawl：本窗口未发现 10 月 19 日 Google Cloud 集成之后的新官方 changelog。** [Firecrawl Changelog](https://www.firecrawl.dev/changelog)继续作为基线；10 月 20 日日报已报道的 Google Cloud / Gemini 接入本期不重复包装。
- **最小验证集：** 动态网页、PDF、登录失败、重定向、重复页和过期页各取样，记录首个正确来源命中率、引用回溯、重复率、输入 token、成本及最终答案准确性。

### Agent 工作流

- **Claude Duet**把晨报、后台观察、长任务和敏感操作审批放进同一持续线程，并继承 Claude 的 memory、skills 与 connectors。[官方说明](https://claude.com/resources/articles/claude-duet)同时承认早期版本可能误判紧急程度或漏掉两次检查之间的新事件；适合先做“只读观察+草稿”，不适合立刻放开高风险写操作。
- **Claude Security**新增持续扫描、修复追踪、知识库/威胁模型、API、Webhook 与 MCP。[官方公告](https://claude.com/resources/articles/claude-security-now-scans-continuously-and-tracks-fixes)显示 Agent 工作流正在从单次工具调用变成有状态闭环；验收重点应是 finding 生命周期、重开条件和跨仓库上下文，而非发现数量。
- **OpenAI × Google Cloud**让 Codex 工作流可以在 GCP 采购和治理边界内运行，并计划进入 Antigravity 与 Gemini Agent。[官方公告](https://openai.com/index/openai-models-google-cloud/)没有给出本期可比较的性能或价格，因此当前应视为分发与治理更新，不是模型能力升级。
- **Mistral × NVIDIA 工程工作流（10 月 21 日）**计划把 Mistral Large 4、数据生成、CUDA-X、Warp 与 Omniverse 连接成仿真—模型—工程设计闭环，并承诺公开 benchmark 与开放数据集。[官方公告](https://mistral.ai/news/mistral-nvidia-ai-for-industrial-engineering/)适合 CAE、制造与 3D 团队关注；在数据集和 benchmark 真正发布前，不应写成已验证的工程提速。

### MCP / Agent Skills 更新

**结论：发现两项值得行动的官方变化——MCP TypeScript SDK 合并 Skills Extension 实现；OpenAI 发布两项 PHP 自查 Codex Skills。MCP 核心协议和 `mcp-server-dev` 三项 skill 清单未发现新版。**

- **核心协议基线｜`2026-07-28`，无新版。** [官方 release](https://github.com/modelcontextprotocol/modelcontextprotocol/releases/tag/2026-07-28)仍标记为 Latest；本窗口未发现新的稳定协议版本。10 月 20 日的 SDK 合并是已稳定 `io.modelcontextprotocol/skills` 扩展的实现进展，不是核心协议升级。
- **TypeScript SDK Skills Extension｜2026-10-20，commit `46d9c99` / PR #3047。** [官方 PR](https://github.com/modelcontextprotocol/typescript-sdk/pull/3047)新增 `ext/skills` 服务端和客户端子路径。服务端可用 `loadSkills('./skills')` 和 `attach(server)` 发布目录；客户端可列举 skills、读取文件，并进行大小、摘要和 frontmatter 校验；根包导出保持不变。
- **能力与迁移影响：** TypeScript 团队不再需要自行拼装 SEP-2640 消息与文件校验；但现有代码不会因升级自动启用，必须显式采用新子路径并处理不支持扩展的客户端/服务端。适合 MCP host、skill registry、企业内技能目录先试；建议用混合新旧客户端测试列举、单 skill 读取、摘要失配、大小上限、同名冲突和缓存失效。
- **OpenAI `phpcheck-server` / `phpcheck-url`｜2026-10-21 随 Patch the Planet 发布，仓库未见语义版本 tag。** [官方仓库](https://github.com/openai/php2shell-checker)的前者用于有服务器访问权时检查本地 PHP，后者用于只有 URL 时读取暴露版本；二者共享机器可读 JSON 和明确退出码。适合 PHP 运维、托管商和事件响应团队快速筛查；`UNKNOWN`、隐藏 header、重定向、发行版回补都要求回到 PHP 官方公告人工核验。

## 今天值得深入研究的 1 个主题

### “主动 Agent”真正的产品边界是可治理的判断

Claude Duet、Claude Security、Patch the Planet 和 OpenAI × Google Cloud 指向同一变化：Agent 不再只等一个 prompt，而是持续观察、跨系统工作、发现异常、推进任务并在必要时请求人类判断。此时模型能力只是底座，决定能否上线的是身份、最小权限、数据流向、批准点、执行日志、撤销和失败恢复。

建议做一个两周可证伪试点：选择一个低风险、跨邮箱/日历/文档的运营流程；第一周只允许观察和起草，第二周只开放一个可逆写动作。记录主动提醒准确率、人工批准率、误操作、漏报、连接器权限、每任务成本、后台检查消耗与恢复时间。任何一项无法审计，就不要把权限扩到付款、签署、删除或外部发送。
