## 分领域进展

### 设计生成

- **Claude Design 当前最值得关注的是 design system 和 handoff，而不是首屏生成效果。** 产品页写明可从 GitHub、设计文件、本地代码库导入设计系统，生成后可交给 Claude Code 或导出到 PDF/PPTX/HTML，并连接 Canva、Miro、Vercel、Wix 等工具。它适合快速产出产品原型、内部门户、deck 和营销页面，但真实落地仍要看组件一致性、响应式、可访问性和工程可维护性。

- **Canva 与 Claude Design 的衔接说明“可编辑”正在成为 AI 设计生成的默认要求。** Canva 新闻稿强调把 Claude 生成的 HTML/视觉内容带入 Canva 进行拖拽编辑、品牌化、协作和发布。影响是明确的：AI 生成稿如果不能进入团队已有编辑器，就很容易停留在 demo 层。建议设计团队优先试“生成后能否被同事编辑”，不要只看 prompt 一次成图质量。

- **Product Hunt 的 AI designer 分类继续显示垂直化趋势。** [Product Hunt AI Designer 分类页](https://www.producthunt.com/categories/ai-designer?order=recent_launches) 最近列出 Miora、Genspark Design、Buddy Figma Agent、Taste Lab、Flowstep、Wonder 等产品。口径限制：该页是分类/近期发布口径，不是全平台热榜；可作为工具雷达，不作为精确增长指标。值得关注的是这些产品分别押注 canvas、Figma agent、设计 DNA 提取、设计到代码等窄场景。

### 数据采集 / RAG

- **Firecrawl `/search` 的新方向是“直接返回可回答问题的摘录”。** 官方 changelog 称新 `/search` 通过 relevance model 对段落、列表、表格打分，并让 agent 用更少上下文处理网页证据。对日报、竞品监控、学术检索和客服知识库来说，这比整页抓取更接近可引用 evidence pipeline。建议用真实问题测召回、引用准确率、重复来源和 token 成本。

- **`pdf-inspector` 的爆发说明 PDF 仍是 RAG 基建最痛的入口之一。** 项目 README 表示它是 Rust PDF 分类和文本抽取库，可判断 text-based、scanned、image-based、mixed，并输出 Markdown，且有 Python、Node、WASM 绑定。适合做 PDF 预检、OCR 路由、表格抽取和文档管线门禁；不适合被误解为完整 RAG 系统。

- **Mistral Search Toolkit 仍是最近一周内值得补看的 RAG/搜索基础设施。** [Mistral Search Toolkit](https://mistral.ai/news/search-toolkit/) 定位为可组合的生产搜索 pipeline，覆盖 ingestion、retrieval、evaluation，强调开源和可部署在 cloud/on-prem/edge。它和 Firecrawl 的差异在于：前者偏搜索系统框架，后者偏网页/PDF 数据入口。做企业检索时可以组合评估。

### Agent 工作流

- **Cursor 的公开产品页已经把 agent 工作流做成多入口界面。** 官网展示了 Cursor Desktop、CLI、Slack、GitHub PR、cloud agents、automations 和移动端入口。这意味着 coding agent 不再只是 IDE 内会话，而是会进入异步任务、代码评审、团队协作和定时修复。团队应补上 agent 任务所有权、失败通知、日志留存、凭据隔离和审批策略。

- **DeepSeek Reasonix 的热度来自“缓存纪律”。** [DeepSeek API 文档](https://api-docs.deepseek.com/quick_start/agent_integrations/reasonix) 将 Reasonix 列为第三方 agent integration，并提示不保证效果或安全；[Reasonix 仓库](https://github.com/esengine/DeepSeek-Reasonix)强调围绕 DeepSeek prefix cache 设计，适合长会话保持低成本。它的价值不是替代所有 coding agent，而是提醒团队把 agent 成本结构纳入架构设计。

- **agent skill 与安全 playbook 正在变成工程资产。** `reverse-skill` 的定位是给 Claude Code、Codex、Cursor 等 agent 提供逆向/授权安全研究路线，而 `microsoft/generative-ai-for-beginners` 的课程也包含 AI agents、RAG、安全和 UX 课程。趋势是：agent 能力靠 skill/规则/课程沉淀，不能只靠模型临场发挥。

## 今天值得深入研究的 1 个主题

**主题：Agent 的“可控上下文”会成为 2026 下半年的工程主线。**

今天的所有线索都能放进同一张图：Firecrawl/pdf-inspector 解决外部证据质量，Claude Design/Canva 解决可编辑生成物，Cursor/Reasonix 解决执行与成本，reverse-skill/superpowers 解决可复用技能，政策框架解决前沿模型发布边界。它们共同说明，agent 的能力不只来自模型，也来自上下文入口、技能边界、执行环境、权限和审计。

建议把内部 agent 平台拆成五层评估：数据入口是否可引用、上下文是否可治理、工具权限是否最小化、执行日志是否可回放、成本是否按任务归因。这样才能判断一个 agent 工具是可生产化，还是只是演示能力强。
