## 今日最值得关注

1. **Claude in Chrome 已面向所有付费 Claude 方案 GA。** 来源：[Anthropic 官方博客，2026-08-26](https://claude.com/blog/claude-in-chrome-generally-available)。结论：浏览器内 agent 从实验进入日常工作入口，Claude 可以读取当前页面并执行点击、输入、导航、填表等动作。影响判断：这会推动“浏览器即工作台”的 AI 应用形态，但也把 prompt injection、账号权限和网页侧误操作风险前置。行动建议：企业试用时先限制域名、只放低风险流程，把付款、删除、对外发送等动作保留人工确认。

2. **OpenAI/Hugging Face 事件继续主导 agent 安全讨论。** 来源：[OpenAI 事件说明，2026-08-26](https://openai.com/index/hugging-face-incident-and-the-road-ahead/)、[YouTube Black Hat talk](https://www.youtube.com/watch?v=87DyyMV0kCY)、[X 趋势页](https://x.com/i/trending/2082935990273101966)。结论：高能力 agent 的问题不是“会不会调用工具”，而是会不会在长期目标、共享状态、越权网络和奖励黑客下绕过边界。影响判断：VM、容器、日志和人工审批都要重新按高权限 workload 评估。行动建议：所有生产 agent 项目本周就该列出外网权限、可写工具、凭据访问和暂停阈值。

3. **WebMCP 在 2026-08-26 发布新的 W3C Community Group draft。** 来源：[WebMCP Draft Community Group Report](https://webmachinelearning.github.io/webmcp/)。结论：网页可以把前端功能声明成结构化 JavaScript tools，让 agent 调用声明接口，而不是猜 DOM 或屏幕坐标。影响判断：如果它后续被浏览器和主流 agent 接受，SaaS 产品会多一个“给 agent 用的 UI 层”。行动建议：前端团队可以先挑一个低风险表单做实验，声明只读或草稿型 tools，不要把不可逆动作直接暴露给 agent。

4. **Gemini API 连续两天更新语音和视频模型。** 来源：[Gemini API Release Notes，2026-08-27/26](https://ai.google.dev/gemini-api/docs/changelog)、[Google Gemini 3.5 Transcribe 官方博客](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-5-transcribe/)。结论：`gemini-omni-1.1-flash` 视频生成/编辑 GA，`gemini-3.5-transcribe` 和 live 版语音转写 GA。影响判断：实时语音、会议记录、视频延展和多模态内容生产会更容易被塞进 agent workflow。行动建议：做客服、会议、短视频工具的团队应把音视频处理从“离线后处理”改成可调用的实时能力评测。

5. **Cloudflare AI Search 加入 6 个 Workers AI 文本生成模型。** 来源：[Cloudflare AI Search Changelog，2026-08-26](https://developers.cloudflare.com/changelog/product/ai-search/)。结论：DeepSeek V4、OpenAI gpt-oss、Qwen3.8、Kimi K2.7 Code 等可直接作为 AI Search 文本生成模型，不需要额外 provider key。影响判断：RAG 产品的门槛继续下降，托管检索、模型选择和 API 权限会合到一个平台层。行动建议：已有 Cloudflare 栈的团队可以优先测试 AI Search 的 metadata filter、长上下文模型和 agent 框架集成。

7. **Firecrawl Developer Index 是最近一周 RAG/抓取工具里最实用的更新。** 来源：[Firecrawl Changelog，2026-08-20](https://www.firecrawl.dev/changelog)。结论：它覆盖 README、外部文档、issues、PR、OpenAPI specs 等 7000 万以上开发者 artifacts，并可通过 `/search/developer`、CLI、MCP、SDK 和 companion skill 使用。影响判断：代码 agent 需要的是 artifact-level retrieval，不是普通网页搜索结果。行动建议：做 repo QA、API 迁移、SDK 助手时，优先把 issues/PR/OpenAPI 纳入检索。

## 分领域进展

### 设计生成

**结论：** 设计生成的竞争重点正在从“生成静态图”转向“理解设计系统，并能被 agent 工作流调用”。

- [Figma Release Notes](https://www.figma.com/release-notes/) 在 2026-08-24 推出 Figma MCP Enterprise-managed authorization GA，让 Enterprise/Organization 管理员可以通过 identity provider 管理 Figma MCP server 与 Claude 等 AI agents 的连接；2026-08-26 又让 desktop app 的 agent chat panel 能独立成窗口，方便一边设计一边持续对话。
- [Figma AI credit FAQ](https://help.figma.com/hc/en-us/articles/42614902212887-AI-credit-updates-FAQ) 显示 2026-08-25 AI credit add-ons 已增加可用额度，并提示 Weave tools 与 Figma Design agent 未来 GA 后会消耗 AI credits。对组织用户，这意味着 AI 设计功能开始进入预算、权限和审计管理。
- [Claude Design](https://claude.com/product/design) 仍是 hosted prompt-to-design 工作区，适合快速生成 prototype、deck、one-pager 和 marketing collateral；它的价值在于把视觉探索接到 Claude Code，而不是替代最终设计评审。
- [Open Design](https://open-design.ai/) 和 [nexu-io/open-design](https://github.com/nexu-io/open-design) 提供 local-first、BYOK、open-source 的 Claude Design 替代路径，强调把 Codex、Claude Code、Cursor 等本地 coding agent 变成设计引擎。适合重视文件归属、可 fork、可版本化 design system 的团队。
- [Product Hunt AI Designer](https://www.producthunt.com/categories/ai-designer?order=recent_launches) 类目近期仍把 Stitch、Framer、Figma Make、Uizard、Kombai、Wonder 等归在“从 brief 到可编辑 UI/资产”的方向。热度口径是 Product Hunt 类目页与近期 launch，不代表实时使用量。

**行动建议：** 不要先买一堆设计 AI 工具。先把品牌规则、组件边界、禁用样式和交付格式写成可复用 brief/skill，再让工具生成。

### 数据采集 / RAG

**结论：** RAG 的新增价值正在转向“高质量专用索引”和“agent 原生调用入口”。

- [Firecrawl Developer Index](https://www.firecrawl.dev/changelog) 覆盖 7000 万以上开发者 artifacts，支持按 result type、repository、doc source、language、topic、license、minimum stars 等过滤，且每个结果带稳定 id、url 和 matched passages。它更适合代码 agent 查 API、issue、PR 和错误信息。
- [Cloudflare AI Search Changelog](https://developers.cloudflare.com/changelog/product/ai-search/) 在 2026-08-26 增加 DeepSeek、gpt-oss、Qwen、Kimi 系列 Workers AI 模型；2026-08-25 增强 custom metadata 存储；此前已支持 Agents SDK、Vercel AI SDK 和 LangChain。适合已经在 Cloudflare 上托管数据/边缘逻辑的团队。
- [WebMCP draft](https://webmachinelearning.github.io/webmcp/) 把网页功能声明为工具，方向上会减少 agent 对 DOM/screenshot 的脆弱依赖。限制：它是 W3C Community Group report，不是 W3C 标准。
- [Firecrawl /monitor](https://www.firecrawl.dev/monitor) 和 web-scale monitor 仍值得作为“变更驱动采集”的参考：只在页面或搜索结果有相关变化时通知 agent，减少重复抓取和上下文浪费。

**行动建议：** 如果你的 RAG 用于开发者支持，第一优先级不是换 embedding 模型，而是把 README、docs、issues、PR、OpenAPI、release notes 放到同一索引，并记录刷新时间。

### Agent 工作流

**结论：** Agent 工作流的热点从“能自主做事”转成“如何授权、审计、暂停和复盘”。

- [Anthropic computer use + Skills API + Files API](https://claude.com/blog/computer-use-skills-api-files-api) 在 2026-08-20 GA，组合了浏览器/软件操作、版本化 skill、文件输入输出和 code execution sandbox。适合保险、客服、运营后台、内部系统等没有标准 API 的工作流。
- [Claude in Chrome](https://claude.com/blog/claude-in-chrome-generally-available) 把同一方向推进到浏览器侧：agent 可以利用用户现有登录态跨 tab 工作。优势是覆盖 legacy/internal/vendor portals；风险是网页内容本身可能携带 prompt injection。
- [GitHub Copilot in Slack](https://github.blog/changelog/2026-08-21-the-new-github-copilot-experience-in-slack/) 让团队能在 Slack 中启动、跟进、协作 Copilot agent session。重点不是“Slack 里能写代码”，而是 agent 工作进入共享频道和 PR 审查流。
- [OpenAI Admin plugin for ChatGPT Work and Codex](https://openai.com/index/introducing-admin-plugin/) 把 workspace usage、members/groups、permissions、spend requests 等管理动作接入 ChatGPT Work/Codex。它说明 agent 工具不只面向终端开发者，也会进入管理后台。
- [Wired 关于 OpenAI Persistent mode 的报道](https://www.wired.com/story/openai-is-developing-a-persistent-ai-agent) 属于媒体报道，非官方 GA。它值得关注，因为“持续工作直到停止”的 agent 形态会显著放大权限和状态治理问题。

**行动建议：** 新 agent 项目默认加四个约束：外网访问开关、按工具分级授权、操作日志、超过时长或异常循环自动暂停。

### MCP / Agent Skills 更新

**检查结论：发现 MCP 官方 8 月路线图仍是最新官方方向更新；未发现比 `2026-07-28` 更晚的官方协议版本；未发现 `mcp-server-dev` 官方 skill 清单新增。**

- **当前协议基线：** [MCP 2026-07-28 specification](https://blog.modelcontextprotocol.io/posts/2026-07-28/) 仍是本次检查发现的最新官方协议版本。核心变化包括 stateless protocol core、Multi Round-Trip Requests、header-based routing、cacheable list results、authorization hardening、Tasks extension、旧 SSE/Roots/Sampling/Logging 的弃用窗口。
- **官方路线图：** [The New MCP Roadmap，2026-08-22](https://blog.modelcontextprotocol.io/) 明确下一阶段关注 agent communication、transport/security hardening、agent identity、improved primitives、SDK developer experience。它不是新 spec，但给出生产实现方向。
- **Agent Skills 官方文档：** [Build with Agent Skills](https://modelcontextprotocol.io/docs/2026-07-28/develop/build-with-agent-skills) 当前列出 `mcp-server-dev` plugin 的三个 reference skills：`build-mcp-server`、`build-mcp-app`、`build-mcpb`。
- **官方 GitHub skill 目录：** [anthropics/claude-plugins-official/plugins/mcp-server-dev](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/mcp-server-dev) 和 [skills 子目录](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/mcp-server-dev/skills) 当前可见三项：`build-mcp-app`、`build-mcp-server`、`build-mcpb`，与文档一致。
- **能力变化：** `build-mcp-server` 是入口，负责询问连接对象、用户范围、action surface、UI 需求和 auth；`build-mcp-app` 用于带 chat inline UI widgets 的 MCP app；`build-mcpb` 用于把本地 stdio server 和运行时打包成 `.mcpb`。本次未发现新增官方 skill，但 WebMCP 和 Figma MCP 的推进说明“agent 可调用 UI/设计工具”正在变成主线。
- **迁移影响：** 维护 MCP server 的团队应优先适配无状态请求、header routing、`server/discover`、issuer validation、DCR 到 CIMD 的迁移准备，以及 Tasks extension。新 server 不建议再围绕隐式 session state 设计。
- **适合试用者：** 企业内部工具平台、Agent gateway、SaaS 插件市场、Figma/浏览器/本地工具集成维护者。单人脚本可以保持 stdio 简单实现，但要预留 MCPB 或 remote HTTP 的升级路径。
