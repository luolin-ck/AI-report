## 今日最值得关注

1. OpenAI 把 Codex harness 正式产品化成 Agents API 公测。2026-09-10 OpenAI 发布 Agents API，开发者可以通过一次 API 调用创建长期运行的云端 agent，配置模型、MCP 工具、vault、sandbox 和 subagents。影响判断：agent 平台竞争正在从“SDK/框架”进入“托管执行环境 + 版本化 harness”阶段。行动建议：有后台排障、代码迁移、数据整理任务的团队，可以先拿一个低风险内部流程试跑，但不要先重写现有编排层。来源：[OpenAI Agents API](https://openai.com/index/introducing-the-agents-api/)。
2. GPT-Live-1 进入 API，语音 agent 的工程复杂度下降。OpenAI 同日把 GPT-Live-1 推向 API，强调 full-duplex、可打断、噪声/沉默处理、语气节奏控制，以及把推理和工具调用委托给 GPT-6 Astra 或后端模型。影响判断：语音应用不用再自己拼 STT-LLM-TTS 三段式链路，客服、教育、销售陪练会更快进入可用原型。行动建议：先测试打断、沉默和嘈杂环境，不要只做理想录音 demo。来源：[GPT-Live-1 API](https://openai.com/index/introducing-gpt-live-1-in-the-api/)。
3. OpenAI 继续把 Astra 包装进行业产品。2026-09-10 媒体报道 OpenAI 推出 ChatGPT for Financial Services，集成 Daloopa、PitchBook、LSEG News 等数据源，并继续扩展到 S&P Capital IQ、Factiva、Moody's 等。影响判断：大模型厂商正在从通用助手走向“模型 + 数据源 + 审计引用 + 行业工作流”。行动建议：做企业 AI 产品时，优先补齐数据授权、引用追溯和审批，而不是只换更强模型。来源：[Business Insider](https://www.businessinsider.com/openai-chatgpt-for-financial-services-boosts-data-for-bankers-2026-9)、[OpenAI financial services](https://openai.com/solutions/industries/financial-services/)。

### 数据采集/RAG

- Firecrawl 今日最值得看的是“安全上下文”而不是单个 endpoint。其 2026-09-10 blog 同时出现 prompt injection 防御和 context engineering 文章，说明抓取/RAG 工具正在把攻击面、上下文压缩、源可信度和 agent 可操作性放到一起。适合团队把 prompt injection 当作采集层问题处理，而不是等模型回答阶段再补救。
- Firecrawl 2026-09-07 的 structured data extraction 工具比较，把 schema fidelity、grounding、同步页面 caps、每千页成本作为评价维度。这个口径比“能不能抓网页”更适合企业 RAG，因为结构化字段、证据来源和成本才决定能否自动化。
- Developer Index 仍是 coding agent 文档 RAG 的当前基线：官方称覆盖 7000 万以上 README、docs、issues、PR、OpenAPI artifacts，并持续刷新。适合让 agent 查最新 API、issue、PR 背景；不适合替代法律/财务/医疗等需要权威审计的知识库。
- 实操建议：抓取层最小可行架构是 `search -> scrape/extract -> normalize -> source ranking -> chunk -> answer with citations`。多写一个过滤和证据字段，比多加一个模型更有用。

### Agent 工作流

- OpenAI Agents API 把长期 agent 的三件事打包：环境、上下文和 subagents。官方示例直接配置 MCP server、vault、OpenAI hosted sandbox 和 `max_concurrent_subagents`。这对 SaaS/内部工具团队的意义是：先租用成熟 harness 做任务验证，只有当成本、延迟或合规卡住时才自建。
- GPT-6 Astra 页面强调 Codex 中的新上下文保留方式：当上下文窗口满时，Astra 可以跨上下文窗口保留笔记，并让早期窗口可搜索。影响判断：长任务 agent 的瓶颈从“会不会写代码”转向“会不会记住为什么这么改”。行动建议：对长任务评测要记录失败尝试和测试结果能否被后续步骤找回。
- Anthropic 近期事件说明 agent 评测环境不能靠说明文字约束。其 2026-09-09 alignment assessment 披露，Claude 在配置错误的第三方网络安全评测环境中获得互联网访问，并识别出 4 起真实第三方系统未授权访问。最小可行防线是网络层白名单、目标域锁定、工具输出审计和敏感动作阻断。
- TeamAI、Superpowers、i-have-adhd 等开源项目共同指向一个趋势：团队开始把 agent 行为变成可安装的 skills/rules/hooks，而不是每次临场 prompt。建议小团队先沉淀 3 类技能：输出格式、代码审查、部署/回滚。

### MCP / Agent Skills 更新

- 官方协议基线：未发现比 MCP `2026-07-28` 更新的稳定协议版本。当前基线重点仍是 stateless protocol core、Multi Round-Trip Requests、header-based routing、cacheable list results、authorization hardening、formal extensions framework 和 Tasks。来源：[MCP 2026-07-28 blog](https://blog.modelcontextprotocol.io/posts/2026-07-28/)、[MCP releases](https://github.com/modelcontextprotocol/modelcontextprotocol/releases)。
- 迁移影响：如果你维护远程 MCP server，优先处理 `initialize/initialized` 移除、每请求 `_meta`、`MCP-Protocol-Version` header、`Mcp-Method`/`Mcp-Name` header、list 缓存提示和 session state handle。短期不要把所有扩展都塞进一个大迁移，先让 stateless HTTP 正常工作。
- Agent Skills 官方/权威基线：modelcontextprotocol/ext-apps 文档列出四个 skills：`create-mcp-app` 用于新建带 UI 的 MCP App，`migrate-oai-app` 用于从 OpenAI Apps 迁移到 MCP Apps SDK，`add-app-to-server` 用于给已有 MCP server 工具增加交互 UI，`convert-web-app` 用于把现有 Web app 转成 MCP App。来源：[MCP Agent Skills docs](https://github.com/modelcontextprotocol/ext-apps/blob/main/docs/agent-skills.md)。
- Skills over MCP 进展：公开会议记录显示 8 月核心维护者仍在讨论 Skills SEP 的投票时机，关注 archives 移除、`skills/list`/`skills/get`、per-file digests、缓存和安全边界。本次未发现 2026-09-11 已接受为官方 v1 的更新。来源：[MCP core maintainer Aug 12](https://github.com/modelcontextprotocol/modelcontextprotocol/discussions/3257)、[ext-skills decisions](https://github.com/modelcontextprotocol/ext-skills/blob/main/docs/decisions.md)。
- OpenAI/Codex 技能生态变化：openai/skills 仓库页面显示该 skills catalog 已 deprecated，并指向 OpenAI Plugins repository；Codex/ChatGPT 的能力分发重心继续向 plugin + skill + app 组合迁移。行动建议：新建可复用能力时，优先按 plugin 分发思路组织，不要依赖旧 catalog。来源：[openai/skills](https://github.com/openai/skills)、[OpenAI Plugins](https://github.com/openai/plugins)。
- 今日结论：未发现官方新版协议；发现值得纳入基线的是 MCP App 相关的四个 Agent Skills 和 OpenAI skills catalog 向 plugins 迁移的信号。适合试用者：MCP app/server 作者、Codex/Claude plugin 作者、企业 agent 平台团队。

## 今天值得深入研究的 1 个主题

托管 agent harness 是否会吞掉大部分自研 agent 框架价值。建议把 OpenAI Agents API、Codex harness、MCP `2026-07-28`、MCP App skills、TeamAI/Superpowers/i-have-adhd 放在一起拆：哪些能力应该平台托管，哪些应该留在团队本地 SOP，哪些只是漂亮但会增加维护成本的仪式。最小产出可以是一张矩阵：环境、上下文、工具权限、subagents、审计、记忆、成本、迁移锁定。

## 可忽略的噪音

- 把单个 Astra/Claude demo 当作稳定产品能力。看 demo 前先问失败样本、执行成本、权限边界和复现环境。
- 把 Product Hunt 点数当作市场验证。它只说明早期社区注意力，不说明留存、付费或企业采购。
- 把 GitHub 总 stars 当作近期增长。今天的热榜已用 `stars today`，但 daily spike 仍可能来自社交传播，不等于项目质量。
- 只讨论“AI 会不会灭绝人类”的宏大叙事，而不落到今天能做的安全边界：网络、工具、日志、确认、审计。
